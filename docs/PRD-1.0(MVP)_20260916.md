## 一、产品概述

### 1.1 产品定位

Marklite 是一款面向 macOS 的轻量级 Markdown 文件编辑与实时预览应用。

用户直接打开本地 `.md` 文件，在源码编辑区修改内容，在预览区查看渲染结果，并将修改保存回原文件或导出为 HTML、PDF。

Marklite 的管理对象是**用户已有的文件**，而非应用内部的笔记、知识库或工作空间。

### 1.2 产品价值

1. **打开即用**：无需注册、创建资料库或导入文件。
2. **源码可控**：始终保留标准 Markdown 文本编辑能力。
3. **结果即时可见**：编辑后快速更新渲染结果。
4. **界面安静**：尽量不占用文档显示空间。
5. **文件安全**：避免未保存内容丢失、外部修改被覆盖、导出污染原文件。

### 1.3 产品边界

Marklite 不承担以下职责：

- 笔记分类和知识管理。
- IDE 式项目管理、多根工作空间与项目级内容索引；允许用户明确授权后的本地目录浏览、新建文件与文件夹、移到废纸篓等基础文件管理。
- 多人协作和云同步。
- 富文本所见即所得编辑。
- AI 写作、问答或内容生成。
- 软件开发 IDE。
- 静态网站构建和发布。

### 1.4 核心工作流

```text
启动应用
  → 新建或打开 Markdown 文件 / 打开本地文件夹
  → 在当前窗口选择文档（可按需展开文件侧栏）
  → 编辑源码
  → 自动更新预览
  → 保存原文件 / 另存为 / 导出
  → 关闭文档
```

## 二、目标用户与使用场景

### 2.1 目标用户

| 用户类型 | 主要诉求 |
|---|---|
| 开发者 | 快速编辑 README、变更日志和技术文档 |
| 技术写作者 | 专注 Markdown 源码和最终排版 |
| 产品、设计人员 | 查看和轻量修改需求文档、说明文件 |
| 普通 Markdown 用户 | 无需打开大型 IDE 或笔记应用即可处理文件 |

### 2.2 核心场景

#### 场景 A：快速查看文件

用户在 Finder 中双击 Markdown 文件，应用直接展示双栏视图；用户也可以切换到纯预览模式阅读。

#### 场景 B：编辑已有文档

用户打开本地文件，修改标题、列表、代码块等内容，实时查看预览，通过 `⌘S` 保存。

#### 场景 C：新建临时文档

用户通过 `⌘N` 新建文件，输入 Markdown，首次保存时选择文件名和位置。

#### 场景 D：导出可分享文档

用户将当前内容导出为独立 HTML 文件或 PDF，不改变原 Markdown 文件。

#### 场景 E：处理外部变更

用户同时通过 Git、终端或其他编辑器修改文件，Marklite 检测变化并防止静默覆盖。

#### 场景 F：连续处理相关文档

用户打开本地文档文件夹，通过轻量目录树查找文件，在同一窗口切换 README、需求文档和设计说明。切换时保留各文档的未保存内容、撤销历史和阅读位置；需要并排参考时，显式将文档移至新窗口。用户也可在目录树中新建 Markdown 文件或文件夹，将不再需要的文件或文件夹移到废纸篓，无需为基础整理频繁切换 Finder。

## 三、产品目标与成功标准

### 3.1 产品目标

- 核心工作流不依赖侧栏、工具栏或账户系统。
- 常用操作符合 macOS 原生习惯。
- 输入体验流畅，预览更新不打断光标和滚动。
- 保存、恢复和冲突处理不存在已知的数据丢失路径。
- 本地文件内容不上传至外部服务。

### 3.2 验证指标

以下指标通过本地测试、可用性测试和自愿反馈验证，首版不默认植入行为分析 SDK。

| 维度 | 目标 |
|---|---|
| 可发现性 | 初次使用者能够通过菜单完成打开、保存、切换视图和导出；首次多文档状态可发现已有会话 |
| 界面占用 | 标准窗口尺寸下，正文区域占窗口内部高度约 94%–95% |
| 输入流畅度 | 常规文档输入无明显阻塞，不因预览计算卡顿 |
| 预览速度 | 100 KB 以内文本，停止输入后到预览稳定更新的 P95 ≤ 300 ms |
| 文件打开 | 1 MB 以内纯文本 Markdown，从确认打开到可编辑的 P95 ≤ 1 秒 |
| 可靠性 | 文件保存与恢复相关验收用例全部通过，无阻塞级数据丢失缺陷 |
| 离线可用性 | 编辑、预览、本地图片和导出均可离线使用 |

**性能测试基线：**Apple Silicon M1、8 GB 内存、SSD、macOS 14 或以上。网络图片下载耗时不计入文本渲染指标。

## 五、信息架构与界面规范

### 5.1 窗口结构

```text
┌────────────────────────────────────────────────────┐
│ ● ● ●   Sidebar    README.md ·              ◫   … │
├───────────────────────┬────────────────────────────┤
│                       │                            │
│ Markdown 源码          │ 渲染预览                    │
│                       │                            │
│                       │                            │
└───────────────────────┴────────────────────────────┘
```

默认打开单个文件时保持上述双栏结构，文件侧栏隐藏。用户打开文件夹或主动显示侧栏后，布局如下：

```text
┌──────────────────────────────────────────────────────────┐
│ ● ● ●   Sidebar          PRD.md ·               ◫   …    │
├────────────────┬───────────────────┬─────────────────────┤
│ Open Documents │                   │                     │
│   README.md    │ Markdown 源码      │ 渲染预览             │
│   PRD.md     · │                   │                     │
│                │                   │                     │
│ docs           │                   │                     │
│ ▾ product      │                   │                     │
│   PRD.md       │                   │                     │
│ ▸ design       │                   │                     │
└────────────────┴───────────────────┴─────────────────────┘
```

侧栏负责已打开文档切换、本地目录导航和基础文件管理（新建文件/文件夹、移到废纸篓），不引入笔记库、项目配置或 IDE 式项目管理。文件操作通过原生菜单和上下文菜单提供，不增设常驻操作工具栏。

### 5.2 视觉原则

- 仅保留一个紧凑统一标题栏。
- 不设置独立工具栏。
- 不设置面板标题栏。
- 不设置底部状态栏。
- 默认隐藏文件侧栏，允许用户按需展开；不设置顶部标签栏。
- 侧栏隐藏不关闭文档、不撤销目录授权、不改变编辑与预览模式。
- 不展示常驻格式工具、词数、编码、缩放或光标坐标。
- 正文区域优先，颜色与装饰保持克制。

### 5.3 尺寸与布局

| 项目 | 规范 |
|---|---|
| 默认窗口尺寸 | 1280 × 820 pt，按可用屏幕自动约束 |
| 最小窗口尺寸 | 800 × 560 pt |
| 标题栏高度 | 约 48–52 pt，以原生窗口约束为准 |
| 默认双栏比例 | 编辑 48%，预览 52% |
| 单栏最小宽度 | 320 pt |
| 编辑区内边距 | 默认约 32 pt，窄窗口可收敛至 24 pt |
| 预览区内边距 | 默认约 48 pt，窄窗口可收敛至 24 pt |
| 分割线 | 低对比度 1 px 视觉线，无常驻拖拽柄 |
| 文件侧栏 | 默认宽约 220 pt，可在 180–320 pt 范围内调整 |

双栏正文仍需满足两栏各至少 320 pt 的约束。窗口内容宽度不足以同时容纳侧栏、正文最小宽度及分割线时，不挤压正文至不可用宽度、不自动改变编辑/双栏/预览模式，文件导航仍必须可访问。

首版优先采用原生布局能力，不强制实现一套自定义覆盖式侧栏。技术验证后可选择：收起停靠侧栏并在用户请求展开时适度扩宽窗口（不得超过可用屏幕），或在无法扩宽时提供原生临时导航面板。具体策略须在阶段 0 的技术设计中明确，包括窗口缩放、自动展开请求与用户主动隐藏之间的优先级。

不论采用何种形式，必须支持键盘与 VoiceOver 进入导航、选择文档、关闭临时界面并返回正文；临时界面支持 Esc。不得因侧栏收起而失去访问已打开文档与文件操作的途径，也不得擅自重置文档阅读位置。

分栏比例可拖动调整，在运行中的文档会话内独立保留。重启后尽力恢复最近有效比例，无法恢复时使用默认比例；新文档使用默认比例。精确比例恢复不作为首版发布门槛。

### 5.4 标题栏

#### 左侧

原生 macOS 窗口关闭、最小化、全屏按钮，其后提供 `Toggle Sidebar` 图标按钮。该按钮始终可发现，侧栏默认隐藏；不另设工具栏。

#### 中间

- 当前文件名，例如 `README.md`。
- 未保存时显示小型低对比度圆点。
- 未命名文档显示本地化名称 `Untitled` / `未命名`，遵循 §5.5。
- 不常驻显示完整路径。
- 通过原生标题菜单或悬停信息提供文件路径访问。
- 标题及其未保存标记对应当前活动文档；后台文档的未保存状态显示在 `Open Documents` 列表中。
- 未保存状态必须同时具备可访问性描述，不仅依赖颜色。

#### 右侧

仅显示两个语义化图标：

1. **视图布局图标**
   - 辅助标签：`View Layout`
   - 点击展开菜单：`Editor`、`Split`、`Preview`
   - 当前模式带勾选标记。

2. **更多图标**
   - 辅助标签：`More Actions`
   - 点击展开次要操作菜单。

图标采用 SF Symbols 风格；视觉尺寸约 16–18 pt，交互区域不小于 28 × 28 pt。

### 5.5 界面语言与 i18n

V1.0 必须完整支持英文（`en`）和简体中文（`zh-Hans`），不是仅预留未来本地化能力。PRD 中的英文操作名称是语义标识，实际显示必须使用当前界面的对应译文。

**语言选择：**

- 遵循 macOS 首选语言顺序及系统为应用指定的语言设置；优先匹配支持的语言，无匹配时回退英文。
- 首版不提供应用内语言切换器，不为此增加独立设置窗口；用户通过系统的应用语言设置选择，重新启动后生效。
- 切换系统应用语言不得修改文档内容、文件名、路径或草稿。正常关闭与重新启动仍遵循保存确认及会话恢复规则。
- Markdown 正文支持 Unicode，界面语言与正文语言相互独立，不自动翻译用户文档或文件夹名称。

**实现要求：**

- 从阶段 1 起使用 String Catalog（`.xcstrings`）或等价本地化资源，英文和简体中文同时维护；禁止在视图、错误处理或业务逻辑中硬编码用户可见文案。
- 覆盖原生应用菜单、上下文菜单、侧栏、空状态、查找替换、错误与确认对话框、导出与恢复提示、工具提示、辅助功能名称、帮助文档及文件类型显示名称。系统原生面板由系统负责本地化，应用提供的标题和按钮同样必须本地化。
- 使用稳定语义键；含文件名、数量和错误原因的文案采用参数化格式，不拼接句子，并支持本地化复数、日期和数字格式。内部标识与状态持久化不得依赖翻译后的显示文本。
- 缺失翻译回退英文，不显示资源键或空字符串；首版交付的两种语言不允许存在已知缺失项。
- 布局适应两种语言的实际字宽，不用固定英文字符宽度设计菜单、提示或按钮；使用系统字体及中文回退，中文输入与 Unicode 路径必须正确显示。
- 快捷键的组合保持一致，菜单名称、VoiceOver 标签和错误状态须对应当前语言；禁止在一个界面中并列显示两种译文。

| New File… | 新建文件… |
| New File in Folder… | 在文件夹中新建文件… |
| New Folder… | 新建文件夹… |
| Move to Trash… | 移到废纸篓… |

## 六、详细功能需求

## 6.1 文件与文档管理

### F-01 新建文档

**入口：**

- `File > New Document`
- `⌘N`

**行为：**

- 在当前文档窗口创建新文档会话；没有文档窗口时创建窗口。
- 不替换或关闭当前已打开文档。
- 初始文档为空。
- 默认双栏模式。
- 编辑区自动获得焦点。
- 预览区保持空白，不显示欢迎卡片或引导按钮；这与 F-08 中无活动文档的目录浏览空状态不同。
- 空白且从未编辑的文档关闭时不提示保存。

首次保存时弹出原生保存面板：

- 默认文件名：按界面语言为 `Untitled.md` / `未命名.md`。
- 默认位置：最近使用的保存目录，首次为系统默认文档目录。
- 用户可以更改文件名和目录。

### F-02 打开文件

**入口：**

- `File > Open…`
- `⌘O`
- Finder 的“打开方式”或双击已关联文件。
- 拖放文件到应用图标或窗口。
- `Open Recent`。

**支持类型：**

- `.md`
- `.markdown`
- `.mdown`

通过“所有文件”选项可以打开可正确解码的纯文本文件；不接受二进制文件作为正常文档。

**规则：**

- 默认在当前文档窗口创建或激活文档会话，不因打开文件增加窗口；没有文档窗口时创建窗口。
- Finder、Open Recent 和拖放到应用图标的打开请求路由至最近活动的文档窗口；拖放到窗口则使用目标窗口。
- 同一实际文件已打开时，聚焦所属窗口并激活现有会话，不创建可独立编辑的重复副本；身份判断需处理路径别名和符号链接。
- 空白、从未编辑的初始文档会话可以被打开文件复用。
- 已包含内容的文档不能因打开其他文件而被静默替换或关闭。
- 同时打开多个文件时，在目标窗口为每个有效文件创建会话，按打开请求顺序排列并激活第一个有效文件；无效文件单独反馈，不阻止其他文件打开。
- 单文件新窗口默认隐藏侧栏；当前窗口首次从一个会话增加到多个会话时，自动显示 `Open Documents` 所在侧栏，让已有文档可发现。批量打开多个文档也遵循此规则。
- 用户在当前窗口运行期间主动隐藏侧栏后，后续打开文档不反复自动展开；该显式偏好优先于首次多文档展开。主动打开/更换文件夹或点击侧栏按钮仍可显示导航。
- 窄窗口下自动显示请求遵循 §5.3 的已验证导航策略，不强制挤压正文；侧栏隐藏时仍可通过 Window 菜单切换文档。
- 对未打开文件提供 `Open in New Window` / `在新窗口中打开`，在新窗口创建会话；对已打开文件提供 `Move to New Window` / `移至新窗口`，将原会话移至新窗口，保留未保存内容、撤销和视图状态，不复制缓冲区。
- File 菜单的 `Move to New Window` 作用于当前活动文档，无活动文档时禁用；侧栏文件上下文菜单按目标是否已打开显示对应动作，目录节点不显示文档会话迁移动作。
- 每个文档会话同时只属于一个窗口。移出最后一个文档后，原窗口有目录则保留目录浏览，无目录则关闭。
- 首版禁用系统自动窗口标签合并，不实现顶部标签栏；多文档导航由文件侧栏和原生菜单承担。

### F-03 文件编码与换行

首版支持：

- UTF-8。
- 带 BOM 的 UTF-8。
- LF 和 CRLF 换行。

规则：

- 新建文档使用 UTF-8 无 BOM、LF。
- 已有文档保留 BOM 状态。
- 已有文档保留主要换行风格；混合换行文件首次保存前需告知将统一换行。
- 不自动添加或删除末尾换行。
- 无法按 UTF-8 正确解码时显示明确错误，不使用替代字符静默覆盖原内容。
- 其他编码转换不在首版范围内。

### F-04 保存

**入口：**

- `File > Save`
- `⌘S`
- 更多菜单中的 `Save`。

**规则：**

1. 已有可写文件保存回原路径。
2. 未命名文档进入保存面板。
3. 使用原子写入或系统等价的安全保存机制。
4. 保存成功后清除未保存标记。
5. 保存失败时保留编辑缓冲区与未保存状态。
6. 保存前检查磁盘文件是否已发生外部变化。
7. 保存过程不能阻塞连续输入。

若保存过程中产生新编辑，保存完成后不能错误地将新内容标记为已保存。必须以保存时的文档版本作为基准。

### F-05 另存为

**入口：**

- `File > Save As…`
- `⇧⌘S`

**行为：**

- 选择新路径后，将当前内容写入目标文件。
- 成功后，当前文档会话切换为新文件；窗口内其他文档不受影响，侧栏同步更新名称与路径。
- 若目标实际文件已由其他会话打开，阻止另存为覆盖并引导切换至该会话或选择其他路径，避免形成双重编辑状态。
- 原文件保持原状。
- 首存及另存为须区分不存在目标、当前源文件和另一个已有目标。覆盖普通已有目标需确认该目标的具体版本，提交前变化则重新确认或中止；不存在目标使用排他创建。不能将源文件基线作为另存目标的覆盖依据。
- 相对资源路径按新文档位置重新解析。
- 首版不自动复制图片或重写相对路径。

### F-06 关闭与退出

区分文档切换、关闭文档、关闭窗口与退出应用：

- 切换文档不等于关闭，不触发保存确认。
- `File > Close Document` / `⌘W` 关闭当前活动文档。
- `File > Close Window` / `⇧⌘W` 或窗口关闭按钮关闭整个窗口。
- 关闭当前文档后激活列表中相邻文档；关闭最后一个文档后，有关联目录则保留侧栏与空内容区域，无关联目录则关闭窗口。
- 无活动文档时禁用文档保存、导出和 Close Document，仍允许打开、新建与关闭窗口。

存在未保存内容时显示原生确认对话框：

- `Save`
- `Don’t Save`
- `Cancel`

规则：

- 保存失败不得继续关闭。
- 用户取消保存面板，视为取消关闭。
- 关闭窗口时检查其中所有文档，包括当前不可见文档；退出应用时检查所有窗口的所有文档，逐一完成确认。
- 多文档关闭逐个执行：单个文档完成保存或明确选择放弃后，关闭该会话并清理或更新对应草稿；全部会话处理完毕后才关闭窗口。
- 任一文档取消或保存失败即中止本次窗口关闭或退出，保留当前及尚未处理的会话；此前已关闭的会话不重新打开，已完成的保存不回滚。
- 不得出现“草稿已因放弃而清理，但该会话仍留在窗口内保持脏状态”的中间结果。应用内删除按 F-10 遇到脏文档即中止，不能调用关闭逻辑擅自放弃或清理草稿。
- 已保存文件和从未编辑的空白文档可直接关闭。
- 放弃确认后、异步清理开始前，安全结束组合输入并核验确认对应内容；清理期间禁止该会话接收新字符修改，失败恢复可编辑状态。干净关闭的异步清理同样保护，不能清理期间变脏后直接关闭。
- 退出期间暂停接纳新建、打开和移入会话，未提交的打开请求暂存；取消退出后恢复处理。向系统确认退出前再次核验存活会话与在途请求；不可将初始关闭清单视为最终全应用状态。

### F-07 最近打开与会话恢复

- 使用原生 `Open Recent` 菜单。
- 提供 `Clear Menu`。
- 最近记录不等于永久文件权限。
- 无法访问的文件要求重新选择或授权。
- 正常退出后的恢复遵循系统设置。系统允许恢复时，首版必须恢复可访问的已保存文件集合、活动文档和关联目录；不恢复未命名空白文档。
- 原窗口归属与列表顺序优先恢复，原布局不可用时允许合理归并无根目录或关联相同根目录的窗口；不同根目录仍使用独立窗口，不能因归并丢失关联目录。原活动文档不可访问时激活其他有效文档并明确提示。
- 侧栏显隐、宽度、目录展开状态、精确滚动位置、视图模式及逐文档分栏比例尽力恢复；恢复失败时采用安全默认值，不阻塞首版发布。
- 目录恢复需有效授权，权限失效时提示重新选择，不阻止可访问文档打开。文档内容、草稿及保存基线的恢复可靠性不属于可降级项。
- 以上降级仅针对重启后的界面还原；运行中的会话切换仍必须保留编辑缓冲区、独立撤销、选择、阅读位置和视图状态。
- 单文件新窗口默认隐藏侧栏；恢复窗口尽力使用原有显隐状态，无有效记录且恢复多个文档时显示已打开文档导航。
- 用户明确选择 `Don’t Save` 后，不得在下次启动时恢复其主动放弃的编辑。

### F-08 打开文件夹与目录导航

**入口：**`File > Open Folder…`、更多菜单 `Open Folder…`；已有根目录时使用 `Change Folder…`。File 菜单另提供 `Close Folder` 与 `Open Folder in New Window…`。

**范围与行为：**

- 使用原生目录选择面板，由用户明确选择并授权本地文件夹；无需导入、创建项目或生成配置文件。
- 每个窗口最多关联一个根目录。没有文档窗口时创建窗口；当前窗口未关联目录时直接使用该窗口。
- 已有关联目录时，`Change Folder…` 在当前窗口选择新的根目录；选择成功并获得权限后替换导航根目录，取消或授权失败则保留原目录。选中相同目录只显示侧栏，不重复加载会话。
- `Close Folder` 解除当前窗口的目录导航关系。更换或关闭文件夹都不关闭、保存或丢弃任何已打开文档；原目录中的文档继续出现在 `Open Documents`。
- 根目录切换后丢弃旧目录的迟到枚举结果，清理不再需要的目录监控；文档与图片仍需要的已授权访问按使用者生命周期保留，不能随关闭文件夹被提前撤销。
- `Open Folder in New Window…` 是显式另开目录窗口入口。普通更换目录不新增窗口。
- 打开文件夹后显示侧栏，但不批量打开目录中的文件、不自动选择首个文件。没有活动文档时，内容区仅显示简短的选文件提示，不生成空白文档。
- 目录按需枚举，展开时加载子项，不启动全文索引或为了过滤空目录递归扫描整个目录树。
- 默认展示文件夹及 `.md`、`.markdown`、`.mdown` 文件；隐藏点开头的隐藏项、应用包，以及名称为 `node_modules` 的依赖目录，首版不提供忽略规则配置。
- 文件夹优先、名称自然排序。无 Markdown 文件的文件夹允许显示，展开后可显示空状态。
- 点击文件在当前窗口打开或激活会话，遵守 F-02 的全应用去重规则；若文件属于其他窗口，则聚焦该窗口，不隐式迁移。
- 高亮当前文件；同名文件通过相对路径或父目录信息消歧。提供 `Reveal in Finder`，以及按 F-02 区分的 `Open in New Window` / `Move to New Window` 文件上下文操作。
- 提供 F-10 定义的树内新建文件、新建文件夹及移到废纸篓；`⌘N` 仍按 F-01 创建未命名文档。不提供树内重命名、任意位置移动、拖动整理、多根目录或项目级搜索。
- 目录浏览不打开文档、不建立文档文件监控或预览；仅实际打开的文件创建文档会话。
- 监听已加载目录的变化并合并刷新；外部删除、移动、Git 替换不应让目录树与磁盘长期失配。刷新失败显示可重试状态，不能清除文档缓冲区。
- 目录不可访问时保留已打开文档，提示重新授权；不得因导航失败丢弃未保存内容。只有读权限时仍可浏览与编辑缓冲区，创建和移到废纸篓按实际写权限禁用或明确反馈失败。

**权限与性能：**

- 打开单个文件不等于获得父目录权限。侧栏无根目录时提供 `Open Folder…`；不能未经用户授权自动枚举父目录。
- 目录授权按安全作用域管理和恢复；符号链接解析后仍需校验边界，越出授权范围需另行授权。首版不递归展开符号链接目录，避免循环遍历。
- 目录授权可由受控资源解析器用于范围内的本地图片，但绝不转换为 WebView 对整个目录的任意读取权限。
- 目录枚举在后台进行，结果绑定窗口与根目录身份，失效结果必须丢弃。列表采用按需呈现，较大目录提供加载反馈且不得阻塞编辑。

### F-09 文件侧栏与多文档会话

**入口：**标题栏 `Toggle Sidebar`、`View > Show Sidebar / Hide Sidebar`、`⌃⌘S`。

- 侧栏包含 `Open Documents` 与关联目录树；未关联目录时不展示空目录树，提供打开文件夹入口。
- `Open Documents` 列出窗口内全部会话，包括未命名文件和根目录外文件；顺序按打开时间保持稳定，切换不重排。
- 每项显示名称、当前选中状态、未保存标记，并提供关闭操作；冲突状态有可访问的明确提示，不能只靠颜色。
- 单击即切换文档，不引入临时预览文档、双击固定或标签固定语义。
- 切换前结束或提交有效的输入法组合输入，不丢字；切换后保留各会话文本、未保存状态、撤销历史、选择、滚动锚点、视图模式与分栏比例。
- 后台文档继续参与草稿备份、外部变更检测和退出确认。后台冲突可延迟至激活时展示详情，但必须标记，不得静默覆盖。
- 隐藏侧栏不关闭文档。首次多文档自动显示和用户主动隐藏的优先级按 F-02 执行。通过 `Window > Open Documents`、`Previous Document` / `Next Document` 仍可切换；上一/下一按当前窗口列表顺序循环。
- 侧栏支持键盘选择、展开折叠、激活、关闭与焦点返回，具备 VoiceOver 名称和状态说明。
- 窗口只展示当前活动会话的编辑与预览；后台会话不能通过迟到的解析或加载结果更新当前文档。

### F-10 基础本地文件管理

首版支持新建 Markdown 文件、新建文件夹，以及将单个文件或文件夹移到系统废纸篓；不提供永久删除、批量操作、重命名和任意移动。所有磁盘变更必须由用户显式操作触发。

**入口与目标：**

- `File > New File in Folder…` / `在文件夹中新建文件…`、`New Folder…`，以及目录树上下文菜单中的 `New File…`、`New Folder…`。File 菜单强调创建位置，树内菜单已有目录上下文，不必重复长名称。
- 目录树选中文件夹时，以该文件夹为创建位置；选中文件时使用其父目录；未选中树节点时使用窗口关联的根目录。
- 创建对话框明确显示目标父目录；无关联目录或权限不足时禁用相应菜单并提供打开文件夹或授权途径。`⌘N` 不受目录选择影响。
- `Move to Trash…` 位于目录树文件/文件夹上下文菜单，不设常驻垃圾桶按钮或首版删除快捷键，避免编辑文本时误触磁盘删除。
- `Open Documents` 中的关闭操作只关闭会话，绝不删除文件；删除只能针对明确的目录树节点。首版不允许删除当前窗口关联的根目录。

**新建文件与文件夹：**

- 使用轻量原生命名对话框。默认文件名为本地化的 `Untitled.md` / `未命名.md`，文件夹建议名为 `New Folder` / `新建文件夹`。
- 文件只创建受支持的 Markdown 类型；无扩展名时补 `.md`，保留 `.md`、`.markdown`、`.mdown`，不支持的扩展名要求用户修正。
- 校验空名称、`.`、`..`、路径分隔符和系统非法名称；输入视为单个名称而非路径，不允许路径穿越或隐式创建多层目录。支持中文、空格和其他合法 Unicode 名称。
- 名称会被当前导航规则隐藏（如点开头名称或 `node_modules` 文件夹）时，在创建前明确提示“此项目不会显示在当前文件树中”；成功后提供 `Reveal in Finder`。隐藏的 Markdown 文件仍可进入已打开文档列表；隐藏文件夹创建后选中其可见父目录，不声称已在树内选中新项。
- 同名目标存在时不覆盖，提示更名；按目标文件系统的实际大小写及名称等价规则检查，并使用排他创建机制处理检查后的竞争。
- 文件以 UTF-8 无 BOM、LF 策略创建为空文件，成功后刷新父目录并在当前窗口打开已保存状态的会话；首个编辑产生未保存标记。可见文件夹创建成功后选中该文件夹，不创建文档会话；隐藏项按上述反馈规则处理。
- 取消不创建文件或文件夹；失败保留输入并显示本地化错误，不留下误导性的成功状态。若磁盘创建成功但会话打开失败，明确告知文件已创建并可重试打开，不能误报磁盘创建失败。

**移到废纸篓与文档保护：**

- 使用系统移到废纸篓 API，不以永久删除作为失败回退。无废纸篓支持、权限不足、目标已变化或操作失败时保留会话并说明原因。
- 最终删除确认必须显示目标名称与路径。删除文件夹的确认必须强调将包含全部实际子项（包括树中隐藏或未显示的非 Markdown 文件），不得让用户误以为仅删除可见 Markdown。
- 执行前检查全应用受影响的已打开会话，包括其他窗口内的目标文件、目录子文件，以及位于目标目录下的浏览根目录。
- 删除范围内存在未保存文档时，本次操作不进入磁盘删除阶段。显示受影响文档的名称和路径，提供定位/切换文档的操作；告知用户先保存、另存为或关闭这些文档后，再手动重试删除。
- 删除流程本身不提供逐文档 `Don’t Save` 或强制另存为步骤，不放弃缓冲区、不清理草稿，也不在用户处理修改后自动继续删除。普通保存、另存为和关闭各自遵循 F-04～F-06。
- 明确提醒：保存到原路径后再删除，保存后的磁盘版本也将被移到废纸篓；若需保留独立文件，应另存到删除范围之外。关闭时主动放弃的未保存编辑不能从废纸篓恢复。
- 受影响会话按实际文件身份和目录归属判定；没有源路径的未命名文档不会仅因同处一个窗口而被纳入。已有源路径但身份不确定时，阻止删除并要求重新定位，不猜测它无影响。
- 只有不存在受影响脏文档时才显示最终删除确认。执行前重新核验目标身份、权限与相关会话状态；如新增编辑、目标替换或归属不确定，立即中止并要求重新处理/确认。
- 成功后关闭仍指向已删除目标的干净会话，刷新相关窗口的树；根目录因此失效的窗口进入目录不可用状态。已另存到范围外的会话保持打开。文件事件按一次已知应用操作协调，避免重复冲突弹窗。
- 操作失败时保留全部会话、缓冲区和草稿，不以清理恢复内容作为删除准备步骤。
- 成功后不承诺编辑器 Undo 能恢复磁盘删除；需要恢复磁盘版本时使用 Finder 的废纸篓。
- 文件操作权限与预览资源读取权限分离。链接节点的磁盘操作针对链接本身，不跟随链接删除目标；对目标父目录解析、权限范围和链接变化做校验，不通过符号链接越界创建或删除。

## 6.2 Markdown 源码编辑

### E-01 基础编辑能力

必须支持：

- 键盘输入、粘贴、剪切、复制、全选。
- 多级撤销与重做。
- 中文、日文等输入法组合输入。
- Unicode、Emoji 和组合字符。
- 标准 macOS 文本导航与选择快捷键。
- 软换行。
- 选中多行后缩进与取消缩进。

编辑器必须是纯文本编辑器，禁止自动转换为富文本。

### E-02 源码样式

- 默认使用系统等宽字体，约 15–16 pt。
- 行高约为字号的 1.6 倍。
- 不显示行号、代码缩略图、折叠按钮或缩进参考线。
- 不显示整行背景高亮。
- 语法高亮保持低饱和度，不影响可读性。

高亮范围至少包括：

- 标题标记。
- 强调、加粗。
- 行内代码与围栏代码块。
- 链接与图片语法。
- 列表与引用标记。
- 表格分隔语法。

### E-03 输入行为

- 默认关闭智能引号和智能破折号替换。
- 不自动改写 URL、标点或 Markdown 内容。
- 粘贴富文本时只保留纯文本。
- Return 默认继承当前行缩进。
- 首版不自动续写列表标记，避免隐式内容修改。
- Tab 插入 4 个空格；选中多行时统一缩进。
- Shift–Tab 取消一级缩进。
- 在 macOS 全键盘导航模式下，遵循系统焦点导航约定。

### E-04 编辑状态与撤销

- 未保存状态由内容相对保存基线的差异决定。
- 撤销回到已保存内容时，应恢复已保存状态。
- 语法高亮和预览更新不能进入撤销栈。
- 输入法候选组合阶段不得重建文本视图、移动光标或破坏候选窗口。
- 自动草稿备份不影响撤销历史或文档已保存状态。

## 6.3 查找与替换

### E-05 查找

**入口：**`⌘F`

行为：

- 在当前查找目标区域顶部临时展开紧凑查找栏：Editor / Split 使用编辑区，Preview 使用预览区。
- 查找栏仅在使用时出现，不作为常驻 UI。
- 高亮匹配项，显示当前项与总数。
- 支持下一项、上一项。
- `Esc` 关闭并将焦点返回本次查找对应的编辑器或预览。
- 在 Editor 或 Split 模式，查找范围是 Markdown 源码；不搜索渲染生成的 HTML 标签。
- 在 Preview 模式，`⌘F` 在预览顶部临时显示查找栏，搜索当前渲染文档中的可见文本，不切换为双栏；“可见文本”指整个渲染文档的展示文本，不仅当前视口，不包含隐藏元素、脚本或 HTML 标签属性。
- 预览查找支持普通文本、区分大小写、当前项/总数、上一项/下一项及 `⌘G` / `⇧⌘G`；定位匹配项时滚动到对应位置，Esc 关闭并返回预览焦点。
- 源码和预览匹配数可能不同。视图切换时保留查询字符串，但按新的查找范围重新计算结果；关闭查找栏不改动正文或文档脏状态。
- 预览重新渲染后重新计算匹配，尽力保留当前匹配位置；高亮仅由应用受控逻辑生成，不允许文档调用查找桥接，也不能污染导出内容。

### E-06 替换

通过 `Edit > Find > Find and Replace…` 或源码查找栏中的展开控件进入。替换始终作用于源码；Preview 模式触发该命令时切换为 Split 并打开源码替换栏，保留查询字符串并按源码重算匹配。预览查找栏不提供直接修改渲染文本的替换控件。

首版提供：

- 替换当前项。
- 全部替换。
- 区分大小写选项。
- 普通文本匹配，不支持正则表达式。

`Replace All` 必须作为一个可撤销操作。空查找字符串不得触发替换。

## 6.4 Markdown 渲染

### R-01 支持语法

解析行为以选定版本的 CommonMark 和以下 GFM 扩展为基准：

| 类型 | 支持要求 |
|---|---|
| 标题 | ATX 与 Setext 标题 |
| 段落 | 常规段落、软换行、硬换行 |
| 强调 | 斜体、加粗 |
| 删除线 | GFM 删除线 |
| 列表 | 有序、无序、嵌套列表 |
| 任务列表 | 渲染复选框，不直接修改源码 |
| 引用 | 普通及嵌套引用 |
| 代码 | 行内代码、缩进代码块、围栏代码块 |
| 表格 | GFM 表格与列对齐 |
| 链接 | 内联链接、引用链接、自动链接 |
| 图片 | 相对路径、本地受控资源、HTTP/HTTPS 图片 |
| 分隔线 | 标准 Markdown 分隔线 |
| HTML | 经安全清洗的有限 HTML |

首版不支持：

- 数学公式。
- Mermaid。
- 脚注扩展。
- YAML front matter 元数据识别。
- 自定义 Markdown 扩展。

不支持的语法按标准解析结果显示，不应导致错误或空白预览。

### R-02 代码高亮

- 支持常用语言：Swift、JavaScript、TypeScript、Python、JSON、HTML、CSS、Bash。
- 未识别语言按普通代码显示。
- 高亮组件随应用打包，不依赖 CDN。
- 大代码块可降级为无高亮文本，不能阻塞编辑。
- 不常驻显示复制按钮或语言徽标。

### R-03 实时更新

- 默认启用，无需开关。
- 常规输入后约 120–180 ms 合并触发一次渲染。
- Markdown 解析在非主线程执行。
- 使用版本号丢弃过期结果，旧渲染不能覆盖新文档。
- 不因每次输入重新加载整个 WebView。
- 更新时保留预览位置，避免跳回顶部。
- 渲染失败时保留最后一次有效结果，并显示简短、可关闭的错误提示。

## 6.5 视图与同步滚动

### V-01 三种视图

| 模式 | 显示内容 | 快捷键 |
|---|---|---|
| Editor | 仅源码 | `⌘1` |
| Split | 源码与预览 | `⌘2` |
| Preview | 仅预览 | `⌘3` |

规则：

- 新文档会话默认双栏；重启恢复的文档尽力使用已记录模式，无有效记录时回退双栏。
- 三种视图仅控制正文区域，与侧栏显隐独立。
- 切换模式不得丢失光标、选择、撤销历史或滚动位置。
- 单栏模式占用完整正文空间。
- 预览模式仍允许保存已有修改。
- 输入焦点返回编辑模式时，应回到之前的编辑位置。

### V-02 同步滚动

双栏默认双向同步，不提供常驻按钮；通过 `View > Sync Scrolling` 勾选菜单可临时关闭或重新启用。开关按当前文档会话保存，运行中切换文档不重置；新文档及重新启动后的默认值为启用。单栏模式保留开关状态但不触发跟随。

**行为定义：**

- 启用同步时，用户主动滚动哪一栏，哪一栏成为当前滚动源；关闭同步时允许两栏独立滚动，预览自身更新仍需尽量保持阅读位置。
- 从关闭切回启用时，以最近获得正文交互的栏为基准对齐另一栏；不得双向同时争抢位置。
- 程序触发的跟随滚动不得再次反向触发，避免循环抖动。
- 源码标题、段落、列表、表格、代码块映射到预览块。
- 优先按块级源码位置同步，不以全文百分比作为主要算法。
- 块内部采用相对位置插值。
- 对无法精确映射的内容使用邻近有效块或比例回退。

**编辑更新：**

- 预览更新前记录顶部可见块及块内偏移。
- 更新后恢复对应位置。
- 插入内容导致原锚点消失时，选择最近存续块。
- 图片异步加载改变高度后，重新校正映射，避免明显跳动。

**验收基准：**

- 首版发布要求：跟随栏能显示对应内容块或其合理邻近位置，不出现滚动互相争抢、持续振荡或突然跳顶。
- 大型表格、长代码块、图片区域允许块内插值或邻近有效块回退，不承诺所有排版情况下达到逐行精度。
- 对固定的普通标题、段落和列表测试夹具，以同步源顶部可见块及块内偏移为基准，记录目标栏定位误差；“约一个正文行高以内”仅作为优化目标，不作为全内容发布门槛。
- 关闭同步后任一栏滚动不移动另一栏；重新启用行为明确、无持续抖动。

## 6.6 图片、链接与本地资源

### A-01 本地图片

相对路径以 Markdown 文件所在目录为基准。

支持常见格式：

- PNG、JPEG、GIF、WebP。
- SVG 仅以受限图片资源方式显示，不作为可执行文档加载。

权限规则：

- 不因打开一个文件而默认获得任意目录访问权限。
- 沙盒环境下访问未授权目录时，通过非模态提示请求用户选择并授权资源目录。
- 仅在明确授权范围内解析资源。
- 规范化路径并解析符号链接后校验权限，防止路径穿越。
- 尚无文件路径的未命名文档无法可靠解析相对路径，显示占位并提示先保存；已有文件路径但存在未保存修改的文档，仍以其当前文件所在目录解析资源。

加载失败时显示轻量占位、替代文本或原因，不遮挡整个预览。

首版仅解析图片引用；不提供图片粘贴、拖入自动复制或附件管理。

### A-02 远程图片

- 默认不自动请求网络图片。
- 检测到远程资源时，预览顶部显示临时提示：`Remote images are blocked.`
- 提供 `Load Images` 操作。
- 授权仅对当前文档会话生效。
- 加载超时或失败时显示占位，不阻塞渲染。
- 不提供任意证书错误绕过。

该策略避免用户仅打开 Markdown 文件就向第三方暴露网络请求。

### A-03 链接行为

- 同文档锚点：在预览内跳转。
- `https:`、`http:`：经用户点击后调用默认浏览器。
- `mailto:`：调用系统邮件处理程序。
- 相对 Markdown 链接：在权限允许时按 F-02 在当前窗口打开或激活；目标已在其他窗口打开时聚焦已有会话。
- 其他本地文件链接：仅经明确用户点击后交给系统处理。
- 拒绝 `javascript:` 和其他未允许的执行型协议。
- 不允许文档脚本自动发起导航。

## 6.7 导出

### X-01 导出 HTML

**入口：**

- `File > Export > HTML…`
- 更多菜单 `Export > HTML…`

行为：

1. 以当前编辑缓冲区为内容来源，包括未保存修改。
2. 生成完整 UTF-8 HTML 文档。
3. 内嵌预览样式与代码高亮样式。
4. 不包含应用脚本、桥接代码、应用附加的追踪信息或应用生成的内部资源地址（如容器临时路径、预览私有协议 URL）。用户正文及显式链接中原有的路径不自动脱敏；导出不是全文隐私清洗服务，用户提供的链接仍须遵守协议安全限制。
5. 默认文件名与 Markdown 文件同名，扩展名为 `.html`。
6. 原 Markdown 文件及其未保存状态不变。

**资源策略：**

- 可访问的本地图片内嵌为数据资源，使导出文件可独立打开。
- 已授权且成功加载的远程图片可内嵌。
- 未授权、不可访问或加载失败的资源不隐式下载。
- 存在缺失资源时先提示，允许取消或导出占位版本。
- 导出 HTML 不包含脚本。

### X-02 导出 PDF

**入口：**

- `File > Export > PDF…`
- 更多菜单 `Export > PDF…`

要求：

- 导出完整文档，不是当前可见区域截图。
- 使用独立打印样式。
- 默认白底深色正文，不随系统深色模式变成黑底。
- 默认 A4 页面、合理页边距。
- 保留文字可选择性和可点击链接，具体以渲染引擎能力验证。
- 代码、长链接和表格需防止横向裁切。
- 标题尽量不单独落在页尾。
- 高于单页的块允许合理分页，不强求完整保留。
- 缺失图片处理与 HTML 导出一致。

### X-03 导出状态与目标保护

以下目标保护同时适用于 HTML 和 PDF：

- 导出面板按格式约束扩展名；写入前按实际文件身份与规范化路径校验目标，不仅比较用户输入的路径字符串。
- 禁止覆盖源 Markdown 文件及任一已打开文档对应的实际文件，包括通过符号链接等别名指向它们的目标；提示选择其他路径。
- 对其他已存在目标明确确认覆盖；确认后目标发生外部变化时重新确认或中止，不能将旧确认应用于新目标。
- 先在临时文件完整生成结果，再以原子替换或系统等价的安全机制提交目标；失败或取消只清理本次临时产物，不删除、截断或损坏原有目标。
- 提交前重新核验目标保护条件，避免导出期间目标被其他会话打开或发生身份变化后仍覆盖。

- 导出绑定启动时的文档版本快照。
- 导出期间用户继续编辑，不影响已启动的导出内容。
- 耗时超过 500 ms 时显示轻量进度状态。
- 较长任务支持取消。
- 失败时清理临时文件，不留下误导性的完整目标文件。
- 成功后默认不弹出模态提示；可提供短暂的 `Show in Finder` 操作。

## 八、数据安全与异常处理

### 8.1 自动保存策略

V1.0 **不自动覆盖用户原文件**。

采用：

- 手动保存原文件。
- 自动备份恢复草稿。

必须明确区分“恢复草稿已更新”和“文件已保存”，草稿备份不能清除标题栏未保存标记。

### 8.2 草稿恢复

- 文档有修改时，停止输入约 2 秒后更新恢复草稿；所有未保存会话均参与，包括不可见的后台文档。切换文档不清除草稿或重置其备份期限。
- 持续输入期间，所有规模的未保存会话统一最长每 30 秒提交一次检查点；停止输入约 2 秒的触发不变。30 秒是成功检查点的期限，不只是启动任务的间隔；存储失败时保留上一有效检查点并持续提示。此口径为 2026-09-17 评审批准的需求变更，取代原 10 秒要求。
- 原子更新草稿，避免备份本身损坏。
- 记录内容、源文件路径引用、源文件基线信息和更新时间。
- 应用内移到废纸篓遇到受影响脏文档时中止，要求用户先处理修改；删除流程不得放弃内容或清理草稿，遵循 F-10。
- 草稿存储在应用容器，不上传。
- 崩溃后启动时提供 `Restore`、`Discard`。
- 恢复内容不得自动覆盖磁盘文件。
- 原文件已改变或不可访问时，以恢复副本打开并提示用户另存为。
- 用户主动放弃修改后清理对应草稿。
- 成功保存后清理或更新检查点基线。

### 8.3 外部修改检测

需要识别：

- 内容被其他程序更改。
- 文件被重命名或移动。
- 文件被删除。
- 文件权限变为只读。
- Git checkout 等通过替换文件实现的变化。

| 当前状态 | 处理 |
|---|---|
| 无本地修改，磁盘内容改变 | 自动重新加载，并尽量保留位置 |
| 有本地修改，磁盘内容改变 | 显示非模态冲突提示，不覆盖任一版本 |
| 文件被外部删除 | 保留内存内容，提示另存为或明确重新创建；应用内显式移到废纸篓按 F-10 协调 |
| 文件变为只读 | 允许继续编辑，保存时提示另存为 |
| 文件成功跟踪到新路径 | 更新标题与路径引用 |
| 路径失效且无法跟踪 | 保留内容，要求重新定位或另存为 |

冲突操作：

- `Reload from Disk`：确认后放弃本地修改与旧撤销历史；成功重载同时持久废弃旧恢复代次，旧草稿不作为自动恢复或历史版本入口。读取失败保留原缓冲区、撤销与草稿；读取期间产生新编辑则中止应用结果，重新处理冲突，不沿用旧确认。
- `Save As…`：保存当前内容到新文件。
- `Overwrite…`：再次确认后覆盖磁盘版本。

冲突期间执行 `⌘S` 必须进入冲突处理，不得静默覆盖。

### 8.4 错误反馈等级

| 错误类型 | 反馈方式 |
|---|---|
| 图片加载失败 | 局部占位 |
| 网络资源被阻止 | 预览区临时提示 |
| 渲染异常 | 保留旧预览，显示轻量提示 |
| 外部文件冲突 | 非模态提示条 |
| 保存失败 | 原生错误对话框 |
| 放弃未保存内容 | 原生确认对话框 |
| 新建文件/文件夹失败 | 命名对话框内本地化错误，保留输入 |
| 移到废纸篓 | 明确目标及影响范围的确认；失败保留会话并显示原因 |
| 无法打开文件 | 明确错误原因与可操作建议 |

提示条仅在异常时出现，不计入默认常驻 UI。

## 九、安全与隐私要求

### 9.1 本地优先

- 不上传文件内容、文件路径、图片或草稿。
- 不要求账户。
- 不默认集成分析 SDK。
- 不在日志中记录正文内容。
- 诊断导出必须由用户主动触发，并对路径等信息做脱敏。

### 9.2 预览内容隔离

Markdown 视为不可信输入。

必须：

- 清洗原始 HTML。
- 移除脚本、事件处理器、iframe、表单和嵌入式执行内容。
- 移除文档提供的任意样式、外部样式表和影响页面导航的标签。
- 通过 CSP 限制资源与执行来源。
- 严格限制 WebView 原生桥接消息类型与参数。
- 禁止文档内容调用任意原生 API。
- 禁止任意本地文件读取。
- 避免文档注入元素伪造应用控制界面。

若预览同步需要 JavaScript，只允许应用受控脚本执行；不得允许文档携带脚本。

### 9.3 网络请求

- 未经用户授权，不加载远程图片。
- 不在渲染阶段自动访问外部链接。
- WebView 使用非持久化站点数据存储，避免文档间共享第三方 Cookie。
- 不依赖远程字体、CDN 或在线渲染服务。

## 十、技术实施建议

### 10.1 推荐架构

| 层级 | 建议方案 | 职责 |
|---|---|---|
| 文档层 | NSDocument 或等价原生文档控制器 | 独立文档会话、保存、脏状态、全应用文件去重 |
| 窗口层 | 原生窗口控制器与会话容器 | 会话归属、活动文档切换、窗口关闭与恢复 |
| 导航层 | 轻量目录模型与文件侧栏 | 单根目录授权、按需枚举、已打开文档列表 |
| 文件操作层 | 原生文件系统与废纸篓 API | 排他创建、删除预检、跨窗口会话保护及操作结果协调 |
| 本地化层 | String Catalog 或等价资源 | en / zh-Hans 文案、格式化、回退与本地化测试 |
| 编辑层 | NSTextView / TextKit | 输入、选择、撤销、查找、高亮 |
| UI 层 | AppKit 为主，可局部使用 SwiftUI | 原生窗口、标题栏、菜单、分栏 |
| 渲染层 | 本地 Markdown 解析器 | AST、HTML、安全清洗、源码位置映射 |
| 预览层 | WKWebView | 排版、锚点、同步滚动 |
| 资源层 | 受控资源解析器 | 本地授权、图片加载、路径校验 |
| 导出层 | HTML 打包与分页渲染 | 独立 HTML、PDF |
| 恢复层 | 应用容器内恢复存储 | 草稿检查点与恢复 |

如使用 NSDocument，需要显式配置自动保存行为，确保不会违背“手动保存原文件”的产品约定。

不能假定 NSDocument 默认窗口模型直接满足同窗口多文档需求。应先验证文档对象与窗口容器的解耦、菜单命令路由、撤销管理器切换和窗口关闭协调，再决定采用 NSDocument 或等价文档控制器。一个窗口可包含多个会话，但每个会话只属于一个窗口；文件树节点不等于已打开文档。

### 10.2 模块边界

建议按以下职责组织，名称为参考，不要求每项都对应独立类、服务或模块；允许在职责清晰、可测试的前提下合并实现：

- `DocumentController`
- `DocumentSession`
- `WindowSessionController`
- `FolderNavigationModel`
- `SidebarController`
- `FileOperationService`
- `LocalizationResources`
- `EditorController`
- `MarkdownRenderer`
- `PreviewController`
- `ScrollSyncCoordinator`
- `ResourceResolver`
- `ExportService`
- `RecoveryStore`
- `FileChangeMonitor`

界面层不得直接承担磁盘写入、资源授权或 HTML 清洗职责。

### 10.3 文档状态模型

以下为文档状态职责的参考模型，不要求逐项建立同名字段或独立持久化副本；可采用能满足生命周期、恢复及安全验收的等价实现：

```text
documentID
fileURL / securityScopedBookmark
textBuffer
contentRevision
savedRevision
savedContentFingerprint
diskBaselineFingerprint
encodingAndBOM
lineEndingStyle
viewMode
splitRatio
syncScrollingEnabled
selectionRange
editorScrollAnchor
previewScrollAnchor
resourcePermissions
externalChangeState
recoveryCheckpoint
```

要求：

- 用文档版本号协调渲染、保存、导出。
- **判脏以内容与保存基线的实际差异为准**（见 E-04、AC-06）：上表的 `savedRevision` 仅用于协调异步结果归属，**不得用 `contentRevision == savedRevision` 或撤销计数器作为判脏依据**，否则撤销回基线时无法恢复已保存状态。具体机制由技术设计确定（当前方案见 TAD-001 §3.4 的长度快速判断与规范文本精确比较、ADR-001 D11）。
- 用磁盘指纹检测外部变化，不能只依赖修改时间。
- UTF-8 字节偏移、编辑器 UTF-16 索引与行位置必须有明确转换，覆盖 Emoji、中文和组合字符。
- 程序自身保存引发的文件事件应去重，不误报外部冲突。

窗口状态与文档状态分离。以下为窗口参考模型，具体字段和存储方式由技术设计确定，产品所要求的恢复行为仍需满足：

```text
windowID
orderedDocumentIDs
activeDocumentID
rootFolderURL / securityScopedBookmark
sidebarVisible
sidebarWidth
expandedDirectoryPaths
sidebarExplicitlyHiddenThisRun
```

`sidebarExplicitlyHiddenThisRun` 仅表达当前窗口运行期间的用户选择，不要求跨重启持久化。重启恢复的强制项和尽力项以 F-07 为准；同步开关的会话范围与启动默认值以 V-02 为准。

目录授权采用共享引用计数或等价生命周期管理，不能因为一个文档关闭就撤销其他文档仍需要的访问。文档恢复检查点按 documentID 隔离；恢复文件访问仍必须验证授权。

### 10.4 渲染链路

```text
文本变更
 → 更新内存文档版本
 → 合并高频更新
 → 后台解析 Markdown
 → 生成带源码范围的安全块结构
 → 丢弃过期结果
 → 更新 WebView 正文
 → 恢复预览锚点
 → 更新滚动映射
```

首版可采用“替换正文 DOM + 锚点恢复”，不强制实现复杂增量 DOM diff；但禁止每次输入重载整个 WebView。

### 10.5 必须先完成的技术验证

在大规模实现前验证：

1. 所选解析器的 GFM 支持、源码范围精度和许可证。
2. 中文输入法与语法高亮是否稳定共存。
3. 长代码块和表格下的滚动映射。
4. App Sandbox 下相对图片授权体验。
5. 安全 HTML 清洗与应用脚本隔离。
6. PDF 多页输出、表格分页和长代码换行。
7. 同窗口多文档切换：输入法、独立撤销栈、菜单路由、后台草稿、关闭确认及会话移至新窗口。
8. 目录授权与更换/关闭、按需枚举、大目录响应；验证并确定窄窗口导航策略及其键盘和辅助功能操作，不预设必须自定义覆盖侧栏。
9. 沙盒内文件/文件夹排他创建、系统废纸篓支持、含跨窗口脏文档的目录删除及竞态保护。
10. 英文与简体中文资源加载、系统应用语言选择、原生菜单本地化及中文长文案布局。
11. 预览可见文本查找、结果计数与导航、DOM 更新后的重新匹配，以及高亮不污染导出。

上述验证不通过时，应调整实现方案，而非在后期降低数据安全要求。

## 十一、非功能需求

### 11.1 大文件策略

| 文件规模 | 行为 |
|---|---|
| ≤ 1 MB | 完整体验目标 |
| > 1 MB 且 ≤ 5 MB | 允许降低高亮与预览频率 |
| > 5 MB 且 ≤ 20 MB | 打开前提示，默认编辑模式；预览由用户主动启用 |
| > 20 MB | 首版拒绝打开，提示当前支持上限 |

本节统一按文件字节数计量，1 MB = 1,000,000 字节。外部重载也执行同样的大小检查：无本地修改且变化后超过 5 MB 时先提示，再按对应级别重载；超过 20 MB 时不载入新磁盘内容，保留现有缓冲区并标记磁盘版本已变化，提供另存为或在外部工具中打开。存在本地修改时始终优先进入冲突处理。不得将保留的旧缓冲区误标为与磁盘同步，后续保存必须经过冲突处理。

该阈值限制打开与重载，不因用户输入或粘贴超过阈值而丢弃内容；编辑中超过阈值时允许关闭或降低预览，并提示性能限制，保留保存及另存为能力。

大文档预览计算必须可取消。图片大小与解码开销独立限制，不能仅依赖 Markdown 文件体积。本地、远程、data URL 与导出资源统一受预算约束，覆盖单图、动画累计帧成本、在途并发及任务总量；不能把缓存上限当作总内存上限。超限显示局部占位或允许取消／占位导出，保留编辑与保存能力。

### 11.2 性能补充

- 主线程不执行大规模 Markdown 解析或图片解码。
- 常规输入处理不应产生连续超过 50 ms 的主线程阻塞。
- 分别验证同一窗口打开 20 个约 100 KB 文档，以及五个窗口各打开一个同规模文档；连续使用 30 分钟，不得出现持续内存增长，切换后内容与状态正确。
- 不为所有后台文档无界保留完整 WebView；非活动预览应暂停更新或按有界缓存策略释放，仅保留必要状态。编辑缓冲区和独立撤销历史不得因释放预览丢失。
- 使用至少 10,000 个条目的目录夹具验证按需枚举与列表呈现；首屏加载有反馈，不递归扫描未展开子目录，加载期间编辑保持可响应。
- 关闭文档后释放其预览资源和文件监控；安全作用域访问在最后一个使用者释放时结束。
- 用户切换文档、移动会话或关闭窗口后，后台任务结果不得更新错误会话。

### 11.3 辅助功能

- 所有图标按钮具备 VoiceOver 名称。
- 菜单、编辑器、预览和临时提示可通过键盘访问。
- 英文和简体中文分别验证 VoiceOver 名称、状态朗读、焦点顺序及对话框操作，不以英文测试代替中文验收。
- 未保存、冲突等状态不只靠颜色表达。
- 正文对比度目标至少 4.5:1。
- 跟随系统浅色、深色外观。
- 支持系统“减少透明度”“减少动态效果”。
- 系统外观切换不触发文档修改，也不重置位置。

### 11.4 国际化质量

- 发布包同时包含 `en` 与 `zh-Hans` 完整资源及本地化帮助；CI 检查资源键完整性、占位符类型与数量一致性，不得以英文回退掩盖中文缺译。
- 在英文系统、简体中文系统，以及系统语言与应用指定语言不同的环境中验证语言选择；无支持语言匹配时验证英文回退。
- 两种语言均覆盖菜单、侧栏、命名、删除确认、保存失败、冲突、草稿恢复和导出，确保无资源键裸露、异常混语或截断关键操作文案。
- 本地化测试含长文件名、中文/Emoji 路径、参数插值与数量变化；正文内容、文件名和用户目录不得被当作界面字符串翻译。
- 英文与中文主界面采用同一信息架构、控件位置和尺寸策略，不维护两套功能不同的布局。

### 11.5 分发与依赖

- 按沙盒约束设计文件访问。
- 发行包完成签名；直接分发时完成公证。
- 第三方依赖固定版本并记录许可证。
- 渲染、高亮、样式等核心资源随应用打包。
- Apple Silicon 为主要测试平台；如提供 Intel 构建，需单独完成兼容验证。

## 十二、验收标准

### 12.1 核心功能验收

| 编号 | 场景 | 验收结果 |
|---|---|---|

| AC-18 | 远程图片 | 未授权时无网络请求 |

| AC-23 | 切换脏文档 | 无保存弹窗，文本、撤销、输入法提交、选择、滚动和视图状态不丢失 |
| AC-24 | 关闭文档与窗口 | 快捷键语义正确；窗口关闭检查全部后台脏文档，取消或失败中止关闭 |
| AC-25 | 后台文档可靠性 | 草稿按期更新、外部修改不静默覆盖；崩溃恢复覆盖全部脏会话 |
| AC-26 | 侧栏与窄窗口 | 可隐藏；按技术验证确定的原生策略提供导航，不破坏正文最小宽度与视图模式；键盘及 VoiceOver 可操作 |
| AC-27 | 目录权限与变化 | 未授权不枚举；越界符号链接不读取；外部移动、删除、替换后正确刷新并保留编辑内容 |
| AC-28 | 显式多窗口 | 移动已有会话不复制缓冲区，保留撤销与脏状态；迟到任务不串文档 |
| AC-29 | 会话恢复 | 系统允许时恢复可访问文件、活动文档与目录；精细界面状态尽力恢复；权限失效可授权，内容与草稿安全不降级 |
| AC-30 | 大目录与多文档 | 通过 §11.2 目录及多文档测试，无阻塞编辑、持续内存增长或无界后台预览 |
| AC-31 | 未命名与目录外文件 | 已打开列表可访问全部会话，同名文件可消歧；侧栏隐藏时菜单仍可切换 |
| AC-32 | 多会话另存为 | 不影响其他文档；目标已由其他会话打开时阻止覆盖并提供替代路径 |
| AC-33 | 树内新建文件/文件夹 | 创建位置明确，合法 Unicode 名称可用，重名不覆盖，成功后树与会话状态正确 |
| AC-34 | 新建取消与失败 | 不越权、不路径穿越、不覆盖竞争创建的目标；取消无磁盘变更，失败文案明确 |
| AC-35 | 文件/目录移到废纸篓 | 确认含隐藏子项的真实范围；根目录不可直接删除，无永久删除回退，失败保留会话 |

| AC-40 | 双语布局与恢复 | 两种语言在最小窗口及长文案下可操作；语言切换后的重启不改变文件或丢失应恢复的会话 |
| AC-41 | 导出目标保护 | 不覆盖源文件及已打开文档；其他现有目标需确认，提交前重检；失败或取消保留原目标 |
| AC-42 | 关闭中途取消 | 已处理会话关闭，当前及剩余会话保留；无草稿已清除但会话仍保持脏状态的结果 |
| AC-43 | 隐藏项创建 | 创建前提示不可见原因，成功后可在 Finder 定位；隐藏文件会话可访问，不错误选中不可见目录 |
| AC-44 | 文件规模变化 | 阈值无重叠；外部超限不覆盖缓冲区或误清冲突；编辑中超限不丢内容，仍可保存 |
| AC-45 | 未保存修改与本地图片 | 已有路径的脏文档仍正确解析相对图片，仅无路径文档提示先保存 |
| AC-46 | 更换或关闭文件夹 | 不新增窗口、不关闭已有文档；取消/失败保留原根目录，迟到枚举不串目录，文档所需授权保留 |
| AC-47 | 纯预览查找 | 搜索整个渲染文档展示文本，不含隐藏 DOM/属性；计数与上下项正确，切换模式重算，高亮不污染导出 |

## 十四、产品决策摘要

为避免实施过程重新引入冗余设计，以下决策作为首版基线：

1. **本地文件工具，不是笔记产品。**
2. **文件优先，支持同窗口多文档和按需文件侧栏，提供新建文件/文件夹及移到废纸篓等基础本地文件管理；不设常驻标签栏，不引入 IDE 式项目管理或笔记库。保留显式多窗口能力，用于并排查看。**
3. **一个紧凑标题栏，只保留侧栏切换、布局与更多图标；单文件默认隐藏侧栏，正文空间优先。**
4. **不提供 Markdown 格式快捷工具。**
5. **不提供常驻状态栏、词数、编码和光标坐标。**
6. **默认双栏，预览自动工作；滚动默认块级双向同步，可通过菜单临时关闭，不以全内容逐行精度阻塞首版。**
7. **原文件手动保存，恢复草稿自动备份。**
8. **远程图片默认不加载，文档内容始终视为不可信输入。**
9. **次要功能通过原生菜单和快捷键提供，不牺牲功能完整性换取表面极简。**
10. **优先保证输入流畅与文件安全，再扩展 Markdown 语法和个性化能力。**
11. **从 MVP 按 i18n 设计，完整交付英文与简体中文，遵循系统应用语言，不翻译用户文档与文件路径。**
