## 1. 目标、原则与约束

### 1.1 架构目标

1. **稳定可靠**：文档操作具有清晰状态机；任何异步结果都能证明自己属于哪个会话、版本和操作；失败不得静默丢弃内容。
2. **易维护**：模块化单体、单一可变文本源、明确线程边界和依赖方向；不构造两套文档系统。
3. **可扩展**：渲染、编辑后端、文件访问与导出有窄接口；增加语法或主题无需修改保存事务。
4. **原生且轻量**：原生窗口、文本输入、菜单和权限；Web 只负责受控文档排版，不承担应用导航与文件业务。
5. **可验证**：安全、恢复、性能、双语和辅助功能都有对应测试与阶段门禁。

### 1.2 不可破坏的不变量

| 编号 | 不变量 |
|---|---|
| INV-01 | 同一实际文件在全应用中至多存在一个可独立编辑的会话 |
| INV-02 | 每个会话同时只属于一个窗口，移窗不复制文本与撤销历史 |
| INV-03 | 原文件仅因显式保存或经确认的冲突覆盖而改变；草稿不写原文件 |
| INV-04 | 保存确认对应被提交的快照，保存期间的新编辑仍未保存 |
| INV-05 | 草稿清理不能删除较新检查点，迟到任务不能复活已放弃内容 |
| INV-06 | 删除遇到受影响脏文档时中止，不在删除流程中保存、放弃或清理草稿 |
| INV-07 | 导出不得覆盖源文件或任何已打开文档，不改变文档保存基线 |
| INV-08 | 未经授权的文件、目录或远程资源不得通过预览和导出被访问 |
| INV-09 | 视图、目录、WebView 与解析任务生命周期不决定文本和撤销历史是否存在 |
| INV-10 | UI 外观、语法高亮、查找高亮和预览更新不构成文档内容修改 |

磁盘损坏、系统故障及不协作外部进程存在现实边界；不能用“原子写入”或“使用 actor”宣称消除所有故障。检测到身份不确定、权限失效或冲突时，优先保留内容并中止危险操作。

## 2. 总体架构与依赖方向

### 2.1 运行时结构

```text
macOS / Finder / 用户输入
          │
          ▼
AppCoordinator + CommandRouter                  主 actor
  ├─ DocumentRegistry ── DocumentSession[*]
  ├─ WindowRegistry ──── WindowSession[*]
  ├─ Open / Save / Close / Trash / Export 协调器
  └─ WindowController[*]
       ├─ SidebarController → NSOutlineView
       ├─ EditorHost → 会话所属 NSTextView/TextKit 后端
       ├─ PreviewController → WKWebView
       └─ 临时查找、冲突、授权与进度 UI
          │ 不可变请求 / 带身份的结果
          ▼
FileAccess / SafeWrite / Recovery / Markdown / Resource 服务
  ├─ Foundation / 受控底层文件 API
  ├─ cmark-gfm 适配器（优先验证）+ 原生安全序列化/清洗
  ├─ 容器内持久化存储
  └─ URLSession / ImageIO 等受控资源处理

WebKit 内容进程
  ├─ 受控 HTML/CSS 与隔离应用脚本
  ├─ 阶段 0 清洗对照上下文（无文件和网络能力）
  └─ 有界的独立导出上下文
```

WebKit 进程是系统实现细节，不能假定“一 WebView 一进程”或以进程分离代替会话权限隔离。

### 2.2 代码组织

拟采用一个 Xcode App target，加一个本地 Swift Package。初期仅建立有真实测试价值的边界：

```text
Marklite.xcodeproj
Marklite/
  App/                    入口、装配、系统事件、命令路由
  Application/            文档/窗口会话及操作协调
  UI/                     AppKit 窗口、侧栏、提示与菜单
  Editor/                 NSTextView/TextKit 适配、语法高亮、主题应用
  Preview/                WebView、桥接、同步、查找
  Infrastructure/
    Files/                权限、身份、协调读写、监控
    Recovery/             草稿与会话持久化
    Rendering/            解析器、安全清洗、资源处理
    Export/               HTML/PDF 任务与提交
  Resources/              xcstrings、图标、帮助、打包 Web 资源
Packages/MarkliteCore/
  Sources/                值模型、状态归约、策略、端口协议、ThemeSnapshot、安全序列化与清洗
  Tests/                  无 AppKit 的领域与故障模拟测试
WebAssets/
  src/                    TypeScript、预览样式、打印样式
  tests/                  安全、查找、几何映射夹具
Tests/
  Integration/            文件系统、恢复、WebKit 测试
  UI/                     双语、焦点、快捷键、输入法验证
  Fixtures/               文档、恶意内容、目录与故障样例
Scripts/                  实际建立后定义构建和验证入口
```

- `MarkliteCore` 不导入 AppKit、WebKit 或第三方 Markdown AST。
- 基础设施实现 Core 中的端口，应用协调层通过构造参数注入实现。
- NSTextView/NSTextStorage 不强行放进纯领域 package；其所有权由应用层会话管理。
- 不引入全局事件总线、插件 ABI、服务定位器、数据库或 React/Vue。
- SwiftUI 如用于 About 等辅助界面，只读取状态投影，不另建文本与文件模型。
- C 解析器的构建依赖在解析适配器内封装，不让 UI 依赖其节点、指针或错误码。

### 2.3 模块职责

| 模块 | 核心职责 | 禁止承担 |
|---|---|---|
| AppCoordinator | 装配、启动恢复、应用退出、系统打开事件 | 解析正文、直接保存字节 |
| DocumentRegistry | 会话注册、文件去重、归属变更 | 渲染、目录扫描 |
| DocumentSession | 文本后端所有权、基线、冲突、撤销及阅读状态 | 固定窗口生命周期 |
| WindowSession | 文档顺序、活动文档、根目录、导航偏好 | 文本副本 |
| CommandRouter | 确定命令语义和目标、菜单可用性 | 在 UI 中拼装文件事务 |
| FileOperationCoordinator | 应用内文件操作资格与提交预留 | 等待用户选择时长期锁住编辑 |
| FileAccessService | 授权租约、身份解析、受控文件读取 | 向 Web 暴露任意路径 API |
| SafeWriteService | 临时写入、条件复核、安全提交与清理 | 决定放弃用户编辑 |
| RecoveryStore | 原子检查点、墓碑、恢复扫描 | 原文件自动保存 |
| MarkdownEngine | 后台解析、范围和资源引用 | UI 或任意网络请求 |
| HTMLSafetyService | AST 安全序列化、raw HTML 清洗与受控输出结构 | 文件授权、信任原始 HTML |
| ResourceResolver | 按会话授权读图、受控下载、资源句柄 | 把根目录直接开放给 WebView |
| PreviewController | 正文展示、版本绑定、脚本桥接 | 文档写入、未授权操作 |
| ExportCoordinator | 快照、资源冻结、HTML/PDF 生成与目标保护 | 从当前活动 DOM 直接另存 |

模块名是职责名称，不要求每行都建立独立单例或 package。

## 3. 关键模型、权威状态与端口

### 3.1 身份与版本

```text
DocumentID          会话 UUID，不因另存为或移窗改变
WindowID            窗口 UUID
FileIdentity        当前实际文件的资源标识 + 卷标识等可验证信息
FileLocation        用户路径、规范化路径、源授权引用
ContentRevision     任意字符变更后递增，撤销也递增
LocationEpoch       路径/源授权基准改变后递增
BindingEpoch        预览绑定会话、导航或重建后递增
RootEpoch           窗口更换/关闭根目录后递增
RecoveryEpoch       检查点代次，放弃/关闭/恢复分支改变时推进
OperationID         单次保存、删除、导出或重载 UUID
```

`FileIdentity` 不是永久主键：安全替换和 Git checkout 可能改变资源标识。应用既维护“当前实际对象”索引，也维护“已占用规范化位置”索引，处理同路径替换而不创建重复会话。

### 3.2 文档与窗口

```text
DocumentSession (@MainActor，应用层)
  id / ownerWindowID
  editorBackend                    唯一可变文本与 UndoManager
  contentRevision / locationEpoch
  source: FileLocation?
  encodingPolicy                   UTF-8、BOM、换行风格
  savedBaseline                    已保存的规范文本快照与指纹
  diskBaseline                     原始磁盘字节指纹与身份
  dirtyStatus                      clean / dirty；仅大文件批准降级时 checking
  baselineGeneration               保存/重载改变比较基线时递增
  externalState                    current / changed / missing / inaccessible
  activity                         idle / saving / closing / trashReserved
  viewState                        模式、分栏、选择、滚动、最近交互栏
  resourceSession                  本地授权引用、远程图授权、资源代次
  recoveryState                    当前代次、最近成功检查点、故障状态

WindowSession (@MainActor，应用层)
  id / orderedDocumentIDs / activeDocumentID?
  rootFolderGrant? / rootEpoch
  sidebarRequested / sidebarPresentation
  sidebarWidth / expandedDirectoryIDs
  explicitlyHiddenThisRun / didAutoRevealDocumentsThisRun
```

采用正交状态而非一个包含几十种组合的巨型枚举。例如文档可以同时 `dirty + saving + externalChanged`，但“关闭”和“删除提交预留”不能同时获得操作资格。

### 3.3 文本与编码基线

1. 磁盘按 UTF-8 严格解码，记录 BOM、主换行风格和混合换行状态；无法解码或识别为二进制时拒绝正常打开，不做有损替换。
2. 编辑后端使用统一逻辑换行 LF；保留是否存在末尾换行，不擅自新增或删除。
3. `savedBaseline` 比较规范文本，`diskBaseline` 比较磁盘原始字节，两者不能混用。
4. 序列化时按当前编码策略输出 BOM 与 LF/CRLF。**混合换行的统一提示由保存流程在首次写入前弹原生确认对话（§11.1 捕获快照之后、申请写入资格之前）**，文案告知将统一为哪种换行与影响范围；确认后该会话不再重复询问，取消则不写入、保持脏状态。混合换行计数相同时默认 LF，作为明确的实现规则在夹具中固定。
5. 打开时的磁盘字节与编辑文本可能因换行规范化不同，不能因此把刚打开的文件标为脏。
6. 另存为改变位置，不改变 DocumentID；更新权限、文件身份和资源基准，原文件不动。

### 3.4 判脏规则（评审修订：简单、精确、可测）

**决策：长度快速判断 + 规范文本精确比较，不自研 Merkle 树、rope 或编辑历史摘要。**

1. `savedBaseline` 持有不可变的规范文本快照；字符变化后在同一主 actor 周期比较 UTF-16 长度，不同则立即 dirty。
2. 长度相同时，按 UTF-16 code unit 逐项精确比较，首个差异即可停止；可使用经验证的原生字面比较接口，不用 Swift String 的规范等价语义替代字面内容相等，不每次转码 UTF-8。
3. 相等才 clean。Undo/Redo、等长替换和全文替换均使用同一逻辑；revision 与撤销计数只协调异步任务，不能决定判脏。
4. 最坏 O(n)，长度不同的快路径 O(1)。不宣称任何编辑 O(log n)，不以密码学摘要相等证明零碰撞。样式更新不触发比较；保存回执改变基线时递增 baselineGeneration 并重新比较当前内容。
5. G0 测量 1/5/20 MB 的文首/文尾等长替换、Undo 回基线、全文同内容替换，含快照获取成本。优先使用系统文本存储与不可变基线，避免增加第二套可变文本模型。

**唯一兜底**：实测 >5 MB 超出主线程预算时，允许该规模使用不可变快照的后台精确比较；结果绑定 DocumentID + revision + baselineGeneration，仅保留最新待请求。尚未确认相等时为 checking，UI 不显示已保存；关闭/删除/保存有界等待当前结果（初值300 ms），超时按可能有修改处理，不读取陈旧 clean。≤5 MB 仍须满足同步判脏；无法满足则 G0 阻断并专项评审，不静默扩大降级范围。

字面比较和Replace All的批量修改以一次文本编辑事务结束为计算边界，避免每个替换片段各扫全文；所有字符变更完成前不得让危险操作读取中间clean状态。

草稿分块与判脏解耦：仅在后台检查点生成时对规范 UTF-8 固定字节块（初值64 KB）计算摘要、复用存储，不在按键热路径维护树。块边界可跨字符，重建完整字节流后严格解码。文首插入可导致后续块全部变化，接受最坏 O(n) 扫描与写入并实测，不引入内容定义分块；块复用遇同摘要时核验字节，校验失败按损坏处理。

### 3.5 核心端口契约

以下是语义接口，不固定具体 Swift 签名：

| 端口 | 输入 | 输出与保证 |
|---|---|---|
| EditorBackend.captureSnapshot | 预期 DocumentID | 不可变文本、revision、编码策略；不暴露可变 NSTextStorage |
| FileAccess.resolve | 位置、授权租约、用途 | 可验证身份或 typed error；用途区分读取与文件操作 |
| FileAccess.readSnapshot | 已授权身份、大小策略 | 同一次读取对应的原始字节、指纹、身份；变化时重试或报告不稳定 |
| MarkdownEngine.parse | 文本快照、取消令牌 | RenderCandidate、源码范围、资源引用、诊断 |
| HTMLSafetyService.serialize | RenderCandidate、安全策略版本、取消令牌 | SafeDocument 或失败；未经序列化器与 raw HTML 清洗器不能构造 SafeDocument |
| SafeWrite.prepare | 快照、目标、预期目标版本 | 本次临时产物与 PrepareToken，不修改最终目标 |
| SafeWrite.commit | PrepareToken、提交资格、最终条件 | CommitReceipt 或明确未提交/结果需复核状态 |
| RecoveryStore.checkpoint | 快照、基线、recoveryEpoch | 仅推进同一代次的新版本，不覆盖新快照 |
| RecoveryStore.discard | documentID、预期代次 | 持久化废弃标记并使旧写入失效 |
| PreviewController.bind | documentID、bindingEpoch、安全内容 | 只向当前绑定应用结果 |

文件错误必须区分 `cancelledBeforeCommit`、`conflict`、`permissionDenied`、`diskFull`、`targetProtected`、`identityUncertain` 和 `commitOutcomeUncertain`。不能将“磁盘已提交但 UI 回调失败”报告成“原文件未改变”。

## 4. 并发、任务调度与提交协调

### 4.1 执行边界

| 执行环境 | 允许执行 | 不允许执行 |
|---|---|---|
| MainActor | AppKit/WebKit API、文本事件、快照捕获、会话状态提交 | 全篇解析、图片解码、阻塞文件 I/O |
| 文件 I/O 执行器 | 协调读写、目录枚举、文件指纹 | 持有 AppKit 对象、等待主线程回调形成互锁 |
| 解析执行器 | cmark 解析、范围转换、块结构生成、安全序列化与 raw HTML 清洗 | 直接访问 NSTextStorage |
| RecoveryStore actor | 检查点次序、代次和磁盘存储协调 | 在 await 后假定状态未改变 |
| 资源执行器 | 受控下载、解码检查、缓存 | 继承 Web 文档任意 URL 请求 |
| WebKit 内容环境 | 排版、查找、受控测量、应用注入的高亮逻辑 | 通用原生调用、任意文件/网络访问、接收未清洗内容 |

Swift `Task` 可能继承 actor 隔离，不能凭其名称认定计算已离开主线程。跨边界只传递不可变 Sendable 值或由明确同步保护的句柄；不以 unchecked Sendable 掩盖可变对象所有权问题。

### 4.2 请求戳与结果接收

所有异步请求按需要携带：

```text
RequestStamp {
  documentID?, revision?, locationEpoch?,
  windowID?, bindingEpoch?, rootEpoch?,
  operationID, policyVersion?
}
```

接收规则按任务类别定义，不能统一成“revision 不同就丢弃”：

- 渲染、高亮、查找：必须匹配当前版本及绑定，否则丢弃。
- 保存：即使已有新编辑，也必须处理成功回执，只更新被保存快照的基线。
- 导出：绑定启动快照，不因用户继续编辑而取消；仍核验最终目标。
- 目录枚举：匹配 WindowID + RootEpoch + 目录身份。
- 资源：匹配会话、位置与授权代次；移窗不撤销仍有效的会话授权。
- 恢复：匹配 RecoveryEpoch，较旧 revision 不得覆盖较新检查点。

### 4.3 有界调度与取消

- 普通预览初始 debounce 150 ms，在 PRD 120–180 ms 范围内。
- 每文档最多保留一个最新待处理渲染请求。
- **渲染管道（解析 + 安全序列化）共用同一个有界执行器，不再设置独立的全应用单清洗槽。** 并发初值：每窗口 1，全应用上限 2，按实测调整。
- 调度按优先级而非 FIFO：**活动文档 > 导出/后台任务**。后台会话不渲染预览（§5.3），因此不参与预览竞争；大文档任务不得阻塞另一窗口活动文档的首屏预览（消除队头阻塞）。
- 高亮与预览分开调度；不让大代码块高亮阻塞输入。
- 对同步 C 解析：分段喂入与 AST 遍历设置取消检查；若最终解析阶段不可中断，必须测量其最坏持续时间。
- **硬门槛**：仅丢弃最终结果不满足大文档计算可取消。若锁定解析器在 5–20 MB 场景无法及时停止工作，阶段 0 必须改用支持合作取消的实现，或评审可终止的隔离工作进程；不能默认降低需求。
- 文件提交临界区一旦开始，取消不意味着回滚。生成阶段可取消；提交后报告成功或复核结果，不能误报取消且仍悄悄改变目标。

### 4.4 应用内操作协调

`FileOperationCoordinator` 为打开、另存为、保存、导出和删除提供规范化位置/实际身份/目录范围的操作预留，防止应用自身产生竞争。

- 用户选路径或确认对话框期间不持有文件锁或长期预留。
- 最终提交前申请短期资格，核验注册表、磁盘身份和用户确认绑定的目标版本。
- 预留期间，冲突的打开请求排队，两个写操作不能提交到同一目标，删除范围内不能新增会话。
- actor 发生 await 时允许重入；资格通过显式 token 和操作状态保持，不能把 actor 当作跨 await 的事务锁。
- 不持有系统文件协调 accessor 等待 UI；先获取应用资格，再在后台执行有限的系统协调区段，最后回主 actor 提交状态。
- 只序列化冲突操作，不把全应用所有输入和 I/O 放进一条巨型队列。

## 5. 应用启动、窗口与命令路由

### 5.1 启动顺序

```text
初始化本地化、服务与系统菜单
 → 读取存储 schema、放弃标记与上次会话清单
 → 扫描可恢复草稿，呈现 Restore / Discard
 → 按系统恢复设置恢复可访问文件、活动文档与根目录
 → 将 Finder/拖放待处理请求通过同一打开入口去重
 → 没有恢复内容或打开请求时，创建一个空白双栏文档
```

崩溃草稿恢复与正常窗口恢复是两条策略：关闭系统窗口恢复不等于主动放弃崩溃草稿。不可访问项单独提示，不阻塞其他有效文件。不同根目录保持独立窗口；系统恢复状态损坏时，精细 UI 可回退，内容与草稿不得直接丢弃。

### 5.2 打开与去重

1. 路由目标：窗口内拖放使用该窗口；Finder、最近打开和应用图标拖放使用最近活动文档窗口。
2. 获取正确授权、解析身份和规范化位置；同批并发请求也通过注册表预留去重。
3. 已存在会话则聚焦其所属窗口，不隐式迁移。
4. 按文件字节大小策略读取，严格解码；读取前后的对象身份不一致则重新确认，避免混合快照。
5. 对新会话创建编辑后端与基线；注册成功才建立监控和渲染任务。
6. 批量打开按请求顺序加入列表、激活第一个有效结果；错误单项反馈。后台读取可并行，但不能让完成先后改变列表语义。
7. 仅空白且从未编辑的初始会话可被复用。

File 类型关联在打包配置中声明受支持扩展名，Finder 请求和 Open Recent 进入同一入口；用户显式选择的普通 UTF-8 文本也按同一安全规则处理。

### 5.3 文档切换与移窗

- 提交或有效结束当前输入法组合；如不能安全完成，保留原会话与焦点，不强制销毁视图。
- 记录当前选区、编辑/预览锚点、分栏比例和最近正文交互栏。
- 初期每会话保留独立编辑后端及 NSTextView/撤销对象；仅活动后端接入窗口视图树。后续如要释放非活动视图，必须先证明不损失撤销与输入状态。
- 窗口宿主替换附着视图，而非把 A 文本覆盖进 B 的同一撤销上下文。
- PreviewController 推进 BindingEpoch、撤销旧资源请求、重绑定新会话。缓存键为 DocumentID + revision + policyVersion，只存位置无关的 SafeDocument 结构。命中后跳过解析/清洗，但必须按当前源位置、LocationEpoch、授权/资源代次重新生成 manifest、linkID 和私有资源句柄，再核验绑定并注入恢复锚点；重建期间先清旧正文，不展示旧地址。未命中则从当前快照解析。
- 移窗更新归属并迁移同一个编辑后端；源窗口有根目录则保留，否则在最后会话移出后关闭。
- 后台会话继续草稿与外部变化检测，不持续渲染预览。
- Open Documents 始终包含未命名和根目录外文档；同名项用父目录/相对路径消歧，顺序按打开时间稳定，不因切换重排。

### 5.4 原生命令

系统 Edit 命令优先遵循 first responder。文档级命令由 CommandRouter 解析明确目标：

| 命令 | 目标 / 行为 |
|---|---|
| Save / Save As / Export | 菜单触发时的活动 DocumentID；任务启动后不跟随焦点变化 |
| Undo / Redo | 编辑器用所属会话 UndoManager；查找输入框使用自身文本撤销，不误改正文 |
| Close Document / Close Window | 分别关闭活动会话/窗口内有序会话集合 |
| Previous / Next Document | 按当前窗口稳定顺序循环 |
| Find | Editor/Split 查源码，Preview 查渲染文本 |
| Find and Replace | Preview 先切 Split，再执行源码替换 |
| **New Document（⌘N）** | 当前文档窗口新建会话；无窗口时建窗。**不受目录选中影响**（区别于 New File in Folder） |
| **New File in Folder… / New Folder…** | 按 §13.1 确定父目录；无关联目录或无写权限时禁用 |
| **Open Recent** | 系统最近文档菜单（§5.5），条目进入 §5.2 统一打开入口；提供 **`Clear Menu`**；记录**不构成访问凭证**，不可访问时要求重选/授权 |
| **Reveal in Finder** | 当前活动文档或被点击的树节点身份；**无文件路径时禁用**（未命名文档） |
| **Open in New Window** | 为目标文件在新窗口打开/聚焦会话；已存在会话则聚焦其所属窗口，不复制缓冲区 |
| **Move to New Window** | 迁移现有会话归属（§5.3），同一编辑后端与撤销栈随之移动，不新建会话 |
| **Open Folder… / Change Folder… / Close Folder** | 按 §10.3 作用于当前窗口根目录；依据是否已有根目录切换前两者的显示 |
| **Open Folder in New Window…** | 显式另开目录窗口；普通更换目录不新增窗口 |
| **Editor / Split / Preview（⌘1/2/3）** | 仅改变活动会话的正文模式，与侧栏显隐独立；不丢光标/选择/撤销/滚动位置 |
| **Show / Hide Sidebar（⌃⌘S）** | 按 §6.2 设置导航意图 `requested`；不关闭文档、不撤销目录授权 |
| **Sync Scrolling** | 切换活动会话的同步开关（§9.1），会话级保存，不改变启动默认值 |
| **Enter Full Screen（⌃⌘F）** | 系统全屏行为；全屏下无法扩宽窗口时侧栏走 §6.2 的原生临时导航面板 |
| **Window > Open Documents** | **按窗口分组**列出全应用会话，标记活动项与未保存状态；同名项用父目录/相对路径消歧 |
| **Marklite Help** | 打开随包交付的本地帮助资源（双语），不请求网络 |
| 树上下文操作 | 使用被点击节点的身份，不依赖稍后改变的选中项 |

菜单校验与执行共享同一能力判断；异步执行前必须重检。没有活动文档时禁用保存、导出和关闭文档。禁用系统自动窗口标签合并，不引入顶部标签栏。

“更多操作”菜单（§6.1 标题栏右侧）与 File 菜单共用同一批 CommandRouter 目标解析与可用性判断，**仅包含** `Open…`、`Open Folder…`/`Change Folder…`、`Save`、`Save As…`、`Export >`、`Reveal in Finder`，不重建第二套判断逻辑。

### 5.5 文档控制器决策（已定稿）

**决策：采用自有 `DocumentSession` + 协调器，不继承 `NSDocument`/`NSDocumentController` 的文档生命周期。**

理由：§3、§5、§11、§12 的权威状态、保存事务、冲突与草稿协议已完整定义同窗口多会话语义；`NSDocument` 的默认生命周期（自动保存、一文档一窗口控制器、内建关闭确认）需要被逐项关闭或绕过，而它附带的收益可用三个独立系统 API 以更小代价取得，不值得为此保留一条可能推翻四个核心章节的架构分支。

`NSDocument` 顺手能力的替代落点：

| 需要的能力 | 替代实现 | 归属 |
|---|---|---|
| 最近打开菜单与 `Clear Menu` | `NSDocumentController.shared.noteNewRecentDocumentURL(_:)` 写入系统最近列表，菜单使用系统 Recent Documents 项；**无需 NSDocument 子类** | AppCoordinator + CommandRouter |
| 窗口恢复 | `NSWindow.isRestorable` + `restorationClass` 实现 `NSWindowRestoration`，恢复标识只存 WindowID/DocumentID 等稳定键 | WindowRegistry |
| 文件协调与外部变化 | 直接使用 `NSFileCoordinator` / `NSFilePresenter`（§10.3 已采用） | FileAccessService |
| 文件类型关联 | 打包配置声明支持扩展名，Finder 请求经 §5.2 统一入口 | 打包配置 |

约束：最近打开记录、窗口恢复与文件关联不得因不使用 `NSDocument` 而缺失；最近打开记录**不构成访问凭证**，仍按 §10.1 重新授权。全应用只有一套可写文档模型，不存在 `NSDocument` 与 `DocumentSession` 并存。

`NSDocumentController` 仅作为“最近打开列表写入”这一项的系统服务使用，不接管打开、保存、关闭与确认流程。

## 6. 布局、导航、外观与辅助功能

### 6.1 窗口组成

NSWindowController 管理统一标题栏；外层 NSSplitViewController 为侧栏与正文，正文内部为编辑和预览分栏。使用系统窗口按钮，不模拟窗口装饰。

- 默认 1280 × 820 pt，最小 800 × 560 pt；标题栏约 48–52 pt，以系统约束为准。
- 正文初始 48%/52%；双栏各至少 320 pt。分栏比例按会话独立保留，重启尽力恢复，无效记录回退 48%/52%（精确恢复不作为发布门槛）。
- 侧栏默认 220 pt，范围 180–320 pt。
- **正文内边距**：编辑区默认约 32 pt、预览区默认约 48 pt；窗口变窄时两者均可收敛至 24 pt。分割线为低对比度 1 px 视觉线，无常驻拖拽柄。
- 使用系统字体、SF Symbols、语义颜色；编辑与预览通过 ThemeSnapshot 同步外观。
- 无独立工具栏行、面板标题栏、底部状态栏或格式工具。
- 统一标题栏内部可使用原生 toolbar/accessory API，但不得增加常驻垂直占用。

**标题栏内容与控件（对应 PRD §5.4）**：

| 位置 | 内容 | 实现约束 |
|---|---|---|
| 左侧 | 系统关闭/最小化/全屏按钮，其后 `Toggle Sidebar` 图标按钮 | 按钮始终可发现；不另设工具栏 |
| 中间 | 当前活动文档文件名 + 未保存时的小型低对比度圆点 | 未命名显示本地化 `Untitled` / `未命名`；**不常驻显示完整路径**，路径经原生标题菜单（⌘ 点击标题）或悬停信息访问；圆点**必须同时具备 AX 描述**，不仅依赖颜色（§6.3）；后台文档的未保存状态显示在 `Open Documents` 列表 |
| 右侧 | 仅两个语义化图标：`View Layout`、`More Actions` | `View Layout` 展开 `Editor`/`Split`/`Preview`，当前模式带勾选；`More Actions` 展开 §5.4 末段的六项。图标视觉尺寸 16–18 pt，**交互区不小于 28 × 28 pt**；两者的辅助标签与菜单项均本地化 |

标题栏只展示活动会话状态；切换文档时随活动 DocumentID 更新，不因后台会话的迟到结果变化（§4.2）。

### 6.2 窄窗口导航的拟定策略

区分导航意图 `requested` 与实际呈现 `hidden/docked/transient`，不把自动收起误当用户主动隐藏。

1. 主动隐藏优先于后续“首次多文档自动展开”；自动展开只在本轮窗口首次从一到多时请求一次。
2. 主动打开/更换文件夹或点击侧栏按钮可重新请求显示。
3. 宽度足够时停靠侧栏；不足时先尝试在当前屏幕可用范围内扩宽窗口。
4. 不能扩宽（含全屏限制）时使用原生临时导航面板，保持原正文模式和最小列宽，不自绘覆盖式侧栏。
5. 用户缩小窗口导致停靠不足时收起停靠，不无故抢焦点弹出面板；侧栏按钮和 Window 菜单仍可访问导航。后续主动请求打开临时面板。
6. 临时面板共享侧栏模型；支持键盘选择、展开折叠、Esc 和关闭后的焦点返回。

此策略须通过阶段 0 在最小窗口、屏幕边界、全屏和 VoiceOver 场景验证；未通过前不视为最终布局实现。

### 6.3 本地化与可访问性

- 使用 String Catalog 稳定键与参数化格式；错误类型在呈现层映射本地化文字，不由领域层拼接句子。
- en/zh-Hans 同步维护；系统应用语言优先，无匹配时英文回退，不添加应用内切换器。
- 帮助、类型名称、提示、确认、工具提示与无障碍状态全部本地化。
- 未保存与冲突同时提供文本/AX 状态，不仅以圆点颜色区分。
- 预览 HTML 设置正确 lang，使用语义标题、列表、表格和链接；不通过把正文整体标为不可访问来实现安全。
- 支持减少透明度/动态效果、正文对比度目标 4.5:1；切主题不改内容或阅读位置。
- Tab/Shift-Tab 的缩进策略与系统全键盘导航保持明确优先级，不能把用户困在编辑器中。

## 7. 编辑器与文本服务

### 7.1 后端约束

`EditorBackend` 封装 NSTextView/TextKit 的创建、选区、快照、编辑命令、几何查询和撤销路由。TextKit 2 优先验证；macOS 14 若存在阻断问题可经同一接口选择 TextKit 1，不混用两套布局 API 或依赖隐式降级。

- 纯文本粘贴，关闭智能引号、破折号和自动内容替换。
- Return 继承缩进，不续写列表；Tab 4 空格，多行统一缩进；Shift-Tab 取消一级。
- 语法高亮通过临时展示属性或受控属性更新实现，不整体重设 attributed string。
- 组合输入期间跳过干扰 marked range 的样式更新，提交后补齐；不强制移动光标。
- 应用修改（缩进、替换）统一经过字符变更入口；替换全部从后往前应用固定匹配范围并作为一个撤销组。
- 文本布局查询只服务可见区域和所需锚点，不每次滚动强制布局整个大文件。

### 7.1.1 源码区视觉规范（对应 PRD E-02）

由 `ThemeSnapshot` 统一提供，编辑与预览共用一份外观快照；切主题不改内容、不改阅读位置（INV-10、AC-20）。

| 项 | 规范 |
|---|---|
| 字体 | 系统等宽字体（`NSFont.monospacedSystemFont`），约 15–16 pt |
| 行高 | 约为字号的 1.6 倍 |
| 不展示 | 行号、代码缩略图、折叠按钮、缩进参考线、整行背景高亮 |
| 高亮色彩 | 低饱和度，正文对比度目标 4.5:1（§6.3） |

**语法高亮 token 清单（最小集，均需夹具覆盖）**：标题标记、强调与加粗、行内代码与围栅代码块、链接与图片语法、列表与引用标记、表格分隔语法。

### 7.1.2 增量高亮调度策略

高亮不复用预览的完整 Markdown 解析，而是用**行导向的轻量词法扫描**，以保证输入延迟与文档规模解耦：

1. **范围**：仅重算「可见区域 ± 一屏」与本次 `editedRange` 所触及的行。滚动时按新进入可见区的行惰性补算，不对全文预先高亮。
2. **跳行传播**：围栅代码块等跳行构造维护一个轻量「行起始状态」表（是否处于围栅内、围栅标记）；编辑后从变更行开始重算，**状态收敛即停止传播**，不从文首重扫。
3. **应用方式**：通过临时展示属性或受控属性更新应用，不整体重设 attributed string，不进入撤销栈。
4. **降级阀值**：单个代码块超过初值 100 KB、或单行超过初值 10 KB 时，该块/行按普通文本显示；>1 MB 文档降低高亮频率（与 §16.1 分级一致）。
5. **与预览分离**：高亮与预览独立调度（§4.3）；高亮计算可在后台完成但**属性应用必须回主 actor**，且每帧预算内有界，不产生超过 50 ms 的主线程阻塞（§16.1）。
6. **组合输入**：组合期间跳过干扰 marked range 的样式更新，提交后补齐（§7.1）。

### 7.2 位置映射

统一 `TextPositionIndex` 保存每行 UTF-8/UTF-16 起点和受影响行的局部映射：

```text
解析器字节/行列范围
 → 明确端点是闭区间还是半开区间
 → 规范化为 UTF-8 半开范围
 → 转换为 UTF-16 半开范围
 → TextKit 片段与视口几何
```

不能按“列数就是字符数”换算中文、Emoji、制表符或组合字符。源码映射与渲染输出使用同一文本快照；不同版本的行索引不可混用。

### 7.3 源码查找

使用共享 `FindState(query, caseSensitive, target, currentMatch)` 管理语义，查找栏为临时原生 UI。NSTextFinder 或自有匹配服务封装在 SourceFindAdapter 后，必须提供总数、上下项与替换单次撤销。

普通匹配固定 Unicode/大小写策略，通过中英文和组合字符夹具验证；不支持正则，不对空查询执行替换。匹配和替换结果绑定 revision，正文改变后重新计算，不沿用旧范围。

## 8. Markdown、安全内容与预览协议

### 8.1 解析输出

优先验证 cmark-gfm 的锁定版本和 Swift 包装。仅启用 PRD 规定的 CommonMark/GFM 能力，不误启用脚注、front matter 或公式插件。

```text
RenderCandidate
  stamp
  blocks[]: blockID, kind, sourceRange, parentID?, structuralHint
  inlineTree[]                     结构化内联节点，非 HTML 字符串
  rawHTMLNodes[]                   仅 HTML_BLOCK / HTML_INLINE，唯一不可信输入面
  resourceReferences[]            原始引用与来源范围，不能自动加载
  diagnostics[]

SafeDocument
  policyVersion / documentID / revision  不持LocationEpoch或绑定能力
  safeBlocks[]                     受控标签、属性、位置无关资源/链接引用标识
  resourceReferences[]            位置无关的安全引用，不含授权、解析后地址或私有令牌
  anchorManifest

BoundPreview（不可作为跨绑定缓存）
  safeDocument / bindingStamp
  resourceManifest / linkManifest  按当前位置与授权重新解析生成
```

任务列表是只读展示，不把 checkbox 变化接回源码。blockID 由应用在序列化时按 AST 结构写入，**天然不经过用户内容**；绝不相信用户提供的 `data-*` 映射或桥接标识，作者 HTML 里的内部命名属性先移除。

解析必须覆盖的 PRD R-01 语法集包含：ATX 与 **Setext** 标题、软换行与**硬换行**、内联/**引用式**/**自动**链接、删除线、任务列表、缩进与围栏代码块、GFM 表格列对齐、嵌套引用与嵌套列表。不支持的语法按标准解析结果显示，不得产生错误或空白预览。

### 8.2 安全序列化与清洗（已修订）

**决策：主选路线为“AST 直出 `SafeDocument`”的原生安全序列化器，运行在 `MarkliteCore` 内，热路径零 IPC、零额外 Web 内容进程。**

两层职责：

1. **`SafeDocumentSerializer`（Swift 纯函数）**：遍历 AST 可信节点，按白名单直接构造 `safeBlocks`。标签与属性白名单定义在 Swift 侧，不存在“先生成再移除”的窗口。文本节点统一转义，代码块内容先转义再交高亮。
2. **`RawHTMLSanitizer`（Swift）**：仅处理 `rawHTMLNodes[]`。输入面小、可完全单测、可合作取消。采用严格有限状态机解析 + 白名单重建（**只重建认识的标签，不修补未识别输入**）；无法确定安全时降级为转义后的纯文本，而不是放行。

安全规则（两层共用同一份 `policyVersion`）：

- 移除事件属性、`script`、`iframe`、`form`、`base`、`object`、`embed`、任意样式与嵌入 SVG 文档；保留 PRD 有限 HTML 所需的安全标签。
- URL 不作为可请求地址直接输出，先转换为资源/链接引用，交原生策略处理（§14）。
- 未经两层输出的内容不能构造 `SafeDocument`；不可信内容永不进入活动预览 DOM。
- HTML 导出（§15.2）复用同一条链路，不存在两套安全语义。

**收益**：

- 热路径去掉一次 IPC 往返与一个 Web 内容进程，直接支撑 §16.1 的分段预算。
- 清洗逻辑进入 §18.1 第 1 层纯领域测试（无 AppKit/WebKit），而不是第 4 层集成测试；恶意内容夹具可全量快速回归。
- 解析与序列化共用同一个可取消的后台执行器，**原“全应用单清洗槽”概念随之取消**，不再存在跨窗口队头阻塞（见 §4.3、§16.2）。
- `SafeDocument` 成为可缓存的不可变值，使 §5.3 的会话切换可跳过解析与清洗。

**降级与对照**：独立受限 WKWebView + DOMPurify 方案降为阶段 0 的**对照实现**，用于交叉校验原生清洗器在恶意夹具上的输出一致性（差异均需定位到具体规则）。若原生清洗器在阶段 0 被证明无法达到等价安全水平，才回退到受限 WebView 清洗，并承担额外 IPC 成本；沿用共享调度器每窗口1/全应用2的在途管道上限，惰性创建最多2个受限清洗上下文，每个上下文一次只服务一个任务，完成/取消后复核并重置绑定，不新增全局单槽或第二套排队器；回退时必须保留“清洗壳 CSP 禁止网络/图片/字体/框架/对象及页面脚本”与“未清洗内容只在惰性/脱离 DOM 中处理”两条约束。

不得取消的边界（两种实现共同）：**进入活动 DOM 前必须完成清洗**。以上是安全边界的实现设计，不是已验证的性能结论；阶段 0 仍需以恶意内容夹具证明两层输出零逃逸。

### 8.3 活动预览壳

每窗口最多一个活动预览 WebView；使用非持久化 WKWebsiteDataStore。用户文档不会被加载为顶层 file URL。

- 固定预览壳和样式随包交付；用户文本作为参数传入，不拼接到 JavaScript 源码。
- 默认 CSP 从 `default-src 'none'` 出发，仅放行应用固定样式与受控图片 scheme；禁用 connect/frame/object/form/base 等能力。
- 不启用页面提供的脚本；应用脚本通过 WKContentWorld 隔离注入，禁止采用 unsafe-eval 兜底。
- 所选系统上 CSP、隔离 world、用户脚本和本地样式的实际组合以安全夹具验证；配置失败则不展示不可信内容。
- 任务只替换正文区域，保持壳和 WebView，不逐次导航重载。
- Web 内容进程终止时重建壳、推进 BindingEpoch，从当前快照重建预览；编辑缓冲区和撤销不受影响。

### 8.4 桥接契约

原生 → Web 仅允许应用构造的固定操作：

| 操作 | 内容 |
|---|---|
| bindDocument | documentID、bindingEpoch、policyVersion |
| render | 安全文档、revision、锚点恢复信息 |
| setTheme | 受控主题枚举和字体参数 |
| scrollToBlock | blockID、块内比例、scrollSequence |
| find / selectMatch / clearFind | 查询与受控匹配序号 |

Web → 原生仅上报：`ready`、`rendered`、`geometryChanged`、`userScroll`、`findResult`、`linkActivated`、受控诊断。

统一 envelope 含 `protocolVersion + documentID + bindingEpoch + revision + messageType`。限制消息字节、数组长度与有限数值；拒绝未知类型、子 frame、错误 WebView 身份、过期绑定和非法 blockID。原生不能单凭消息内的 documentID 选择任意会话。

文件保存、打开面板、目录删除和任意路径读写不属于桥接能力。链接激活只能解析当前 BoundPreview.linkManifest 中的 linkID，并要求对应真实用户交互路径；文档不能通过自造消息自动启动外部程序。

### 8.5 更新与锚点恢复

```text
编辑快照
 → debounce 与后台解析
 → 安全序列化（AST 直出位置无关结构）
 → 按当前位置/授权重建BoundPreview资源与链接manifest
 → 原生校验 RequestStamp
 → Web 校验 documentID / epoch / revision
 → 记录顶部块与块内偏移
 → 替换正文，执行受控代码高亮
 → 测量块几何，恢复锚点
 → 返回 rendered 与几何摘要
```

原生和 Web 双端都校验版本，防止跨 IPC 调用晚到。blockID 通过结构、内容摘要和邻近范围尽力延续；丢失时选择最近存续块，不能只按原行号跳转。

每份几何表标记 renderedRevision。新编辑产生后，在对应映射尚未就绪时暂停跨版本精确同步或使用明确的邻近回退，不能拿旧行范围套用新文本。切换到其他会话时先清空旧正文或展示新会话自己的缓存；“保留最后有效预览”只能在同一会话内成立。

高亮仅打包 Swift、JavaScript、TypeScript、Python、JSON、HTML、CSS、Bash 所需实现；未知或超大代码块按普通文本显示。代码文本先转义，第三方高亮输出仍受展示白名单约束。

## 9. 同步滚动与预览查找

### 9.1 块级同步

`ScrollSyncCoordinator` 持有模式、启用状态、最近用户交互源、同步序列与当前版本几何表。

1. 从用户滚动源顶部位置查到源码块或预览块。
2. 计算块内比例 `t = clamp((offset - blockStart) / blockHeight, 0...1)`；零高或不可映射块选择邻近有效块。
3. 将同一 blockID 和比例映射到另一栏，带 scrollSequence 执行跟随。
4. 程序跟随期间的回调仅作为执行回执，不再反向发起同步；真实新用户手势可以接管。
5. 图片、字体或窗口宽度改变后重新测量，使用最近锚点校正，不重新设为顶部。

**几何测量粒度（新增，避免 O(n) 强制 reflow）**：

- 几何表**不对全文块预先测量**。每次只测量「视口 ± 一屏」范围内的块，其余块标记为未测量。
- 定位时先对已知块序列做**二分查找**确定候选区间，再惰性补测该区间；跳转到远处锚点时只补测路径上必要的少量块。
- 尺寸变化优先使用 `ResizeObserver` 的**增量通知只失效受影响块**，不全表重算；图片 `load` 同理。
- 测量批量执行并与样式写入分离（先读后写），避免布局抖动；单次测量批次预算计入 §16.1 的 Web 侧 30 ms。
- 每份几何表标记 renderedRevision；跳过未测量块时使用邻近已测块作为回退，**不得用旧版本几何冒充当前版本**。

同步关闭时两栏独立；重新启用时以最近正文交互栏对齐。单栏不执行跟随，但保留本会话开关。重启默认启用，不从持久化 UI 状态恢复关闭值。

长表格、代码、图片区采用块内插值或邻近回退；不把逐行精度误作为所有内容的发布门槛。

### 9.2 预览查找

- 从整个渲染文档的展示文本构建 `VisibleTextIndex`，排除隐藏节点、脚本、属性和应用控制区。
- 合并相邻文本节点并保留索引到 DOM Range 的映射，支持跨强调、链接等节点边界的匹配。
- 固定空白折叠、块分隔和大小写规则；按照实际展示文本处理，不搜索 HTML 标签。
- 定位匹配项时滚动，返回当前序号与总数；重新渲染后按文本位置尽力恢复当前匹配。
- 优先使用不改变语义的高亮机制；需要临时包裹节点时必须可完全移除，并在几何变化后更新映射。
- 查询状态在模式切换时保留，但目标切换后重新计数；纯预览替换明确返回 Split 源码查找。
- HTML/PDF 从安全模型重新生成，不读取查找修改过的 DOM。

## 10. 文件身份、权限与目录导航

### 10.1 授权租约

`PermissionBroker` 管理持久 bookmark 与运行时租约：

```text
GrantRecord
  grantID / bookmarkData / accessScope / origin
  resolvedURL / staleState

AccessLease
  grantID / purpose / ownerID / resourceEpoch
```

- `startAccessingSecurityScopedResource` 与 `stopAccessing...` 按真实持有期配对；不假定单个返回值足以代表最终读写权限，操作仍处理权限错误。
- 导航、文档、图片和导出分别持有租约；最后使用者释放才结束访问。
- 单文件授权不能自动升级为父目录枚举授权；图片缺权通过非模态提示引导用户选目录。
- bookmark 失效/陈旧时按系统结果刷新或重新授权，不把 Open Recent 记录当访问凭证。
- entitlement 使用用户选择文件读写及所需 bookmark、网络能力的最小组合，阶段 0 在签名沙盒包中验证；不申请宽泛目录或关闭沙盒来绕过问题。

### 10.2 路径与身份规则

读文档/图片时可解析符号链接，但解析后的真实目标仍须在授权范围。目录树不递归展开链接目录。

文件操作另用入口节点身份：删除符号链接只删除链接本身；创建须验证真实父目录，不允许通过链接父目录逃逸授权。

- 不使用字符串前缀判断目录包含关系，应使用组件边界与可验证实际路径/身份。
- 对存在的目标结合资源标识、卷信息和必要的打开句柄；对新目标结合父目录身份与单个合法名称。
- 不自行转小写或统一 Unicode 来模拟文件系统等价性；以实际文件系统行为和排他操作为准。
- 硬链接别名在可识别时参与去重与保护。安全替换可能打断硬链接关系，应在阶段 0 固定保守策略：不能可靠保留或确认语义时提示另存为，不悄悄声称所有别名同步。
- 无法确认目录删除影响范围或当前源身份时阻止操作，要求重新定位。

### 10.3 目录枚举与监控

- `FolderNavigationModel` 只维护展开/已加载节点：未加载、加载中、已加载、失败可重试。
- 后台分批枚举单层，文件夹优先、自然排序；隐藏点项、应用包和 node_modules，仅展示受支持 Markdown 文件。
- NSOutlineView 按需呈现；不为过滤空目录预扫描子树，不为树节点创建文档监控和 WebView。
- 更换根目录先获得新授权，再原子切换 RootEpoch 和导航模型；取消/失败保持旧根。
- Close Folder 只释放导航租约与导航监控，不关闭文档，不清理其草稿/资源租约。
- 监控事件合并刷新已加载节点；迟到枚举按 RootEpoch 丢弃，失败保留可重试状态。
- 文档变化以 NSFilePresenter/协调访问为基础，辅以可验证的目录/文件事件和激活时复核，覆盖文件替换；事件只是重新核验的信号。

## 11. 保存、另存为与外部冲突

### 11.1 保存时序

```text
用户 Save
 → 确定目标：未命名/Save As 先弹原生保存面板获取路径
 → 捕获 DocumentID、revision、规范文本、编码策略
 → 已知冲突则进入冲突决策
 → 申请目标写入资格，读取并比较磁盘基线
 → 记录操作恢复信息，生成同卷临时产物
 → 复核目标身份、授权、磁盘版本和提交资格
 → 系统安全替换/排他新建提交
 → 返回 CommitReceipt（操作 ID、快照、目标身份、字节指纹）
 → 主 actor 更新文件索引与对应保存基线
 → 比较当前文本，清除或保留脏状态
 → 按版本更新草稿，释放资格并协调自身文件事件
```

**快照捕获时机（已定稿）**：统一为“**目标确定后再捕获快照**”。已有路径的文档，目标即刻确定，捕获发生在命令触发的同一个主 actor 周期；未命名文档与 Save As，捕获发生在原生保存面板返回之后。

理由：原生保存面板是窗口 sheet，展示期间编辑器不接收文本输入，因此“面板后捕获”既不丢内容也符合用户直觉（“保存”存的是按下确认时的内容），并消除了“选路径期间的编辑属于哪个快照”这类边界情形。若存在非 sheet 路径使面板期间仍可产生编辑，以面板返回时的文本为准。**所有入口共用这一契约，不得各自决定。**

- 快照捕获完成后（即进入写入流程后）发生的编辑不改变已捕获快照；保存完成后这些编辑继续是脏状态（AC-05）。
- 同一会话的多个保存请求合并为当前任务加最新待保存请求；提交前使用最新磁盘基线，避免第二次保存误报第一次为外部变化。
- 写失败保留缓冲区、撤销和旧磁盘目标。只清理本次拥有的临时文件，不能清空父目录。
- 文件权限、扩展属性和原子替换行为通过真实文件系统测试确认，禁止用 truncate-and-write 作为失败回退。
- 应用可写单文件不代表可任意创建同目录临时文件；沙盒下应使用系统允许的安全替换路径/临时位置并协调提交，无法安全提交则保留内容并报错。

### 11.1.1 目标覆盖期望

所有保存入口使用 `TargetExpectation`：`absent(parentIdentity, name)`、`sourceBaseline(identity, fingerprint)`、`confirmedExisting(identity, fingerprint)`。首存/另存为面板确认普通已有目标时捕获目标期望并取得明确覆盖确认；若不能证明系统面板确认对应哪个版本，应用补充确认后再提交，不把面板曾显示过确认当作授权任意新版本。

源文件的 diskBaseline 与目标期望分开持有；absent 仅排他创建，竞争出现目标则中止。已有目标在短期资格内最终复核身份和内容版本，变化则释放资格再重新确认或中止。另存为选回源文件走 sourceBaseline，不得借覆盖确认绕过源冲突。导出复用该机制并增加源/全部会话目标保护。

### 11.2 另存为

使用同一写入服务，但目标保护增加“不得覆盖其他会话文件”。成功后在一次主 actor 状态提交中更新 source、LocationEpoch、文件注册表、监控与资源基准。

新内容、撤销栈与 DocumentID 保留；原文件不变，不复制图片或重写源码链接。保存中继续编辑仍可发生，保存成功后的新输入属于新位置会话的未保存内容。失败不改变当前源路径。

### 11.3 外部变化与重载

| 状态 | 行为 |
|---|---|
| 干净、磁盘内容改变 | 捕获当前 revision 后后台读取；提交重载前再次确认仍干净且版本未变 |
| 读取期间新增编辑 | 不自动应用重载结果，转为冲突 |
| 脏、磁盘改变 | 保留两版本，显示非模态冲突；后台先标记，激活时解释 |
| 文件删除 | 保留文本，提示另存为或显式重新创建，普通 Save 不偷偷复活 |
| 成功跟踪到新位置 | 更新身份、路径、监控和资源代次 |
| 只读/无权限 | 继续允许编辑缓冲区，保存时引导另存或授权 |
| 超过打开阈值 | 按 §16 执行，不覆盖内存且不得假装与磁盘同步 |

冲突的 Reload from Disk、Save As、Overwrite 都绑定具体基线。Reload 需确认并安全处理旧草稿；成功重载按下述事务重建对应基线与恢复代次，旧撤销链不允许悄悄回写旧磁盘版本。Overwrite 的确认只授权被确认的磁盘版本，提交前变化则重新确认。

**Reload 后的撤销栈语义（已定稿）**：成功重载**清空该会话的撤销/重做栈**（`UndoManager.removeAllActions()`），并同步推进 `contentRevision` 与 baselineGeneration、重建 `savedBaseline` 与 `diskBaseline`，按 §3.4 精确比较。

理由：Reload 是用户已确认的“放弃本地修改”，保留旧撤销栈会制造一个危险路径：用户 `⌘Z` 可把文本退回到重载前的混合状态，而该状态既不对应磁盘也不对应任何已保存基线（违反 INV-03 的意图）。本版明确不建设历史版本功能：成功 Reload 持久废弃旧草稿代次，不能用旧检查点再次恢复用户已放弃的内容。确认对话必须明确告知“本地修改与撤销历史将不可通过 ⌘Z 恢复”。自动重载（干净文档路径）同样清空，但因无本地修改，不需额外确认。

**Reload 提交事务**：确认绑定 DocumentID/revision/LocationEpoch/磁盘版本 → 后台取得完整稳定磁盘快照（失败保留全部旧状态）→ 申请会话短期资格、安全结束 IME、重检 revision 与确认版本（变化即中止旧确认）→ 阻止字符修改 → 在恢复串行提交队列持久化 `reloadCommitted` 记录（旧代次废弃、新代次、已校验新快照、双基线）→ 同一主 actor 提交替换文本/清 Undo/更新基线及代次 → 恢复编辑。新快照与记录均安全落盘前，旧草稿仍有效；记录是持久提交点，之后崩溃优先恢复新状态，不恢复旧代。若磁盘此后再变，新快照只能作为明确标识的副本，不能自动写源。记录提交前失败解锁并保留旧状态；提交后结果不确定先复核，不误报未重载。自动重载复用同一协议，只省略无本地修改时的确认。

### 11.4 原子性与故障边界

安全替换是提交点，提交前可取消，提交后不能宣称“取消且未写入”。为覆盖“磁盘已保存、进程在状态更新前崩溃”，操作恢复记录含旧基线、新快照指纹、目标身份和操作 ID；重启以磁盘实际结果核验，不盲目重放写入。

系统协调无法锁住所有外部进程。最终复核、狭窄提交区间和提交后复核减少竞态；若结果不确定，保留恢复信息并要求处理，不将会话标为已确认干净。不承诺任意文件系统上的通用原子 compare-and-swap。

## 12. 草稿恢复、会话恢复与关闭

### 12.1 持久化布局

使用系统返回的应用容器 Application Support 路径，不硬编码用户主目录：

```text
Application Support/Marklite/
  state-v1.json                     schema、窗口/文件恢复清单
  grants-v1.json                    bookmark 引用，不写入日志
  recovery/<documentID>/
    current.json                    原子更新的代次/快照指针或 tombstone
    snapshots/<snapshotID>.bin      自包含文本、元数据、校验
    chunks/<chunkDigest>.bin        大文档增量快照的共享块（§12.2）
  operations/<operationID>.json     未完成文件事务的最小恢复记录
```

持久文件包含 schemaVersion；写入权限按用户私有文件处理，不声称应用容器等同额外加密。旧版本/损坏记录进入隔离或只读恢复路径，不自动删除未知格式。

### 12.2 检查点提交协议

1. 停输入约2秒触发，持续输入所有规模统一最长30秒提交检查点，后台会话相同，切换不重置期限。期限按首次变脏/上一成功检查点计，须预留生成及I/O时间；失败持续告警，不只每30秒启动一次任务。
2. revision 与基线/位置/编码元数据均未变可跳过；否则后台比较最近检查点内容，内容未变但元数据变化仍须更新元数据，不能仅按正文摘要跳过。
3. 捕获规范文本、编码、源授权引用、保存/磁盘基线、revision、RecoveryEpoch、baselineGeneration 与 LocationEpoch。
4. 写快照并验证长度/校验，明确文件及指针的同步顺序。>1 MB 在后台使用固定64 KB字节块，按摘要索引并核验相同字节后复用；边界移动时允许重新扫描/写入全部块。它是存储优化，不参与判脏，不承诺任意编辑增量 O(log n)。快照可压缩。
5. 仅在同一代次且版本不倒退时，原子更新 current 指针。
6. 新指针成功后再清理不再引用的旧快照；清理失败不影响新快照可用性。

**存储配额（新增）**：

- 每会话保留快照代次上限 2（current + 上一份，用于 current 损坏时回退）；增量块按引用计数回收。
- `recovery/` 目录总配额初值 2 GB。接近配额时先回收已被保存覆盖的旧代次与孤立未提交产物；仍超额时**优先保障活动与脏会话，并按 §17 显示非模态可靠性警告**；绝不为腾出空间而删除任何会话的唯一有效检查点，也不清除脏状态。
- 配额触顶与磁盘满走同一条 §17 “草稿失败”处理路径，不引入第二套语义。
- 20 MB 仅限制打开/重载，不限制用户编辑后的文本体积；超限编辑仍参与草稿，受总配额及失败告警保护，不静默跳过备份。

同一 documentID 的 current 指针提交、tombstone 和基线更新进入显式串行提交队列；大快照生成可以在队列外进行，但更新指针前必须重新核验代次、版本、baselineGeneration与LocationEpoch；保存/另存为改变元数据时，在队列内以当前基线更新待提交快照元数据，不让先生成后提交的快照带回旧基线。不能仅依赖可重入 actor，就假定 await 期间旧检查点不会越过 Discard 写回指针。

快照文件未被 current 引用时只是未提交产物，不自动以“最新 mtime”恢复。草稿存储失败显示持久但非模态的可靠性警告，不清除脏状态、不用“已自动保存”误导用户。

### 12.3 放弃与清理协议

- 显式 Don’t Save/Discard 确认绑定 revision。先安全结束 IME 并复核内容，取得会话 closing 资格后禁止一切字符修改入口，再使旧任务失效并持久化废弃标记；确认成功后紧接移除会话。内容变化不得沿用旧确认，提交前失败恢复编辑与旧有效草稿。
- current 中的 tombstone 优先于旧快照，不因扫描找到正文就恢复。
- 若无法写入放弃标记且无法可靠移除可恢复记录，保留会话、解释错误并中止关闭；不能同时满足“保留脏会话”和“已经清理其草稿”。
- 内存移除会话紧接成功确认，不跨新的用户交互；崩溃发生在两者之间时，以用户已经确认的持久废弃记录为准。
- 保存成功只清理对应或更旧且已被保存覆盖的检查点；更新较新草稿的基线，不删除其内容。
- 干净会话关闭也需处理残留旧草稿；异步清理前取得相同 closing 资格并再次判脏，期间不接收字符变更，失败解锁。不能在正常关闭后恢复陈旧编辑。

### 12.4 恢复算法

- 验证 schema、校验和代次，先消费放弃及 reloadCommitted 操作记录，再选择有效current；一项损坏不影响其他项。reloadCommitted引用的新快照保持可达，直到新代current和状态清单提交完成才清理记录，不可作为孤立文件回收。
- 原源可访问且磁盘基线匹配：以原会话源恢复编辑内容，保持未保存状态。
- 源改变、删除或无权限：以恢复副本打开，保留来源说明，要求另存为；不自动覆盖。
- 显式放弃的内容不参与恢复；未命名从未编辑空文档不恢复。
- 正常退出的会话清单独立于草稿；按系统允许恢复设置恢复文件、活动项和根目录，布局精度尽力。
- 退出开始时捕获待恢复窗口/已保存文件清单，随后将保存及另存为后的有效位置合入；不能逐文档关闭后再从空注册表生成退出清单。正常关闭单个文档则更新运行中清单，避免下次误恢复已关闭文档。退出中途取消时丢弃候选退出清单，持久化当前仍存活的会话集合。
- 同一文件的恢复与 Finder 打开统一经过注册表，不产生双重可编辑源。
- 恢复同步滚动默认为开启；主动隐藏侧栏的本轮偏好不跨启动强制继承。

### 12.5 关闭与应用退出

`CloseCoordinator` 使用有序文档集合，逐项处理，不预先批量删除草稿：

```text
检查当前会话
 → 无修改：清理安全残留并关闭
 → 有修改：Save / Don’t Save / Cancel
      Save → 保存成功且仍干净才关闭
             保存失败/取消路径选择 → 中止
             保存中有新编辑 → 再次处理该会话，不能直接关闭
      Don’t Save → 执行持久放弃协议 → 关闭
      Cancel → 中止剩余流程
 → 激活邻近会话 / 保留目录空窗口 / 关闭无根空窗口
```

退出应用使用系统延迟终止机制等待异步确认；取消或失败回复“不退出”。红色关闭按钮和 Close Window 都走同一协调器；已完成关闭的前序文档不回滚，不重复显示系统与应用两套确认框。

窗口关闭期间暂停向该窗口新增/移入会话；应用退出进入 `terminationPending`，所有新建、打开、恢复和移窗入口统一经过准入判断。已在途读取可完成但不得注册新会话，请求按原顺序暂存；取消关闭/退出时重新校验目标后恢复处理。成功退出不将暂存请求伪记为已打开。最后在主 actor 核验无未处理存活会话、无可绕过准入的在途提交，并协调导出任务后才回复系统允许退出。保存期间仍可输入，仅放弃/clean清理的短提交区禁止受影响会话修改；不持有全应用I/O锁等待UI。

## 13. 新建文件、文件夹与移到废纸篓

### 13.1 创建

- 由树选中目录、文件父目录或根目录确定目标，命名对话框显示实际父目录。
- 仅接受单个合法名称，拒绝空、`.`、`..`、分隔符及不支持扩展；无扩展补 `.md`。
- 中文和 Emoji 名称按原样处理；不自行改写用户名称以绕过碰撞。
- 隐藏名称提前提示；隐藏 Markdown 仍打开会话，隐藏文件夹选中可见父目录。
- 确认后重新核验真实父目录与授权，使用排他创建，碰撞只报错不覆盖。
- 成功创建空文件后刷新父目录并打开干净会话；打开失败说明“磁盘已创建”，保留重试入口。
- 取消无磁盘变更，失败保留用户输入，无权限时给出明确操作途径。

### 13.2 删除影响分析

`TrashPlan` 记录目标入口身份、父目录身份、全应用受影响会话、浏览根目录及确认时版本。

1. 不允许删除发起窗口的根目录，不递归遍历文件夹去“仅删除 Markdown”。
2. 根据真实目录归属和文件身份检查全应用会话，包含其他窗口；无源的未命名文档不因同窗被纳入。
3. 任一受影响会话 dirty、IME 未完成或身份不确定，立即中止并列出路径与定位入口。按 §3.4 精确判脏；仅 >5 MB 经批准降级时有界等待当前 revision + baselineGeneration 的结果，超时按可能修改处理，绝不使用陈旧 clean。
4. 全部干净才显示最终确认，明确包含隐藏和非 Markdown 子项；提醒保存到原位置的内容也会被删除。
5. 不在用户处理脏文档后自动继续，必须由用户手动重新发起。

### 13.3 删除提交

确认后申请目录范围预留，再次核验身份、权限、会话版本和状态。存在新增编辑/新会话/目标变化则中止并重新处理。

进入系统废纸篓调用前，受影响编辑后端短暂进入明确的操作中只读状态，防止预检后接收新编辑；先完成组合输入，若因此变脏则不提交。不禁用无关文档，不静默丢弃已经接收的输入。临界区不能变成长时间无反馈阻塞，慢操作显示进度并保留缓冲区。

- 只调用系统废纸篓 API；无支持或失败保留会话，不永久删除兜底。
- 成功回执后，仅关闭仍指向已删除目标的干净会话；更新相关根目录可用性和树。
- 已另存到范围外的会话不受影响；符号链接节点操作不跟随删除目标。
- 任何与预期不符的回执需要重新核验，内容优先保留，不凭收到一个文件事件就清理会话。
- 不承诺文本 Undo 撤销磁盘删除，恢复磁盘文件使用 Finder 废纸篓。

## 14. 本地图片、远程图片与链接

### 14.1 受控资源协议

预览只看到类似 `marklite-resource://<opaque-session-token>/<resourceID>` 的不透明地址，不包含真实路径。它不是通用文件服务器。

`ResourceManifest` 将 resourceID 绑定到会话、LocationEpoch、来源引用、授权租约、内容类型和资源版本；WKURLSchemeHandler 只服务当前绑定 manifest 的合法请求。

- scheme 请求本身不能创建新授权，也不能把路径或 URL 参数当指令。
- 取消任务或重绑定时，登记终止状态，后台晚到结果不得向已停止的 WKURLSchemeTask 回调。
- 资源令牌只是索引，不是唯一安全边界；原生同时校验请求所属 WebView、当前绑定与权限。
- 未命名无路径文档提示先保存；已有路径的脏文档继续以当前源位置解析图片。

### 14.2 本地读取

相对路径按源目录解析，解码 URL 后规范化并验证真实目标、授权和文件类型；尽可能用稳定句柄读取并复核，避免检查和读取之间链接被替换。

PNG/JPEG/GIF/WebP 按受控图片处理；SVG 作为受限图片，移除/阻断外部引用与执行内容，不允许作为顶层文档、object 或嵌入可执行 DOM。图像验证/解码开销在后台，失败以占位和 alt 文本呈现。

### 14.3 远程读取

- 默认 blocked，应用原生提示条上的 Load Images 才将当前会话授权置为允许。
- URLSession 使用非持久化、无环境 Cookie/凭据的配置；WebView 不直接连接远程图片站点。
- 允许 HTTP/HTTPS 的产品语义不等于关闭系统传输安全：阶段 0 明确 ATS 的最小必要策略，验证 HTTP 受控加载；不得全局允许任意 Web 内容联网或绕过证书错误。
- 每次重定向检查协议和资源策略，限制跳数、响应字节、时间和解码像素。
- 缓存绑定会话授权；换到另一个文档不能因缓存存在而绕过授权。移窗保留会话授权，重启不恢复远程授权。
- `srcset`、CSS URL、SVG 子资源、data URL 都经过同一政策，不留下“主图片受控、附属资源直连”的旁路。

建议初始工程保护值：单资源响应 20 MB、解码 40 百万像素、30 秒总超时、最多 5 次重定向；这些是待原型校准的保护参数，不是 PRD 新增格式限制。达到限制显示具体原因并保持编辑可用，修改数值必须保留有界约束。

### 14.3.1 统一资源预算（本地／远程／data URL／导出）

使用一个 ResourceBudget 记账器与有限并发队列，不另建资源服务框架。以下均为 G0 必须实测校准的初值；G3 按校准后的值验收，不作为已证明的内存上限：

| 成本 | 初值及处理 |
|---|---|
| 单图 | 输入字节≤20 MB、静态解码≤4000万像素；读取/下载流式计数，先检查元数据再解码，本地与data URL同样限制 |
| 动画 | 帧数≤200、所有帧累计≤8000万像素，并计入解码预算；超限占位，不静默无界解码 |
| 并发与排队 | 全应用最多4个读取/下载、2个解码；每个预览/导出任务累计最多256个唯一资源（含待处理与已载入），超出部分标缺失；取消释放槽与记账 |
| 累计驻留 | 每个预览/导出任务估算≤256 MB，全应用图片相关估算≤512 MB；缓存128 MB属于其中，不另加；包含输入字节、解码像素、在途缓冲、导出冻结字节与Base64副本，实际共享只记一次，复制必须追加预留 |
| SVG | 输入仍受字节限制，解析嵌套深度初值64、节点数初值100,000，输出尺寸计入像素预算；外部引用禁止，不因禁脚本而允许无界解析/栅格化 |

资源准入前预留最坏可知成本，尺寸未知时有界读取头部；无法安全估算则占位。不得先完全读取/解码后才检查。任务超预算不删除其他任务正在引用的数据，也不清用户撤销或草稿；预览局部占位，导出进入缺失资源选择并允许取消。

WebKit 自身副本/解码不能由原生记账精确限制，因此同时限制送入DOM的累计像素及资源数，在G0/G4测原生+Web内容进程峰值，校准放大系数和准入预算；128 MB缓存不等于全应用内存上限。导出排队时只持有文本/引用，取得任务资格后才冻结资源字节，避免等待队列无界占用图片。

### 14.4 链接路由

- 文内锚点通过 anchorManifest 在当前预览跳转。
- http/https/mailto 仅经用户激活后交给系统处理。
- 相对 Markdown 链接走统一打开/去重入口，缺权时请求授权，不直接让 WebView 导航到文件。
- 其他本地文件仅经显式用户点击调用系统打开。
- 拒绝 javascript、未知执行型协议和文档自动导航；所有 target/new-window 请求同样校验。

## 15. HTML 与 PDF 导出

### 15.1 独立任务模型

```text
ExportJob
  operationID / documentID / revision
  textSnapshot / sourceLocationSnapshot
  resourcePolicySnapshot / retainedLeases
  target / targetExpectation / format
  state: preparing → rendering → awaitingMissingResourceChoice
                   → readyToCommit → committing → completed
                                      ↘ failed / cancelledBeforeCommit
```

导出拥有启动时文本快照、源位置、资源策略及租约，启动时冻结已授权且成功加载远程资源的版本。排队只存引用，取得任务资格后按预算固定该版本字节；已淘汰则标缺失，不改用后来版本。若排队期间强引用资源，仍必须记入驻留预算；不能用引用绕过持有成本。本地资源在准备阶段读取成固定字节。缺失资源提示取消或占位，不为导出新开未授权网络请求。

超过 500 ms 显示轻量进度；生成阶段可取消，提交阶段按 §11.4 的真实结果报告。文档关闭不让导出改用别的文档；任务可继续持有快照，应用退出时协调完成或取消未提交任务。

### 15.2 HTML 生成

从文本快照重新解析并使用同一安全模型，序列化为完整 UTF-8 HTML，内嵌预览/代码样式与允许的图片数据。

输出检查：

- 无 script、桥接、查找高亮、私有资源 URL、容器临时路径或应用诊断数据。
- 不自动删除用户正文中原有的显式路径；安全协议规则仍适用，导出不是全文脱敏工具。
- 任务列表仅显示，不提供修改源文档逻辑。
- 输出文件可离线打开，无 CDN、远程字体或运行时脚本需求。

### 15.3 PDF 生成

`PDFRenderer` 优先验证 WebKit 打印路径与 NSPrintOperation：独立导出 WebView、打印 CSS、A4、白底深色和合理页边距。初始页边距建议 15 mm，经样例验证后固定。

- 渲染完成条件是受控资源 settled、字体就绪、布局稳定，不仅是 didFinish 导航回调。
- CSS 处理长代码换行、长 URL、宽表格和超高块分页；避免标题孤立在页尾，但不对跨页块作不现实的整块承诺。
- 验证文字可选、链接、页数与分页边界，不采用可见视口截图。
- `WKWebView.createPDF` 仅作为原型对照，不因 API 名称就假定符合分页规范。
- 不能达标时提交专项 ADR 选择本地输出后端，不直接加远程转换服务。

### 15.4 目标保护与提交

保存面板约束扩展名。**默认文件名为源 Markdown 文件的基名加对应扩展名（`README.md` → `README.html` / `README.pdf`）；未命名文档使用本地化的 `Untitled` / `未命名` 基名。默认目录为最近使用的导出目录，首次为源文件所在目录（未命名文档为系统默认文档目录）。** 目标期望区分“不存在”与“已确认的具体版本”：

1. 按规范化路径、实际身份、符号/硬链接等可识别别名，排除源文件和所有已打开文档。
2. 其他现有目标需确认覆盖并记录版本；确认后变化则中止或重新确认。
3. 在私有临时产物中完整生成，然后在目标允许的位置准备安全提交。
4. 最终提交预留期间再次检查注册表和目标；导出期间新打开的目标也必须受保护。
5. 失败/取消只清理本次临时产物，原目标不删除、不截断。

同一保护策略供 HTML/PDF 共用，不在两个导出器中分别实现。

## 16. 性能、资源预算与降级

### 16.1 PRD 指标

基线为 M1、8 GB、SSD、macOS 14+；MB = 1,000,000 字节。

| 场景 | 门槛 / 策略 |
|---|---|
| ≤100 KB 预览 | 停输入到稳定预览 P95 ≤300 ms，包含合并等待、解析、安全序列化、IPC 和布局；网络耗时除外。**测量条件：单窗口活动文档、无并发大文档任务**（否则指标不可测；并发下的优先级见 §4.3） |
| ≤1 MB 打开 | 确认打开到可编辑 P95 ≤1 秒；预览不能挡住编辑器就绪 |
| 常规输入 | 不产生连续超过 50 ms 的主线程阻塞（含字面精确判脏与高亮属性应用） |
| 20 个约100 KB 会话 / 五窗口 | 30 分钟操作，内容与状态正确，无持续内存增长 |
| 10,000 项目录 | 首屏有反馈、按需枚举与呈现，不扫描未展开子目录 |
| ≤1 MB | 完整体验目标 |
| >1 MB 且≤5 MB | 可降低高亮与预览频率 |
| >5 MB 且≤20 MB | 打开前提示，默认编辑模式，预览由用户主动启用（状态机见下） |
| >20 MB | 拒绝打开/重载，不因此丢弃已有缓冲区 |

**≤100 KB 预览的分段预算（旧初值，G0校准后才作为 CI 回归阈值）**：

| 阶段 | 预算 | 归属 |
|---|---|---|
| 合并等待（debounce） | 150 ms | §4.3 |
| 主 actor 快照捕获 | ≤10 ms | §7.1 EditorBackend |
| Markdown 解析 | ≤60 ms | MarkdownEngine |
| 安全序列化 + raw HTML 清洗 | ≤40 ms | §8.2 |
| 桥接 IPC（往返） | ≤20 ms | §8.4 |
| Web 侧注入、布局与锚点恢复 | ≤30 ms | §8.5、§9.1 |
| 合计 | 310 ms：仅为旧分段初值之和，不是300 ms目标的余量，也不是可验收预算 | — |

G0 必须以实测重新分配各段预算，使计划总上限≤300 ms；上表未校准前不得作为CI通过阈值。各段按 §16.3 度量用于定位，总体另测端到端P95≤300 ms，不能求和分段P95替代整体分布。若阶段 0 回退到受限 WebView 清洗，需为额外 IPC 往返重新分配预算并重测，不得沿用本表。

**>5 MB 文档的预览启用状态机（对应 PRD §11.1）**：

`previewAvailability: autoEnabled | suppressedBySize | userEnabled`

- 打开前以原生提示告知规模与影响；确认后会话进入 `suppressedBySize`，默认 Editor 模式。
- 此状态下不调度解析与序列化，不创建预览 WebView；预览区展示可操作的启用入口（本地化文案 + AX 描述）。
- 用户通过该入口或 `⌘2`/`⌘3` 主动切到含预览的模式即进入 `userEnabled`，**该选择按会话保留**，不反复弹提示。
- 编辑中粘贴使内容超过阈值：只降级预览（可转 `suppressedBySize`），**不丢内容、不禁用 Save/Save As**（AC-44）。
- 重载后规模回到 ≤5 MB 时恢复 `autoEnabled`。

外部重载超过 5 MB 先提示，超过 20 MB 保留旧缓冲区并标记磁盘已变；有本地修改时先进入冲突。编辑中粘贴超过阈值只降级预览，不丢内容、不禁用保存和另存为。

### 16.2 有界资源初值

- 活动预览每窗口最多一个；后台文档不保留完整 WebView。
- **渲染管道并发：每窗口 1、全应用上限 2（见 §4.3）。不存在独立的全应用单清洗槽。** 若阶段 0 回退到受限 WebView 清洗，则共享池惰性创建最多2个清洗上下文，单上下文串行且每窗口仍最多1个在途任务；不为每个窗口常驻创建上下文，也不另设全局单槽。
- PDF 导出渲染槽一个，等待队列初值最多4个任务，满则提示稍后重试；排队及生成可取消，不在排队期复制图片。
- **位置无关 SafeDocument 缓存**：每窗口LRU初值3份，键为DocumentID/revision/policyVersion；无解析后路径、授权租约、私有URL或旧绑定令牌。每次命中按 §5.3 重建当前资源/链接manifest及绑定后才注入，位置变化不要求重新解析Markdown。
- 图片缓存初值128 MB计入 §14.3.1 全应用预算，联合限制本地/远程/动画/导出冻结和在途成本；WebKit实际峰值另行实测，不能把缓存额度当总内存。
- **草稿存储预算（新增）：每会话最多保留 2 份快照（current + 上一份）；草稿目录总配额初值 2 GB。** 达到配额按 §12.2 的降级与告知策略处理，不静默停止备份。
- 编辑器及撤销按会话保留，不为满足缓存限额清除用户撤销；若内存压力需要优化，必须重新验证后端分离方案。
- 临时导出/解析资源按 OperationID 释放；关闭会话取消任务、移除 observer、解除桥接并释放最后租约。

数值是待测工程起点，不是实测结论。首版不承诺固定总内存；进程与 Web 内容进程须一起测量，建立基线后固定回归阈值。

### 16.3 可观测性

使用 OSLog/signpost 记录操作 ID、耗时、字节规模区间、队列长度、过期结果数、缓存成本与失败类型，不记录正文、原始 HTML、图片 URL 或未脱敏路径。

**诊断导出（对应 PRD §9.1）**：仅由用户主动触发（Help 菜单入口），不自动上传、不后台发送。导出内容经**路径脉敏处理**：用户目录、容器路径与文件名替换为稳定占位符（如 `<doc-1>`），仅保留扩展名与规模区间；绝不包含正文、图片 URL、草稿内容与 bookmark 数据。导出前向用户展示将包含的数据类别，并写入用户选定位置（遵守 §15.4 目标保护）。

分别测量快照捕获、解析、清洗、桥接与布局，避免只测解析时间就声称满足 300 ms。主线程全篇快照复制如果超预算，需要优化存储/分块快照，不把瓶颈转嫁到输入回调。

## 17. 错误处理与生命周期故障

| 故障 | 处理 | 必须保留 |
|---|---|---|
| 解析/清洗失败 | 保留当前会话最后有效预览并提示；首次失败显示安全错误状态 | 文本、选择、撤销 |
| WebKit 内容进程退出 | 推进绑定、重建受控壳并重渲染 | 文档与阅读锚点 |
| 文件保存失败 | 原生错误，允许重试或另存 | 内存和旧目标 |
| 结果不确定 | 复核磁盘与操作记录，禁止误标干净 | 快照、操作证据 |
| 草稿失败/磁盘满/配额触顶 | 非模态可靠性警告，关闭时按明确安全协议处理；不以清理有效检查点腾空间 | 上个有效检查点与当前编辑 |
| 权限失效 | 保留模型，请求重新授权 | 文档、草稿、可访问项 |
| 目录加载失败 | 树节点错误与重试，不清空打开列表 | 所有会话 |
| 网络/图片失败 | 局部占位与 alt，不阻塞排版 | 正文与未保存状态 |
| 原生桥接非法消息 | 拒绝并记录脱敏计数，不执行操作 | 原生权限边界 |

仅解析/清洗结果可以按策略降级；文件内容、保存基线、草稿恢复与安全边界不能通过“尽力而为”跳过。

## 18. 测试与验收追溯

### 18.1 测试分层

1. **纯领域测试**：状态迁移、文件目标保护、版本接收、关闭列表、字面精确判脏、权限引用与资源策略，**以及安全序列化与 raw HTML 清洗的全量恶意夹具**（§8.2 使其可在无 AppKit/WebKit 环境下运行）。
2. **确定性并发测试**：注入 Clock、I/O 完成顺序、取消和假文件系统，主动打乱保存、切换、重载、关闭与草稿回调。
3. **真实文件集成**：临时目录、符号链接、可识别硬链接、大小写等价文件系统、Git 式替换、只读与磁盘失败。
4. **WebKit 集成**：网络拦截、桥接、SVG、查找、滚动、进程重建、HTML/PDF，以及与阶段 0 清洗对照实现的输出一致性校验。
5. **UI 与人工专项**：XCUITest 覆盖菜单和流程；真实输入法、VoiceOver、触控板惯性与系统语言必须人工/辅助测试，不能只靠模拟按键。
6. **性能/故障恢复**：Release 构建、最低系统与当前支持系统；在每个持久化提交边界注入进程终止并重启验证。

### 18.2 必须存在的竞态夹具

- Save(r10) 进行中输入 r11：成功后 r11 仍脏。
- Undo 回保存内容但 revision 不同：字面内容相等 → 同步clean；批准的大文件降级按当前版本有界等待。
- 判脏：文首/尾等长替换、组合字符及规范等价但码元不同文本、全文替换与全文比较oracle一致；保存更换基线时旧异步结果拒绝。
- 关闭墓碑/clean清理期间输入、退出期间Finder打开/新建/移窗、取消退出恢复暂存请求。
- 首存目标竞争创建、另存为覆盖确认后替换、选回源文件不能绕过冲突。
- Reload读取期间编辑、旧checkpoint晚到、reloadCommitted前后强杀及磁盘再次变化。
- 内容未改而另存到不同图片目录、权限变化、移窗后缓存命中重建manifest。
- 短文档大量图片、本地巨图/高帧GIF、预览与导出同时持有资源及预算耗尽。
- 删除预检时受影响文档刚被撤销回基线：应视为干净并继续流程，**不得因异步判脏未回而中止**。
- 重载开始时干净、读取期间编辑：不覆盖新增文本。
- A 渲染晚于窗口切到 B：双端拒绝 A 更新。
- 更换根目录后旧枚举返回：不污染新树、不撤销旧文档所需租约。
- Discard 后旧 checkpoint 返回：墓碑有效，不恢复已放弃内容。
- 保存成功更新基线时较新草稿存在：不删除新内容。
- 窗口关闭到第二个文档取消：第一个保持关闭，剩余完整。
- 删除确认期间另一窗口编辑或新增目标会话：中止。
- 导出确认后目标被替换或打开：不覆盖。
- 系统保存已提交、进程在 UI 回执前终止：恢复核验，不自动重复写入。
- WebView/资源 scheme 任务取消后回调到达：不串会话、不调用已停止 task。

## 19. 构建、依赖、CI 与分发

### 19.1 构建与资源

- Xcode 工程管理 App、集成/UI 测试与签名；本地 SPM package 管理纯核心及其测试。
- 锁定稳定工具链与 SPM/JS 依赖；具体版本在阶段 0 核验后记录，不使用未经核验的“最新版”描述。
- WebAssets 使用 TypeScript + 最小打包工具，拟采用 npm 锁文件；Node 仅为开发/构建依赖，不随应用运行。
- 固定构建产物清单和资源哈希，App 包含所有样式、清洗器、高亮和帮助资源，不在启动时下载。
- 不硬编码尚不存在的测试脚本；建立工程后在 Scripts 与 CI 中定义并共享同一入口。

### 19.2 CI 门禁

1. Swift 编译、静态检查、严格并发诊断和核心测试。
2. Web 脚本类型/单元测试、资源构建确定性与许可证检查。
3. 双语键、占位符、帮助资源与应用语言配置检查。
4. 文件操作/恢复/WebKit 集成测试。
5. 定期在受控 macOS 机器进行 Release 性能和手工输入法/VoiceOver 回归。
6. 发布前签名、entitlement、文件关联、沙盒、离线使用与导出验证。

CI 云主机不能替代 M1/8 GB 指标基线；macOS 14 最低系统测试需真实可用环境，不假定托管 runner 永远提供该版本。

### 19.3 分发与更新

发行包必须签名，直接分发完成公证；渠道、自动更新机制与 Intel 支持仍由产品确认。未经明确需求不加入更新框架或额外联网入口。若提供 Intel 构建，独立验证解析 C 依赖、文本布局、性能和签名，不能仅靠通用编译成功认定支持。
