## 2. D09：安全清洗后端

### 2.1 决策

`MarkdownEngine` 输出**结构化 AST**（块语义、内联树、源码范围、资源引用、诊断），**不输出 HTML 候选字符串**。安全内容由两层原生实现构造：

1. `SafeDocumentSerializer`：遍历 AST 可信节点，按 Swift 侧白名单直出 `SafeDocument`。
2. `RawHTMLSanitizer`：仅处理 `HTML_BLOCK` / `HTML_INLINE` 两类节点，FSM 解析 + 白名单重建，不确定安全时降级为转义文本。

### 2.2 理由

ADR-001 §8.2 让 `MarkdownEngine` 返回「HTML 候选」，再由 §8.3 整体清洗。该链路存在一个可避免的降级：**cmark 给出的是 AST（结构可信），先渲染为 HTML 字符串等于主动丢弃结构信息、把可信输入变为不可信文本，然后付出额外代价洗回来**。

PRD R-01 只要求「经安全清洗的**有限** HTML」，真正不可信的仅两类 AST 节点。因此不可信输入面远小于「整份渲染后的 HTML」，无须为它引入一个独立 Web 内容进程。

采用 AST 直出后：

- 热路径去掉一次 IPC 往返与一个 Web 内容进程，直接支撑 TAD §16.1 的分段预算（序列化 ≤40 ms）。
- blockID 由应用按 AST 结构写入，**天然不经过用户内容**，无需依赖清洗器保留内部属性，也消除 DOM clobbering 对映射标识的攻击面（回应 ADR-001 §8.3 第 5 条）。
- 清洗逻辑成为 `MarkliteCore` 内的纯函数，进入 TAD §18.1 第 1 层纯领域测试（无 AppKit/WebKit），恶意内容夹具可全量快速回归，而非第 4 层集成测试。
- 取消了「全应用单清洗槽」的必要性（见 D12）。

### 2.3 保留的 ADR-001 约束（不因换后端而放松）

- 不通过正则替换实现 HTML 安全，不把 CSP 当作清洗替代品。
- **内容在插入活动 DOM 前完成清洗与 URL 重写**；URL 不作为可请求地址直接输出。
- 移除脚本、事件属性、表单、iframe、base、外部样式与用户提供的任意样式。
- 防止 ID/name 冲突、DOM clobbering 与文档内容伪造应用控件。
- CSP、导航拦截与资源代理仍形成多层防线；默认不允许直接 http/https 图片加载。

### 2.4 阶段 0 证据与回退

| 必须取得的证据 | 失败处理 |
|---|---|
| 恶意内容夹具零逃逸，且与受限 WebKit + DOMPurify **对照实现输出一致**（差异均定位到具体规则） | 若原生清洗器无法达到等价安全水平，回退受限 WebView 清洗 |
| 可合作取消；符合 TAD §16.1 分段预算 | 回退时须为额外 IPC 往返重新分配预算并重测，不沿用现表 |

回退时必须保留：清洗壳 CSP 禁止网络/图片/字体/框架/对象及页面脚本；未清洗内容只在惰性/脱离 DOM 中处理。

**不得取消的边界（两种实现共同）：进入活动 DOM 前必须完成清洗。**

## 3. D10：文档控制器

### 3.1 决策

采用自有 `DocumentSession` + 应用级协调器，**不继承 `NSDocument`/`NSDocumentController` 的文档生命周期**。

### 3.2 理由

ADR-001 §6.2 已确定「独立 DocumentSession + 应用级注册表」为架构确定项，仅把「是否用 NSDocument 作后端适配」留给阶段 0。但 TAD §3、§5、§11、§12 已完整定义同窗口多会话的权威状态、保存事务、冲突与草稿协议，而 `NSDocument` 的默认生命周期（自动保存、一文档一窗口控制器、内建关闭确认）需要被逐项关闭或绕过。

保留该分支的风险是**不对称的**：若阶段 0 反转，返工面覆盖四个核心章节；而它附带的收益可用三个独立系统 API 以更小代价取得。因此现在定稿。

### 3.3 NSDocument 顺手能力的替代落点

| 需要的能力 | 替代实现 |
|---|---|
| 最近打开菜单与 `Clear Menu` | `NSDocumentController.shared.noteNewRecentDocumentURL(_:)` 写入系统最近列表；**无需 NSDocument 子类** |
| 窗口恢复 | `NSWindow.isRestorable` + `restorationClass` 实现 `NSWindowRestoration` |
| 文件协调与外部变化 | 直接使用 `NSFileCoordinator` / `NSFilePresenter` |
| 文件类型关联 | 打包配置声明支持扩展名，Finder 请求经统一打开入口 |

约束：最近打开、窗口恢复与文件关联**不得因此缺失**；最近打开记录不构成访问凭证。全应用只有一套可写文档模型。`NSDocumentController` 仅用于「写入最近打开列表」这一项系统服务。

## 4. D11：判脏机制

### 4.1 决策

按固定块（初值 64 KB）维护摘要树，在 `NSTextStorage.didProcessEditing` 中按 `editedRange` 只重算受影响叶块及祖先路径；判脏 = 当前根摘要 ≠ 基线根摘要，**O(1) 同步精确**。`dirtyStatus` 只有 `clean / dirty` 两态。

### 4.2 理由

PRD E-04 要求「未保存状态由内容相对保存基线的差异决定」且「撤销回到已保存内容时应恢复已保存状态」（AC-06）。这排除了 `contentRevision == savedRevision` 与 UndoManager change count 两种廉价实现。

若改用异步全文比较，则会引入 `checking` 中间态，并迫使每个危险操作（关闭、删除、保存、退出确认）在「读到陈旧 clean」与「保守误判为脏」之间二选一。实测后果之一：用户敲一个字后立即右键删除另一目录，会因判脏未回而被中止并要求「先处理修改」，而该文档可能本就干净。

摘要树消除了这一整类问题，并顺带为草稿协议提供两项依据：内容未变则跳过检查点；大文档分块增量快照复用同一分块边界。

### 4.3 阶段 0 证据与回退

- 证据：20 MB 文档下叶块重算不破 TAD §16.1 的 50 ms 主线程约束；块边界插入删除、跨块组合字符、全文替换的摘要结果与标定比较一致。
- 回退：仅对 >5 MB 文档降级为异步比较，并**仅在该降级路径**恢复 `checking` 语义——此时危险操作**有界等待该 revision 的精确结果（初值 300 ms），超时才保守处理**，不得直接保守中止。

摘要使用加密学摘要（如 SHA-256）以消除碰撞风险；根摘要相等时的一次标定比较仅作验证夹具，不在热路径执行。

## 5. D12：渲染并发模型

### 5.1 决策

解析与安全序列化共用同一个有界可取消执行器，并发为**每窗口 1、全应用上限 2**，调度按**活动文档 > 导出/后台任务**的优先级而非 FIFO。不设独立的全应用单清洗槽。

### 5.2 理由

「全应用单清洗槽」会与 PRD §11.2 的多窗口场景冲突：窗口 A 处理一个 5 MB 文档时，窗口 B 的 100 KB 文档编辑将排在其后（队头阻塞），使 ≤100 KB 文档的 P95 ≤300 ms 无法成立。单槽 + 可取消只能取消待执行任务，无法取消已在执行的工作。

同时明确该 P95 指标的**可测条件**为「单窗口活动文档、无并发大文档任务」，否则指标本身不可测。后台会话不渲染预览，因此不参与预览竞争。

## 7. 残余风险

- 原生 `RawHTMLSanitizer` 是本项目自实现的安全组件，缺少 DOMPurify 的长期公开审计历史。缓解措施：输入面限定为两类 AST 节点、白名单重建而非黑名单过滤、不确定即降级为转义文本、阶段 0 与 DOMPurify 双向对照、恶意夹具进入 CI 常态回归。
- 摘要树在极端编辑模式（如超大单行、频繁全文替换）下的重算成本需实测，已设 D11 的降级路径。
- 上述决策均未经原型验证，阶段 0 结果与本文冲突时以实测为准，并追加 ADR 记录反转理由。
