# 阶段 4：性能、质量与发布准备

## 1. 项目背景

Marklite V1.0 的发布标准不只是功能可见，还包括没有已知数据损失/越权路径、最低系统与沙盒行为可靠、英文及简体中文完整可用，以及可复现的性能与发行证据。本阶段在功能齐备版本上完成全量质量门禁、缺陷修复和发行准备，不把先前阶段未完成的安全能力包装为“发布后优化”。

依据：[PRD](<../../PRD-1.0(MVP)_20260916.md>) §3、§5、§9、§11～§14及AC-01～AC-47；[TAD](../../TAD-001-技术架构设计方案_20260916.md) §16～§20；[ADR](../../ADR-001-技术选型与架构决策_20260916.md) 风险/依赖/支持边界；[界面 Prompt](../../Prompt-Layout_20260916.md) 的single-file、folder-open、folder-menu场景。

## 3. 目标与边界

### 3.1 目标

1. 对AC-01～AC-47逐条给出通过证据，而非仅按模块勾选完成。
2. 在M1/8 GB/SSD/macOS 14+的Release构建上满足端到端速度、输入延迟、规模和资源生命周期要求。
3. 完成en/zh-Hans实际UI、系统语言路由、帮助、错误和VoiceOver验收。
4. 完成签名、最小entitlement、文件关联、离线资源、依赖许可及所选渠道发行验证。
5. 输出发布检查单、已知限制、问题处理和可回退构建信息，不附带额外联网/自动更新能力。

### 3.2 边界

- 不新增AI、账户、云同步、主题设置、插件、重命名等MVP外功能。
- Intel仅在负责人明确承诺且独立验证后支持；不能以Universal编译成功代替实测。
- 自动更新机制和渠道按已批准决策执行；未要求则不加入更新框架。
- 精细布局恢复和所有内容逐行滚动精度不是发布硬门槛；数据安全、授权、正文恢复不可作为已知限制豁免。

## 4. 阶段详细设计

### 4.1 S4-01：测试矩阵与候选构建冻结

每个候选记录commit、工具链/SDK、依赖锁、资源hash、最低系统和目标架构、签名entitlement、已批准ADR/需求变更。修复后生成新候选并重跑影响范围及核心安全回归，不沿用旧构建证据冒充新包通过。

| 维度 | 必测组合 |
|---|---|
| 系统/设备 | macOS 14最低系统与当前支持系统；M1/8 GB/SSD基线；额外架构按承诺验证 |
| 语言 | 英文系统、简中系统、系统与应用指定语言不一致、无支持语言时英文回退 |
| UI | 浅色/深色、默认/800×560窗口、屏幕边缘、全屏、减少透明度/动态效果 |
| 文本/路径 | 中文/日文输入法、Emoji/组合字符、长文件名、同名根外文件、BOM及换行、非法UTF-8 |
| 文件系统/权限 | 签名沙盒单文件/目录授权、只读、bookmark失效、符号/可识别硬链接、Git替换、竞争创建 |
| 故障 | 写入失败、磁盘满/配额、进程在提交点终止、草稿坏、Web进程退出、资源取消晚到 |
| 规模/并发 | 1/5/20 MB边界，20会话单窗，5单文档窗口，10,000项目录，多任务交错 |

CI云主机承担可重复自动检查，不替代M1实机指标、最低系统和真实输入法/VoiceOver。磁盘故障可在隔离卷/测试替身注入，明确证据类型，不污染用户文件。

### 4.2 S4-02：性能与资源收敛

采样协议先固定，再优化：同一Release构建、同一夹具/系统、记录冷启动与热缓存，不混算；建议每个速度场景预热5次、正式至少100次，保存原始样本并按固定算法计算P50/P95。此采样数是实施测试协议，不是新增产品功能。

| 指标 | 测量起止/场景 | 门槛 |
|---|---|---|
| 预览 | ≤100 KB、单窗活动文档且无并发大任务；最后字符输入至rendered并布局稳定，包含debounce/快照/解析/清洗/IPC/布局 | 端到端P95≤300 ms，不只测parser；网络下载耗时排除 |
| 打开 | ≤1 MB，用户确认打开至编辑器可接收输入，不等待预览 | P95≤1秒 |
| 输入 | 常规输入及高亮属性/字面精确判脏，记录主线程连续阻塞 | 无连续>50 ms主线程阻塞 |
| 多文档 | 20个约100 KB文档在同一窗口，连续编辑/切换/保存30分钟 | 状态正确，无持续内存增长 |
| 多窗口 | 五个窗口各一个同规模文档，连续30分钟 | 无串状态、无无界WebView/任务/缓存增长 |
| 大目录 | ≥10,000项，展开/刷新期间同时编辑 | 首屏有加载反馈，不扫描未展开子树、不阻塞编辑 |
| 大文件 | 阈值前/等于/后一字节，打开/重载/输入粘贴跨阈值 | 策略无重叠，预览可取消，已有内容与保存能力保留 |

分段预算沿用G0修订并批准的表，保留TAD的责任划分：合并等待、快照、解析、序列化/清洗、桥接、Web布局。初始150+10+60+40+20+30=310 ms不能作为达标证据；各段独立回归，总P95单独测量。清洗回退或后端变更必须重新分配预算。

资源观察包含原生和Web内容进程，不能假定一WebView对应一进程。采样队列长度、observer/租约/任务数、峰值和释放后内存；前5分钟预热后观察驻留趋势及重复开关后的回落，具体容差用G0实测基线固定，不编造总内存上限。不能为压低内存删除用户撤销或草稿。

检查G0校准的有界参数：主选/回退共用每窗口1/全应用2调度，回退最多2个惰性清洗上下文；每文档1个最新待请求；每窗3份位置无关SafeDocument缓存，命中重建当前位置资源；PDF一个槽/初值4个等待任务；草稿每会话2份/总2 GB，持续输入统一最长30秒成功提交。

图片按TAD §14.3.1联合验收：单图20 MB/4000万像素、动画200帧/累计8000万像素、全应用4读2解码、每任务累计256个唯一资源（含待处理与已载入）、每任务256 MB/全应用512 MB估算驻留（128 MB缓存包含其中）、SVG深度64/节点100,000，均以G0校准值为准。测本地巨图、高帧GIF、大SVG、短文档大量图片、预览+导出冻结及Base64副本，记录原生+Web峰值和预算耗尽/取消后的释放。不能把缓存或估算预算当实际进程总内存硬上限。

两个大文档占槽时再提交小文档，按G0固定的取消响应/最大等待阈值验收；两个槽不等于自动保证公平性。判脏采用长度快路径+UTF-16字面精确比较，最坏O(n)；分别测1/5/20 MB尾部等长替换、Undo、快照成本，仅批准的>5 MB降级可异步等待，禁止悄悄放宽≤5 MB门槛。

优化顺序：定位signpost责任段 → 消除主线程全篇复制/扫描 → 收敛高亮/布局测量范围 → 合并取消队列与资源释放 → 重跑正确性；不通过降低安全清洗或草稿保障换性能。

### 4.3 S4-03：安全与持久化故障回归

围绕TAD INV-01～INV-10逐一验证：唯一可编辑会话、唯一窗口归属、显式写原文件、快照保存、草稿代次、dirty阻止删除、导出目标保护、授权、生命周期独立、展示不改内容。

必须执行TAD §18.2全部竞态夹具，至少包含：

- 保存r10期间输入r11；Undo回同内容但revision不同；文尾等长替换、规范等价但码元不同文本、全文替换；基线更换后旧比较结果拒绝。
- 首存不存在目标被竞争创建；另存普通目标覆盖确认后被替换；另存选回源文件仍受冲突保护。
- 墓碑/clean关闭清理期间输入、失败解锁；退出期间Finder打开/新建/移窗/在途注册暂停，取消恢复请求、完成前再次核验集合。
- Reload读取期间输入、读取失败、旧checkpoint晚到；reloadCommitted前后强杀以及提交后磁盘再次变化，新旧代不会混用。
- 内容未改而另存到不同图片目录，外部移动、权限代次变化、移窗后命中缓存，重新生成当前manifest，无旧私有URL。
- 删除预检前Undo回clean；确认期间另窗输入/新增会话；目标身份/权限变化。
- 干净重载读取期间产生编辑；覆盖确认后磁盘再次变化；自身保存事件紧跟外部写入。
- A渲染晚于切B/移窗；旧根枚举晚到；scheme取消后返回；Web进程退出后旧桥接到达。
- Discard后旧checkpoint；保存成功但已有新草稿/先生成后提交的旧元数据；关闭第二项取消；所有持久提交点强杀重启。
- 所有规模/后台持续输入最长30秒成功检查点、停输入约2秒；20 MB文首插入及>20 MB编辑内容仍受恢复保护；块复用按完整字节验证，不假设局部O(log n)。
- 磁盘提交成功而UI未收到回执；导出确认后目标替换/被打开；无废纸篓支持。

安全夹具覆盖畸形HTML、脚本/事件、危险URL编码、DOM clobbering、伪造内部data属性、SVG/srcset/CSS旁路、跨frame及超长非法桥接。通过实际网络监听/测试端点记录证明未授权零请求，而非只看UI提示。清洗对照差异须有规则解释；不能用“与对照相同”单独证明绝对安全。

数据丢失、误删、静默冲突覆盖、任意脚本执行或越权读取属于发布阻断。修复增加可复现回归夹具，不接受仅在报告中说明风险后发布。

### 4.4 S4-04：双语、辅助功能与视觉验收

- CI检查String Catalog两语键完整、参数类型/数量、复数与本地化帮助，漏译不能以英文回退掩盖。
- 系统/应用语言选择验证重启，文件正文、名称、路径、草稿不变；无界面语言选择器、旗帜或混语标签。
- 全流程覆盖菜单、命名、删除范围确认、保存失败、冲突、恢复、导出、远程阻止、可靠性警告、工具提示及文件类型名。
- 双语各自人工VoiceOver验证标题脏状态、冲突、菜单、树、临时导航、查找、提示和对话框；图标标签、朗读状态、Tab顺序/Esc返回均正确。
- 真实输入法验证候选、marked range、切文档/移窗/关闭，不能只用XCUITest模拟普通键代替。
- 对比度目标≥4.5:1，系统主题、减少透明度/动态效果有效；切主题不改dirty或阅读位置。

视觉场景在同一信息架构分别检查en/zh-Hans，用户文档保持原文：

1. single-file：默认隐藏侧栏，正文满宽，无空槽/标签栏。
2. folder-open：约220 pt侧栏，已打开列表+单根树，README可同时出现在两组但仅一活动编辑器；正文剩余宽度48/52。
3. folder-menu：只打开目录上下文菜单，New File/New Folder、分隔、Reveal in Finder、分隔、Move to Trash；无Rename/永久Delete/额外工具条，菜单焦点下不显示编辑caret。

默认1280×820 pt、最小800×560 pt；标题栏约48～52 pt、正文约占内部高度94%～95%、双栏各≥320 pt、交互区≥28×28 pt。Prompt的1920×1200是参考截图画布，不作为应用窗口像素尺寸。侧栏/查找/错误条按场景出现，不为截图擅删功能。

### 4.5 S4-05：帮助与隐私诊断

随包交付英文、简中本地帮助：打开/保存/编码、目录与会话区别、快捷键、冲突与恢复、废纸篓范围及手动重试、图片授权、查找模式、导出和大文件限制。不依赖网络，明确“草稿不是原文件已保存”。

Help加入用户主动诊断导出入口，列明将包含的数据类别，确认后写用户选定目标。只含操作ID、耗时、规模区间、队列/缓存和错误类型，路径/文件名替换稳定占位符；不得含正文、原始HTML、URL、草稿或bookmark，不自动上传。目标写入复用导出保护，不能覆盖源/已打开文档。用含敏感样本的自动检查验证脱敏，而非仅审查文案。

### 4.6 S4-06：构建、签名与发行验证

CI使用已经建立的同一Scripts入口执行：Swift编译/静态检查/严格并发、Core与确定性测试、Web类型/单测/资源构建、许可证、双语完整性、真实文件/恢复/WebKit集成；定期实机跑Release性能及人工专项。脚本名字以实际交付为准，本计划不假定不存在的命令可运行。

发行检查：

- 锁定工具链、SPM/JS/C依赖与许可证，生成依赖及随包资源清单/hash。所有样式、高亮、脚本和帮助本地存在，Node不随App运行。
- 签名标识、entitlement最小权限、security-scoped bookmark、HTTP策略与批准基线一致，无关闭沙盒或任意联网豁免。
- 在干净测试账户/机器安装候选包，验证Finder关联三类Markdown、Open With、应用图标/窗口拖放、Recent/Clear Menu和系统恢复。
- 验证无网络时编辑、预览、本地图、HTML/PDF导出与帮助正常；首次启动不下载资源、不默认采集分析。
- 直接分发须完成公证、票据及Gatekeeper验证；若选择商店渠道，按实际渠道规则验证，不能把本地签名成功等同可分发。
- 保存校验后的包hash、签名/公证结果、发布说明、已知限制及支持系统；凭证不进仓库、不进日志。
- 回退保留上一已验证构建，未知/较新恢复schema采用隔离/只读路径；不能为了旧版本兼容自动删除用户草稿。新schema或迁移需单独回归。
