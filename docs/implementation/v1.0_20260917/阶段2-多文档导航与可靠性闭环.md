# 阶段 2：多文档导航与可靠性闭环

## 1. 项目背景

Marklite 的多文档不是多份 UI 文本副本，而是由应用注册表管理、可跨窗口迁移的独立会话。目录树只承担导航，不拥有文档生命周期。阶段 2 在单文档安全闭环之上实现多会话、目录、冲突和持久化可靠性，为下一阶段真实磁盘删除提供前提。

依据：[PRD](<../../PRD-1.0(MVP)_20260916.md>) F-02、F-06～F-09、§8、§11；[TAD](../../TAD-001-技术架构设计方案_20260916.md) §3～§6、§10～§12、§16～§18；[界面 Prompt](../../Prompt-Layout_20260916.md) 的 folder-open 与功能模型；[ADR](../../ADR-001-技术选型与架构决策_20260916.md) 文档所有权、文件身份和恢复协议。

## 3. 目标与边界

### 3.1 目标

- 全应用同一实际文件最多一个可编辑会话，每个会话同时属于一个窗口。
- 同窗口批量打开、切换与显式移窗不丢文字、独立撤销、输入法提交、选择和阅读状态。
- 可选侧栏包含完整已打开列表与单根按需目录；更换/关闭目录不影响已打开文档。
- 后台会话同样拥有草稿、外部变化检测、退出确认与恢复。
- 通过持久化代次、短期操作资格和确定性竞态测试证明危险操作不会使用陈旧状态。

### 3.2 边界

不交付创建/废纸篓、完整查找、资源加载和 HTML/PDF 导出；但要为这些功能提供真实的目标保护、目录范围预留与租约接口。禁止以树刷新失败、权限失效、缓存淘汰为由删除文本或撤销历史。

重启精细布局允许安全回退；运行中会话切换的文字、撤销与阅读状态不允许降级。崩溃草稿恢复独立于系统正常窗口恢复设置。

## 4. 阶段详细设计

### 4.1 S2-01：应用注册表与操作协调

扩展 `Marklite/Application/`：DocumentRegistry、WindowRegistry、FileOperationCoordinator、Open/MoveSession 协调器。

- 同时维护实际身份索引与规范化位置占用索引；符号链接及可识别硬链接参与去重，不自行小写路径或 Unicode 归一化模拟文件系统。
- 并发打开先预留，读取失败释放；Git 式同路径替换更新身份，不创建第二编辑源。
- 请求戳按任务携带 DocumentID/revision/LocationEpoch、WindowID/BindingEpoch/RootEpoch、OperationID，草稿另含 RecoveryEpoch。
- 渲染/高亮/查找仅接收匹配当前版本的结果；保存回执即使落后于当前 revision 仍必须处理；不能统一写成“版本不等全部丢弃”。
- 预留覆盖路径、实际身份和目录范围，冲突操作排队；等待用户选择/确认时不长期持锁，系统协调 accessor 不等待 UI。
- 不能将可重入 actor 当跨 await 事务锁；token 必须在提交前重核资格。

### 4.2 S2-02：打开、切换与移窗

| 操作 | 实现契约 |
|---|---|
| 普通打开 | 当前窗口新建/激活会话；Finder、Recent、应用图标拖放走最近活动窗口，窗口拖放走指定窗口 |
| 批量打开 | 读取可并行，列表按请求顺序，激活第一个有效项；错误逐项反馈，不按 I/O 完成顺序排序 |
| 已打开文件 | 聚焦所属窗口，不隐式迁移、不复制文本 |
| 新文档 | ⌘N 不受树选择影响，在当前窗口增加未命名会话 |
| 切换 | 安全结束 IME，记录选择/锚点/分栏/最近交互栏；不能完成则保留原会话和焦点 |
| 移窗 | 同一编辑后端及 UndoManager 迁移，仅变 ownerWindowID；源窗有根则留空浏览，否则最后会话移出后关闭 |
| 前后文档 | 按当前窗口稳定打开顺序循环，切换不重排列表 |

每会话保留独立NSTextView/TextKit后端，仅活动后端挂接视图树。预览重绑定推进BindingEpoch并取消旧资源请求。LRU初值每窗口3份，键为DocumentID+revision+policyVersion，只存位置无关SafeDocument结构和未解析引用，不存解析后路径、授权、私有URL或旧令牌。命中后跳过Markdown解析/清洗，但必须按当前源位置、LocationEpoch、授权/资源代次重新生成资源/链接manifest及私有句柄，再核验绑定并注入恢复锚点；重建期间清旧正文，不先显示旧资源。未命中则解析。后台不持续预览，不释放文本/撤销。

菜单区分未打开文件的 Open in New Window 与已打开会话的 Move to New Window；即使发生竞态，“在新窗口打开”也不得复制已有会话。

### 4.3 S2-03：侧栏、窄窗口与命令面

`SidebarController + NSOutlineView` 展示两组：Open Documents 与当前单根目录。列表包含未命名、根目录外、隐藏文件会话；同名项用父目录/相对路径消歧，标记活动/未保存/冲突并提供 AX 状态。行关闭只是关闭会话，不是删除。

导航采用 `sidebarRequested` 与 `hidden/docked/transient` 分离：

1. 单文件新窗口默认隐藏；本轮首次由一到多请求自动显示一次。
2. 用户已主动隐藏优先于后续自动展开；主动打开/更换目录或点击按钮可重新显示。
3. 宽度足够停靠；不足先在屏幕范围扩宽，不能扩宽时使用 G0 验证的原生临时面板，不改变正文模式、不把双栏压到320 pt以下。
4. 被动缩窄仅收起停靠，不抢焦点自动弹面板；用户主动请求才打开临时导航。
5. 支持键盘选择/展开/激活/关闭，Esc 关闭临时面板并回原正文焦点。Window > Open Documents 按窗口分组，隐藏侧栏时仍可访问所有会话。

参照 Prompt：文件树与已打开列表同时出现同一 README 是会话/路径两种投影，不是两个编辑器；静止态不显示关闭/创建/垃圾桶工具条。深浅色和双语使用同一结构，不翻译用户文件名。

### 4.4 S2-04：目录授权、枚举与变化

`PermissionBroker` 管理 bookmark 与 AccessLease，导航、文档、图片、后续导出分别持租约，最后使用者释放才 stopAccessing。Recent 不是权限，单文件授权不自动允许枚举父目录。

- Open/Change Folder 先选目录并获得权限，成功后原子切换 root 与 RootEpoch；失败/取消保留旧根，相同根只显示导航。
- Close Folder 只解除导航关系/监控；已有文档、草稿、资源租约保留。Open Folder in New Window 才显式建新窗。
- 打开文件夹不自动打开子文件；无活动文档仅简短选文件提示，不生成空白会话。
- 单层后台分批枚举，文件夹优先、自然排序，隐藏点项/应用包/node_modules，仅展示三类 Markdown 扩展；空目录不预扫描过滤，链接目录不递归展开。
- 节点状态 unloaded/loading/loaded/failed 可重试；结果匹配 WindowID+RootEpoch+目录身份，不接收旧根迟到结果。
- 监控仅刷新已加载目录，不为树上所有文件创建 DocumentSession、文件监控或 WebView。
- 授权陈旧刷新或请求重新选择；无权限保留模型与正文。路径范围用组件与实际身份校验，不能字符串前缀判断。

### 4.5 S2-05：外部变化、冲突与重载

以 NSFilePresenter/协调访问为基础，配合目录事件与激活时核验。事件只是复核信号；磁盘指纹不能仅用 mtime。自身保存事件用操作记录协调，但不能屏蔽紧接的外部写入。

| 场景 | 处理 |
|---|---|
| clean 外部变化 | 捕获 revision 后读取；提交前仍 clean 且 revision 未变才重载，尽力恢复位置 |
| 读取期间产生编辑 | 不应用旧读取，转冲突，保留新文本 |
| dirty 外部变化 | 非模态冲突提示；后台先标记，激活解释，不覆盖任一版本 |
| 文件删除/只读 | 保留编辑；另存、重新授权或显式重新创建，不普通 Save 偷偷复活 |
| 可靠跟踪到新路径 | 更新位置、身份、监控、LocationEpoch 与资源基准 |
| 外部规模跨阈值 | >5 MB 先提示；>20 MB 保留旧缓冲区并标 changed，有本地编辑先冲突，不误标同步 |

冲突操作：Reload from Disk明确告知丢弃本地修改、撤销及旧恢复代次；不建设隐式历史版本入口。Save As复用三类TargetExpectation。Overwrite只授权确认过的磁盘版本，再变化须重确认。

**Reload事务（G0必须验证）**：
1. 确认绑定DocumentID/revision/LocationEpoch/磁盘版本，后台读取完整稳定的新快照；读取失败保留原缓冲区、Undo和草稿。
2. 取得会话短期资格，安全结束IME，再核验内容revision和磁盘版本；读取期间产生新编辑则中止旧确认，不覆盖新输入。
3. 禁止该会话字符修改，在恢复串行提交队列持久化`reloadCommitted`：旧代废弃、新RecoveryEpoch、已校验的新快照及双基线；先确保新快照持久有效，再原子提交记录。记录之前不删旧草稿。
4. 持久提交后同一主actor替换文本、清Undo/Redo、推进revision/baselineGeneration并更新双基线，再解锁。记录提交前失败恢复旧状态；提交后结果不确定先复核，不误报未重载。
5. 启动先消费记录再扫描草稿；记录前崩溃旧代仍有效，记录后旧代不可恢复，新状态可重建。磁盘此后再变，新快照作为明确副本而非自动写源。新代current/状态清单提交完成前不得清理记录引用的快照。自动clean重载复用该事务，只省略放弃确认。

### 4.6 S2-06：草稿存储与检查点

拟实现 `Infrastructure/Recovery/`：版本化 `state-v1.json`、`grants-v1.json`、每文档 current 指针/快照/块存储，以及每操作恢复记录。全部放系统返回的容器 Application Support，不硬编码主目录，用户私有权限；不声称容器提供额外加密。

- 停输入约2秒触发；所有规模持续输入统一最长30秒成功提交检查点，后台相同，切换不重置。首次变脏/上一成功检查点起计，预留生成和I/O时间，不能只每30秒发起一次写入。
- revision与基线/位置/编码元数据均未变可跳过；否则后台精确比较内容，正文不变但元数据变了仍更新。记录内容、编码、revision、RecoveryEpoch、baselineGeneration、LocationEpoch、授权引用、双基线和校验。
- >1 MB后台固定64 KB UTF-8字节块，摘要索引后核验字节再复用；块可跨字符，拼完整后解码。不维护按键热路径摘要树，接受文首插入导致后续全变及O(n)扫描/写入；每个已提交索引可重建全文。
- 先写并校验快照，再在串行提交队列复核代次/版本及基线/位置代次后原子更新current；保存/另存为已改变元数据时合入当前基线，不让先生成后提交的checkpoint带回旧基线。旧结果不得覆盖新指针，>20 MB编辑内容仍备份并受总配额/告警保护。
- 初值每会话保留 current+上一份，总配额2 GB。只回收已覆盖旧代和孤立产物，不删唯一有效检查点；仍满显示持续非模态可靠性警告，保留 dirty。
- 磁盘满、校验错、未知 schema 隔离或只读恢复；不能用 mtime 最大的孤立快照冒充已提交检查点。
- 所有后台 dirty 会话同等参与，不仅活动文档有草稿。

### 4.7 S2-07：关闭、放弃、退出与恢复

**放弃协议**：确认绑定revision → 安全结束IME并复核（内容变了重新确认）→ 取得closing资格并阻止全部字符修改入口 → 使旧任务失效 → 持久化tombstone/废弃代次 → 确认成功后紧接移除会话。若无法持久化或可靠清除恢复记录，中止关闭、解锁并保留旧有效草稿。磁盘提交结果不确定先复核，不提前恢复输入导致放弃范围漂移；慢操作有反馈且无关会话可编辑。

**保存后的草稿**：只清理被保存快照覆盖的相同/更旧版本；较新草稿更新基线不删内容。clean关闭异步清理前取得closing资格、结束IME并重新判脏；新编辑已进入则转脏关闭流程，清理中禁止字符修改，失败解锁。不能以清理前clean为由关闭已变脏会话。

**关闭队列**：⌘W 当前文档，⇧⌘W/红按钮当前窗口，⌘Q 全应用。按有序集合逐个处理 Save/Don’t Save/Cancel；前序完成不回滚，当前取消/失败中止后续。保存期间新编辑则重新处理当前会话。最后会话关闭时有根留空浏览，无根关闭窗口。系统延迟终止等待异步结果，不重复出现两套确认。

**关闭/退出准入**：窗口关闭暂停向该窗口新建/打开/移入；应用退出置terminationPending，统一拦截所有窗口的新建、Finder/Recent/拖放、恢复和移窗入口。已在途读取可结束但不得注册，按请求顺序暂存。取消后重新核验目标窗口/身份并恢复处理；成功退出不将暂存请求伪记为已打开。最终在主actor再次检查无未处理存活会话、无绕过屏障的在途提交，协调导出后才回复系统允许退出；不以初始队列已空代替最终检查。

**退出清单**：退出开始先捕获候选，再合入保存/另存为后位置，不能从关闭后的空注册表生成。取消退出废弃候选，持久化仍存活集合并恢复暂存请求；正常单文档关闭更新运行中清单。

**启动恢复顺序**：初始化服务/语言 → 读schema/墓碑/reloadCommitted及保存操作记录，确定有效恢复代次 → 扫描草稿并 Restore/Discard → 按系统设置恢复正常文件/活动项/目录 → 统一处理 Finder 待办与去重 → 无内容时才新建空白。

- 草稿源可访问且磁盘基线匹配：恢复到原源会话并 dirty；源变化、丢失、权限失效：作为恢复副本，要求另存为，绝不自动写源。
- tombstone 优先，当前快照损坏可回退上一有效代；单项失败不阻塞其他项。
- 保存已提交但 UI 回执前崩溃：按磁盘实际指纹核验操作记录，不自动重放写入、不误报未写。
- 正常恢复必须含可访问已保存文件、活动项和关联根，保持不同根独立窗口；布局、精细滚动等尽力恢复。
- 系统关闭窗口恢复不等于放弃崩溃草稿；不恢复从未编辑的未命名空文档。同步开关重启默认开，主动隐藏偏好不跨运行强制继承。

### 4.8 执行顺序、交付及故障矩阵

顺序：S2-01 → S2-02 → S2-03/S2-04 → S2-05/S2-06 → S2-07 → 全组合门禁。恢复与关闭必须集成完成，不能以“已落盘草稿”代替“可安全放弃”。

主要交付：多会话应用、目录/租约模型、持久化schema及恢复策略、系统恢复适配、双语可靠性提示、故障注入与压力报告。证据建议 `evidence/stage-2/`。

必须覆盖：A渲染晚于切B/移窗、旧根枚举；同内容另存到不同图片目录后缓存命中、权限代次变化；保存r10/r11草稿及先生成后提交的旧基线；Discard晚到；墓碑/clean清理期间输入；退出Finder/新建/移窗/在途打开和取消后恢复；手动/自动Reload读取中输入、失败、旧checkpoint晚到、reloadCommitted每个提交点强杀及磁盘再变；关闭第二项取消；保存提交后退出；30秒检查点含文首插入、编辑超限、磁盘满/配额/坏指针/缺块；恢复与Finder去重。故障模拟与真实沙盒测试分开记录，不能用前者替代平台权限证据。

## 5. 验收标准

| 编号 | 可执行验收 | 关联需求 |
|---|---|---|
| G2-01 | 同路径、符号/可识别硬链接、并发打开与恢复/Finder竞争仅一个可编辑会话，聚焦所属窗 | AC-19 |
