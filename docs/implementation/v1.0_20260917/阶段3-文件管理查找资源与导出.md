# 阶段 3：文件管理、查找、资源与导出

## 1. 项目背景

Marklite 在已有安全编辑和多会话可靠性基础上补齐 V1.0 功能。真实文件操作、资源读取与导出必须复用统一身份、权限、快照及提交协调，不能在菜单或 WebView 内另建文件业务。本阶段结束应功能齐备，但仍需阶段 4 全量发布验收。

依据：[PRD](<../../PRD-1.0(MVP)_20260916.md>) F-10、E-05/E-06、A-01～A-03、X-01～X-03；[TAD](../../TAD-001-技术架构设计方案_20260916.md) §7.3、§9.2、§13～§15；[界面 Prompt](../../Prompt-Layout_20260916.md) folder-menu 场景及菜单限制；[ADR](../../ADR-001-技术选型与架构决策_20260916.md) §7～§9。

## 3. 目标与边界

### 3.1 目标

- 在明确目录创建 Markdown 文件/文件夹，单项移到系统废纸篓；正确处理跨窗口受影响会话。
- 源码查找/替换与全文渲染文本查找符合模式语义，临时高亮不改变内容或导出。
- 本地图片按授权读取，远程图片按会话显式允许，所有链接经受控用户激活路径。
- HTML/PDF 从启动快照独立生成，可离线使用，且绝不覆盖源文件或任何已打开文档。

### 3.2 边界

不实现树内重命名、拖动整理、批量操作、永久删除、图片粘贴/自动复制、正则查找、在线转换或任意网络访问。任务列表仍只读；导出不是正文隐私脱敏工具，不自动删除用户显式路径文字。

## 4. 阶段详细设计

### 4.1 S3-01：排他创建与菜单目标

拟扩展 `Application/` 的创建协调器和 `Infrastructure/Files/`，树上下文命令在触发时绑定节点身份，不能稍后读取可能改变的选中项。

- ⌘N 始终创建未命名会话；File > New File in Folder/New Folder 与树上下文创建分开。
- 父目录优先选中目录，其次选中文件的父目录，再次窗口根目录；无根/写权不足时禁用或明确授权途径。命名对话框显示实际父目录。
- 默认 Untitled.md/未命名.md、New Folder/新建文件夹；输入是单个名称，拒绝空、`.`、`..`、分隔符和非法名称，无扩展补`.md`，仅允许`.md/.markdown/.mdown`。
- 合法中文、空格、Emoji原样保留；碰撞按实际文件系统规则，通过排他创建处理校验后竞争，不覆盖、不自动改名绕过冲突。
- 点开头名称或node_modules文件夹等会被隐藏时创建前告知；创建后提供Reveal in Finder。隐藏文件仍打开会话，隐藏文件夹选中可见父目录。
- 最终确认后重新核验真实父目录身份、授权、链接变化与操作资格，禁止通过链接父目录越界。
- 空Markdown以UTF-8无BOM/LF策略创建，成功刷新树并打开clean会话；可见目录成功选中且不建会话。
- 取消零磁盘变更；失败保留输入；磁盘已创建而打开失败须如实说明并提供重试，不能误报“没有创建”。

### 4.2 S3-02：废纸篓影响分析与安全提交

`TrashPlan` 记录入口节点/真实父目录身份、目录范围、全应用受影响会话、浏览根、确认版本。只允许明确的树节点触发，禁止发起窗口根目录删除；Open Documents关闭不映射删除，无删除快捷键/常驻垃圾桶按钮。

```text
解析被点击节点与影响范围
 → 全应用检查dirty、IME与身份
 → 有风险则中止并提供定位（不由删除写磁盘/改草稿）
 → clean但有相关在途保存：等待原保存完成并消费回执
 → 重建影响范围/重新判脏，变脏即中止且须手动重试
 → 全部clean且相关保存已结清，才显示新的真实范围确认
 → 用户确认后申请短期范围资格
 → 重检身份、权限、会话版本及新会话
 → 受影响编辑器短暂操作中只读
 → 系统Trash API
 → 核验回执并更新仍受影响的clean会话/树/根目录
```

- 任一受影响dirty、组合输入未安全结束或身份不确定即中止。撤销刚回基线的文档应按实际clean处理；仅G0批准的降级路径允许有界等待判脏。
- 提示列出跨窗口文档名称/路径与定位操作，要求用户自行保存、另存或关闭后**手动重试**。删除中不调用Save/Don’t Save、不清草稿、不自动继续。
- 按TAD §4.5仲裁已存在的保存，不把clean视为无在途写入：源或保存目标涉及范围的请求均检查，未知目标安全中止。仅clean时等待已接受请求，暂停相关会话新普通保存但不锁输入、不持范围锁；取消等待只取消删除。保存失败/面板取消/结果不确定则中止并保留记录。成功回执更新位置/双基线后废弃旧TrashPlan和确认，重新分析，dirty则立即中止，仍clean才重新确认。原保存可能正常写入，不能向用户声称取消删除同时取消了保存。
- 确认期间新增保存使计划失效；最终范围/会话资格与保存提交互斥，不能先Trash再等保存完成。DIRTY-01同步Undo回基线立即clean；DIRTY-02仅批准的大文件异步比较可有界等待当前版本，超时安全中止。两类均不能绕过在途保存检查。
- 确认目录包含所有真实子项，明确含隐藏与非Markdown内容；提醒原位置保存后也会随目录删除，需保留独立文件应另存范围外。
- 确认期间不锁编辑；提交前若新增输入/会话/身份变化中止。临界区只影响受影响后端，已接收输入不得丢弃；慢操作有反馈，不冻结无关文档。
- 删除符号链接只删入口链接，不能跟随删目标；可识别别名纳入保守保护，不确定中止。
- Trash失败/不支持保留所有会话、草稿、缓冲区，绝不永久删除兜底。结果不确定先复核，不能凭单个文件事件清会话。
- 成功后关闭仍指向被删目标的clean会话，刷新相关窗口，失效根进入不可用状态；已另存范围外会话保留。正常清理按已有协议执行，不在提交前删除恢复信息。
- 不承诺文本Undo恢复磁盘删除，指引Finder废纸篓。

### 4.3 S3-03：源码查找与替换

`FindState(query, caseSensitive, target, currentMatch)` 由应用层维护，SourceFindAdapter封装系统查找或已验证匹配服务。临时原生查找栏放对应区域顶部，不常驻。

- Editor/Split中的⌘F查源码，显示当前/总数，⌘G/⇧⌘G切项；Esc回到对应正文焦点。
- 普通文本及大小写策略固定，覆盖Unicode/中文/组合字符；空查询不能替换，不支持正则。
- 匹配结果绑定DocumentID/revision，编辑后重算，禁止沿用旧范围。
- 替换当前项或全部；Replace All对固定范围逆序应用，作为一个Undo组及文本编辑事务，结束时统一更新revision、字面精确判脏及草稿，不逐片段全文比较；事务中不允许危险操作读取中间clean状态。
- Find and Replace（⌥⌘F）在Preview中先切Split，再查源码；保留query、重算计数，渲染文本不提供直接替换。
- 查找输入框使用自身撤销，不能误改正文；查找高亮不影响dirty。

### 4.4 S3-04：全文预览查找

Web侧从整个渲染文档的展示文本构造VisibleTextIndex，不限当前视口；排除隐藏节点、属性、脚本及应用控制区。

- 合并相邻文本节点，建立索引到DOM Range映射，覆盖跨强调/链接节点、中文、空白折叠、块分隔与大小写。
- Preview下⌘F不切模式，提供总数/当前/上下项/快捷键，定位时滚动；Esc回预览焦点。
- 视图切换保留查询但按新target重算；重渲染绑定新revision，尽力保持匹配位置。
- 临时高亮可完全移除，不破坏链接/语义/AX；几何改变通知滚动映射更新，不能触发持续反馈。
- 文档不能自造查找桥接调用原生能力；导出从SafeDocument重新生成，绝不读取被高亮污染的DOM。

### 4.5 S3-05：本地图片与受控资源句柄

实现ResourceResolver、ResourceManifest及WKURLSchemeHandler，只暴露 `marklite-resource://<opaque-session-token>/<resourceID>`，不含真实路径，不是通用文件服务器。

- 每个资源绑定DocumentID、LocationEpoch、授权/资源代次、类型和版本；原生校验当前WebView及绑定，令牌本身不是唯一权限边界。
- 有路径文档即使dirty仍按当前源目录解析相对图片；仅无路径提示先保存。另存为不复制图片或改源码。SafeDocument缓存只存位置无关安全结构/未解析引用；键为DocumentID/revision/policyVersion，命中后按当前源位置、LocationEpoch、授权/资源代次重建资源与链接manifest、私有URL和句柄，再绑定注入。缓存不携带租约/解析后路径/旧令牌，不能先注入旧资源再补校验。
- URL解码、规范化、符号链接真实目标和授权边界均校验，尽量以稳定句柄读取后复核，不能通过`..`或链接替换越权。
- 缺权使用非模态提示选择资源目录；关闭根目录不撤销仍由文档/资源持有的租约。
- PNG/JPEG/GIF/WebP后台验证/解码，读取头部与检查尺寸在完整分配前完成；本地图同样受单图/动画/累计预算限制。SVG阻断执行/外部引用，限制解析复杂度与输出尺寸，不作为顶层、object或内嵌DOM。
- 失败显示alt/局部占位及原因，不遮整个预览。scheme取消后登记终止，晚到数据不再回调停止的WKURLSchemeTask。
- 图片加载高度变化走增量几何失效与锚点校正，不能重置顶部或套旧版本几何。

### 4.6 S3-06：远程图片与链接

默认blocked，原生临时提示条Load Images只授权当前会话。移窗保留，另一个会话不能共享授权，重启不恢复。

- 原生URLSession非持久配置，无环境Cookie/凭据；WebView不能直接请求站点。HTTP/HTTPS使用G0验证的最小ATS策略，不全局放行、不绕过证书错误。
- 每次重定向复核协议/策略；总超时30秒、最多5次重定向。输入/解码/缓存统一受下述ResourceBudget限制，参数使用G0校准值，不因来源不同绕过限制。
- srcset、CSS URL、data URL、SVG附属资源纳入同一政策；未授权不因缓存命中或导出而读取网络。
- 文内锚点通过anchorManifest；http/https/mailto仅真实用户点击后交系统；相对Markdown走统一打开去重/授权，其他本地文件显式点击后交系统。
- 拒绝javascript及未允许执行协议，拦截自动导航和target/new-window旁路。桥接仅解析当前BoundPreview.linkManifest的linkID，不接受任意原始URL指令。

### 4.6.1 统一图片预算与失败行为

只建立一个ResourceBudget记账器及有限队列，复用TAD §14.3.1，不增加独立资源服务框架。本地、远程、data URL、预览和导出共用政策；以下为G0待测初值，实测批准后固定：

| 范围 | 初值 |
|---|---|
| 单图 | 输入≤20 MB，静态解码≤4000万像素；流式字节计数、头部尺寸检查先于完整读取/解码 |
| GIF等动画 | ≤200帧、累计≤8000万像素，所有帧成本计入预算；超限占位 |
| 并发/待处理 | 全应用4个读取/下载、2个解码；每预览/导出任务累计最多256个唯一资源（含待处理与已载入），其余标缺失；取消释放槽/记账 |
| 驻留估算 | 每预览/导出任务≤256 MB、全应用图片相关≤512 MB，128 MB缓存包含其中；在途字节、解码像素、冻结资源、Base64和副本均记账，共享仅计一次、复制追加预留 |
| SVG | 深度≤64、节点≤100,000；输入与输出尺寸仍受字节/像素限制，禁止附属请求 |

先预留再分配，不在解码完成后才检查额度；不能可靠估算时安全占位。预算耗尽不回收仍被任务引用的数据，不动正文/Undo/草稿；预览局部提示，导出走缺失资源选择。WebKit副本与解码不是原生缓存能精确控制的，须限制送入DOM的累计像素和资源数，并测原生+Web进程峰值、校准放大系数；以上估算值不冒充实际总内存硬上限。

### 4.7 S3-07：独立导出任务与共享提交保护

ExportJob在启动时冻结文本/revision、源位置、资源策略及已授权且成功加载的远程资源版本，并持必要租约。排队只保留引用，资源仍可用才在取得任务资格后按预算固定字节；若启动版本已不可用，按缺失处理，不悄悄改用更新版本。资源在排队期间若需保留，必须记入预算，不能靠引用逃避持有成本。本地图片在准备阶段读取为固定字节。焦点、编辑、移窗、关闭源会话不能改变任务内容。

流程：preparing → rendering → 缺失资源选择 → readyToCommit → committing → completed；生成阶段可取消，提交后按真实结果报告。超过500 ms显示轻量进度，应用退出时协调完成或取消未提交任务。

- 缺失图片允许取消或占位导出，不为导出额外请求未授权/未加载远程图片。
- 保存面板约束格式扩展；默认源基名+.html/.pdf，未命名用本地化Untitled/未命名。默认最近导出目录，首次源目录，无源则系统文档目录。
- TargetProtection复用阶段1三类TargetExpectation、注册表/身份/预留并增加源Markdown及全部已打开文档保护，包含符号/可识别硬链接；不按扩展名猜身份。普通目标确认与源基线分开，不能为导出另建弱化覆盖流程。
- 普通已存在目标确认具体版本；确认后变化重新确认或中止。导出期间新打开的目标也应在提交前被保护。
- 先完整生成私有临时产物，再准备平台允许的安全提交；生成/取消/失败只清本次产物，不删截旧目标。
- 提交一旦开始不承诺取消等于未写；结果不确定保留操作证据并复核。导出不更新源savedBaseline、dirty或Undo。

### 4.8 S3-08：HTML与PDF生成

**HTML**：从冻结文本重新解析，经PRD R-01.1/TAD §8.2.1同一静态HTML子集生成完整UTF-8文档，内嵌样式和允许图片。HTML-01～HTML-05验证标签/属性、跨节点配对、实体/锚点与降级规则；预览、HTML及PDF保持内容语义一致，不把details/summary重新变成导出交互，也不全转义原本支持的HTML。输出无script、桥接、查找高亮、私有scheme、容器临时路径、诊断数据、CDN和远程字体；任务列表只读。用户正文自带的显式路径不自动脱敏，但链接仍遵循协议限制。离线浏览器打开验证样式与内容。

**PDF**：使用G0选定本地打印后端与独立WebView，初值一个渲染槽、最多4个等待任务，满则提示稍后重试，排队/生成可取消。排队不复制图片，取得资格后遵守统一资源预算；不借用当前活动预览DOM。

- A4、白底深字、独立打印CSS；页边距按G0结果固定（候选15 mm）。
- 等待资源settled、字体就绪、布局稳定，不能只等待didFinish。
- 全文、多页、可选文字、链接，长代码/URL/宽表无明显横向裁切；尽量避免孤立标题，超高块允许合理分页。
- 禁止截图替代全文PDF；后端无法达标回到专项决策，不默认引入远端服务。

### 4.9 顺序、交付与集成测试

实施顺序：S3-01 → S3-02；S3-03 → S3-04；S3-05 → S3-06 → S3-07 → S3-08。各链可按模块推进，导出需等待安全资源及快照契约就绪；最后统一回归菜单/语言/焦点及危险操作竞争。

交付模块位于`Application/`、`Infrastructure/Files/`、`Infrastructure/Rendering/`、`Infrastructure/Export/`、`Preview/`和`WebAssets/`；所有新增用户文案进入String Catalog，帮助草稿同步更新。证据建议`evidence/stage-3/`。
