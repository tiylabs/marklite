# 阶段 0：技术风险验证与实施基线

## 1. 项目背景

Marklite V1.0 是 macOS 14+ 本地 Markdown 文件编辑与实时预览工具，以 Apple Silicon 为主要测试平台。产品采用同窗口多文档、可选单根目录侧栏与显式多窗口；不是笔记库、IDE 或云端服务。原文件仅显式保存，恢复草稿独立存储，所有 Markdown 均视为不可信输入。

本计划依据：

- [界面 Prompt](../../Prompt-Layout_20260916.md)：场景、视觉与交互参考，不替代 PRD。
- [PRD V1.0](<../../PRD-1.0(MVP)_20260916.md>)：功能、安全、性能与 AC-01～AC-47 产品验收基线。
- [TAD-001 v1.3](../../TAD-001-技术架构设计方案_20260916.md)：模块、状态机、并发、持久化与实现方案。
- [ADR-001 v1.3](../../ADR-001-技术选型与架构决策_20260916.md)：技术路线及 D09～D12。

2026-09-17 编制时，仓库主要包含需求、架构及设计参考图，尚无 Xcode 应用、Swift Package、WebAssets 或测试工程。因此所有代码路径、测试入口和组件均为拟交付，不能视作已实现、已编译或已验证。

## 3. 目标与边界

### 3.1 目标

1. 证明原生编辑、受控 Web 预览、文件事务和草稿协议能够共同满足产品要求。
2. 将“建议实现”转为带证据的可执行基线：工具链、解析器、TextKit 后端、清洗策略、PDF 路径与沙盒权限。
3. 建立可复用测试夹具、可控时钟/故障注入、性能采样及证据格式。
4. 尽早暴露数据损失、越权、取消失败和最低系统兼容风险，避免在完整 UI 后返工。

### 3.2 边界

- 仅验证 Swift + AppKit + NSTextView/TextKit + WKWebView 路线，不重启 GPUI/Tauri 等框架竞争。
- 采用自有 DocumentSession 与协调器，不继承 NSDocument 生命周期；首存及另存为统一在目标确定后捕获快照。这两项已定稿，不重新列为自由选型。
- 原型可先做最小纵向切片，但不得接触真实用户资料；创建、替换、删除均使用隔离夹具。
- 不交付生产可用的完整应用，不承诺原型代码直接入主工程；通过评审的部分才复用。
- 不引入自动保存原文件、云服务、AI、插件、顶部标签栏、重命名和永久删除。

## 4. 阶段详细设计

### 4.1 首先结清的基线问题

下表记录评审决策与验证风险。2026-09-17用户已批准本次修订，PRD/TAD/ADR已同步；“口径已定”不等于原型通过，全部运行证据仍待G0取得。

| 编号 | 问题与来源 | 计划执行口径及结清方式 |
|---|---|---|
| B-01 | 草稿周期原口径不一致；本次用户批准统一30秒 | 所有规模/后台脏会话持续输入最长30秒成功提交检查点；停输入约2秒不变，切换不重置。提前预留生成/I/O时间；故障保留上一份并持续告警；实测20 MB连续输入及编辑超限 |
| B-02 | 旧分段初值合计310 ms不能作为300 ms目标余量 | 已撤销余量说法；G0实测后将计划总上限校准至≤300 ms，另测端到端P95≤300 ms，不求和分段P95替代整体分布 |
| B-03 | 统一主选与清洗回退调度，避免过度设计 | 共用一个每窗口1/全应用2调度器；回退惰性创建最多2个受限清洗上下文，每上下文串行，复用前重置绑定。无全局单槽或第二排队器；回退IPC、取消及两个大任务下小任务等待均实测并固定阈值 |
| B-04 | 去掉未经证明的Merkle树复杂度与零碰撞假设 | 长度快速判断＋UTF-16字面精确比较，最坏O(n)；不自研rope/增量树。G0验证1/5/20 MB等长替换、Undo、快照成本；仅>5 MB超预算可有界异步兜底。草稿后台固定64 KB字节分块独立于判脏，接受边界移动后的全文扫描/写入 |
| B-05 | Prompt 约 1280×800 pt、固定浅色截图；PRD/TAD 默认 1280×820 pt 并随系统深浅色 | 实际实现以 PRD/TAD 尺寸和外观为准。Prompt 只约束对应截图场景；folder-open 不是首次单文件默认态 |
| B-06 | 分发渠道、签名标识、Intel 与更新政策待确认 | 由产品/发布负责人在 G0 明确计划支持范围或登记期限；未确认不加入更新框架、不声称支持 Intel。最迟 G4 前必须结清分发阻断 |

B-01的30秒与B-04的简单比较已同步至PRD/ADR/TAD；若最低环境仍不满足则G0阻断，不能继续放宽。≤5 MB同步判脏不达标须专项评审，不能替换为revision判脏或静默扩大异步范围。

评审问题1～5同时固定：关闭/退出准入屏障、三类TargetExpectation、Reload成功持久废弃旧代（不建历史版本功能）、统一图片预算、位置无关SafeDocument缓存命中后重建资源/链接manifest。具体协议见TAD §11～§14；S0-05/06/07/09必须验证，不能把这些问题留给最终AC表。

2026-09-19评审修订2：用户确认关闭/删除等待已接受保存完成后重检，以及原始HTML常用静态子集。G0增加TAD §4.5、§8.2.1的协议/允许表交付与§18.2专项夹具。DIRTY-01同步Undo回基线立即clean；DIRTY-02仅批准的大文件异步判脏等待当前版本、超时中止，两者不再使用同一“不得中止”断言。删除遇脏即时中止，不自动等待用户处理再续删。

### 4.2 验证工程与接口骨架

拟建立 Xcode App 验证 target、本地 `Packages/MarkliteCore`、`WebAssets` 和 `Tests/Fixtures`。正式目录沿用 TAD §2.2；验证代码与正式代码明确区分，避免把临时绕过混入发布配置。

- Core：DocumentID、WindowID、FileIdentity、基线、RequestStamp、操作 token、纯状态归约、安全值模型。
- AppKit 层：EditorBackend、最小窗口宿主、会话独立文本与 UndoManager。
- 基础设施：FileAccess、SafeWrite、RecoveryStore、MarkdownEngine、HTMLSafetyService、PDFRenderer 原型。
- 注入 Clock、I/O 完成顺序与错误类型；用测试替身复现竞态，用真实签名沙盒应用验证系统能力。
- 约束依赖方向：Core 不导入 AppKit/WebKit/第三方 AST；UI 不直接写文件或决定授权。
- 建立真实可运行的构建、核心测试、Web 测试入口，再写入 `Scripts/`；本计划不假定已有脚本。

### 4.4 夹具与证据管理

夹具至少包含空文件、常规 README、中英日文/Emoji/组合字符、UTF-8 BOM、LF/CRLF/混合换行、无末尾换行、非法 UTF-8、二进制、长行/表格/代码、恶意 HTML、越界/循环链接、权限失效和规模边界。

规模统一按字节计算，MB=1,000,000；1 MB、5 MB、20 MB 都测试阈值前一字节、等于阈值、后一字节。多文档夹具包含同名、根外、未命名、跨窗口脏会话、迟到回调与保存提交后进程终止。

建议后续证据写入本目录 `evidence/stage-0/`（本次不生成空报告）。每份报告至少记录：任务编号、代码提交、工具链/依赖、硬件/系统、夹具版本、执行命令或人工步骤、预期/实际、原始日志/截图路径、通过/失败、残余风险和批准人。日志不含正文、原始 HTML、URL、bookmark 或未脱敏路径；恶意样本作为测试夹具而非用户诊断日志管理。

### 4.5 执行顺序与交接

1. 结清 B-01～B-05，建立环境及夹具，实施 S0-12 的最小构建部分。
2. 先跑编辑/精确判脏、解析/安全、文件/恢复三条关键链；同一组件的写入责任清晰，集成按依赖顺序进行。
3. 基于安全链验证滚动、查找、图片、PDF、窄导航与双语；禁止先接不安全预览作为演示捷径。
4. 做组合场景与性能采样，形成补充 ADR、确定参数及失败策略。
5. G0 评审决定进入阶段 1，或退回阻断项继续验证；不能把失败标为“以后优化”。

交接包包含原型提交、可复用代码清单、弃用原型清单、锁文件/许可证、接口契约、测试入口、结果与补充决策。环境或权限缺失的项目保持未通过。
